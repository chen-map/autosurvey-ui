# Skill: A1.4-b 评估实践元分析与基准审计

**层级**：P1.4 后果影响层 · Consequences & Impacts  
**RQ类型**：带来什么后果？（认知级偏差）  
**元认知逻辑**：不直接分析问题后果，而是审查「评估行为」本身的质量，揭示领域内常用基准数据集的构建偏差、标签方式、覆盖盲区，论证现有评估如何导致对问题严重性的系统性低估。  
**认知基准面**：以「评估实践的元认知审视」为透镜——评估结果的可信度取决于评估工具（数据集、指标）的质量；先审计「尺子是否准确」再看「测量结果」，否则所有关于 Problem 后果的结论都建立在沙滩上。

---

## Goal

审计 Problem Space 研究中使用的主要评估数据集和基准，揭示其来源偏差、粒度不足、覆盖局限等缺陷，分析这些缺陷如何导致领域对 Problem 后果严重性的系统性低估或失真评估。

---

## Inputs

- `knowledge_graph/nodes/dataset_nodes.json` — KG 中的数据集节点
- `knowledge_graph/edges/` — 论文与数据集的 `uses` / `evaluates_on` 边
- `paper_cards/parsed/` — Paper Cards，提取 Evaluation Setup / Dataset 章节
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `analyze_report/design_report.md` — RQ 定义

## Execution Steps

### Step 1: 建立评估实践全景图

**认知目标**：从 KG 结构出发建立评估实践全景，而非手动翻阅论文——`get_entity_by_type(loader, "dataset")` 和 `get_entity_by_type(loader, "metric")` 是获取领域评估实践全集的正确起点，它们覆盖了所有被 KG 收录的数据集和指标节点，不会遗漏。

```python
# 获取 KG 中所有数据集节点
all_datasets = get_entity_by_type(loader, "dataset")
# 获取 KG 中所有指标节点
all_metrics = get_entity_by_type(loader, "metric")

# 对每个数据集，通过 evaluates_on 边找到使用它的方法/论文
for dataset in all_datasets:
    dataset_id = dataset["node_id"]
    # 找到所有在该数据集上评估的方法节点
    evaluated_methods = get_head_entity(loader, "evaluated_on", dataset_id)
    # evaluated_methods 揭示了哪些方法共享相同的评估上下文（共评数据集）
```

对每篇论文的评估设计编码（来自 Paper Cards Evaluation 章节）：
- **评估形式**：受控实验 / 案例研究 / 理论证明 / 用户研究 / 自动化测试
- **使用数据集**：通过 `evaluated_on` 边获取，而非手动提取
- **评估指标**：通过 `all_metrics` 节点映射

统计各评估形式的使用频率分布。

### Step 2: 对高频使用数据集执行谱系审查

**认知目标**：「谱系审查」的目标是找到数据集构建过程中的系统性缺陷，而非偶发性错误。使用 `get_head_entity(loader, "evaluated_on", dataset_id)` 找到共同使用该数据集的所有方法——方法共享同一数据集意味着它们共享同一评估偏差，该偏差对整个共评方法群的结论都有影响。

对被 ≥ 3 个方法节点通过 `evaluated_on` 边使用的数据集（高频数据集），审查：

```python
for dataset in all_datasets:
    dataset_id = dataset["node_id"]
    shared_methods = get_head_entity(loader, "evaluated_on", dataset_id)

    if len(shared_methods) >= 3:
        # 这是高频数据集，执行谱系审查
        # 从 dataset 节点的 description, label, origin_paper_id 字段提取构建信息
        origin_paper = dataset.get("origin_paper_id")
        if origin_paper is None:
            evidence_papers = get_evidence_papers(loader, dataset_id)
        
        # 检索该数据集的构建方法描述
        dataset_provenance = search_paper_sections(
            paper_cards_root="paper_cards/parsed",
            query=f"{dataset['canonical_name']} dataset construction annotation",
            paper_ids=[origin_paper] if origin_paper else [],
            topk=3
        )
```

审查维度：
- **来源**：人工标注 / 自动生成 / 爬取 / 合成（不同来源的可信度差异）
- **标签粒度**：函数级 / 文件级 / 项目级
- **语言/领域覆盖**：单一语言 / 单一领域 vs 多样化
- **时效性**：数据集创建年份（来自 `origin_paper_id` 对应论文的发表年份）vs 当前最新威胁

若数据集来源在论文中未披露，强制标注 `label_source: unknown`，不得猜测。

### Step 3: 识别偏差类型与影响

**认知目标**：偏差方向的判断必须有逻辑论证——仅声称「这个数据集有问题」没有分析价值，必须论证「这个缺陷导致结论朝哪个方向失真」以及「为什么是这个方向」。

```python
# 检索论文中对评估局限性的承认
bias_acknowledgements = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="dataset limitation bias coverage",
    topk=10
)
# 这些命中往往在 Limitation 章节，是作者自认的评估缺陷
```

对每个发现的数据集缺陷，分析其导致的评估偏差方向：
- **过度乐观偏差**：数据集过于简单，导致高估方法效果（如：仅含简单样本的测试集导致虚高 accuracy）
- **覆盖盲区偏差**：数据集未覆盖真实高危场景，导致低估问题严重性
- **标签噪声偏差**：自动化标注错误，导致评估结果失真（如：False Negative 被当作 True Negative 计入指标）

偏差方向的逻辑论证结构：「数据集缺陷 X → 导致测量值 Y 偏离真实值 Z → 因为 [论证]」

### Step 4: 估算偏差对结论可信度的影响

**认知目标**：置信度降级必须是有区分度的判断——影响核心结论的偏差（`major`）与仅影响边缘实验的偏差（`minor`）有本质差别，前者意味着该论文的主要贡献主张需要重新审视，后者仅影响某个子实验的可靠性。

对每篇使用了有缺陷数据集的论文，评估其核心结论的可信度降级：
- `major`：数据集偏差影响该论文的核心贡献声明（如唯一评估数据集存在系统性偏差）
- `moderate`：数据集偏差影响部分重要结论但不影响整体贡献
- `minor`：数据集偏差仅影响某个边缘实验，核心结论仍可信

### Step 4a: 对抗性验证「系统性低估」结论

**认知目标**：「系统性低估」是强主张——它声称整个领域对 Problem 后果的认知是系统性偏差的，而非个别论文的偶发错误。在作出此主张之前，必须检验：是否有反例论文使用了更严格的评估方法并得到了不同（更高）的危害估计？

```python
# 检索是否有论文指出现有评估低估了问题严重性
underestimation_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="underestimate severity real-world impact worse than reported",
    topk=5
)
# 若无，则系统性低估结论需标注 identified: false
```

若文献集中无论文明确讨论数据集偏差问题，`systemic_underestimation.identified` 必须标注为 `false`，不得主动构造此结论。

### Step 5: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **审计对象必须是文献集中实际使用的数据集**，禁止引入未在文献中出现的外部数据集作为对比；起点必须是 `get_entity_by_type(loader, "dataset")` 的完整返回集，不得手动筛选。
- 若数据集来源在论文中未披露，强制标注 `label_source: unknown`，不得猜测。
- 偏差方向的判断必须有逻辑论证（「为什么这个偏差会导致高估/低估」），不可简单断言。
- 结论置信度降级评估需区分：偏差影响该论文的核心结论（`major`）还是仅影响某个边缘实验（`minor`）。
- 若文献集中无论文明确讨论数据集偏差问题，系统性低估结论必须标注 `identified: false`，不得主动构造此结论。
- **认知坐标纪律**：`get_head_entity(loader, "evaluated_on", dataset_id)` 返回的共评方法数是数据集影响范围的客观度量，必须作为高频数据集的判定标准，不得凭「这个数据集很有名」主观判断重要性。
