# Skill: A1.1-c 分层抽象堆栈

**层级**：P1.1 实体识别层 · Phenomenon & Inventory  
**RQ类型**：有什么？（属性刻画 · 技术特征）  
**元认知逻辑**：将系统抽象为 N 层技术栈，把问题/威胁归入其发生的特定层级，分析跨层传播路径与层级间的依赖放大效应。  
**认知基准面**：将系统视为一个垂直依赖栈，下层是上层的基础设施，问题的严重性不仅取决于自身，更取决于它所在层级被多少上层依赖——分析任务是绘制这张依赖放大地图。

---

## Goal

构建研究对象的技术栈分层模型，将 KG Problem Space 节点按层级归类，识别各层的问题密度与跨层传播链，揭示哪些层级是风险源点、哪些是风险放大器。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点，需含 `layer` / `component` / `level` 属性
- `knowledge_graph/edges/` — 问题节点间的 `propagates_to` / `targets` 边
- `analyze_report/design_report.md` — RQ 定义，确认系统架构上下文
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）

---

## Execution Steps

### Step 1: 从 KG 描述关键词归纳实际层级结构

**为什么**：预设的层级模型（如"硬件→OS→框架→应用"）往往与特定领域的实际技术栈不匹配。必须先从 KG 节点的 `description` 字段中找到实际出现的技术组件词汇，再自底向上归纳层级。

扫描全量 Problem 节点的 `description` 字段，提取技术层级信号词：

```python
layer_keywords = {
    "training":     ["training", "pre-training", "fine-tuning", "gradient", "backprop", "optimizer"],
    "inference":    ["inference", "generation", "decoding", "forward pass", "serving"],
    "deployment":   ["deployment", "containerization", "orchestration", "scaling", "endpoint"],
    "api":          ["API", "interface", "endpoint", "request", "prompt injection", "jailbreak"],
    "ecosystem":    ["package", "dependency", "supply chain", "plugin", "extension", "community"],
    "data":         ["dataset", "data collection", "annotation", "preprocessing", "poisoning"],
}

for p in get_entity_by_type(loader, "Problem"):
    matched_layers = []
    desc = p.description.lower()
    for layer_name, keywords in layer_keywords.items():
        if any(kw in desc for kw in keywords):
            matched_layers.append(layer_name)
    # 记录每个层级信号词的出现频率
```

同时用 `search_paper_sections` 从论文 System Model / Architecture 章节中验证层级划分：

```python
arch_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="system architecture layer stack component module",
    paper_ids=all_paper_ids,
    topk=15
)
# 从命中片段中提取论文明确描述的层级名称，与上述关键词扫描结果交叉验证
```

基于以上两路证据，确定 4~6 个技术层，每层必须有 ≥2 篇论文在 System Model 章节中明确提及该层的名称或等价描述。层级定义确定后固化，后续步骤不得修改。

### Step 2: 归类 Problem 节点到层级

**为什么**：`layer` 字段常常缺失，`description` 字段是最可靠的语义来源。分层归类的关键是找到问题的"根因层"，而非影响层。

```python
for p in get_entity_by_type(loader, "Problem"):
    # 优先级1：KG layer/component/level 字段
    layer = p.attributes.get("layer") or p.attributes.get("component")
    
    # 优先级2：字段缺失时从 description 推断
    if layer is None:
        layer = judge(
            f"Given this problem description: '{p.description}', "
            f"in which technical layer does this problem ORIGINATE (root cause layer)? "
            f"Choose from: {layer_list}. "
            f"Note: choose the layer where the vulnerability/fault is introduced, "
            f"not where the impact is felt."
        )
        p.attributes["layer_source"] = "inferred_from_description"
    
    # 优先级3：仍无法确定时，调用 get_evidence_papers 补充上下文
    if layer is None:
        source_papers = get_evidence_papers(loader, p.id)
        # 从来源论文的 threat model 章节中查找层级信息
        for sp in source_papers:
            layer_hints = search_paper_sections(
                query=f"{p.description[:80]} layer component",
                paper_ids=[sp.id],
                topk=1
            )
        # 若仍无法确定，标记 layer: unknown
```

跨层问题：归入「首发层」（根因所在层），其余受影响层记录在 `impact_layers` 字段。

### Step 3: 构建跨层传播图

**为什么**：问题在垂直栈中向上传播（底层漏洞危害上层应用）是技术栈分析的核心价值。仅靠 KG 现有边可能不完整，需要结合链式推导补全传播路径。

首先从 KG 现有边获取直接传播关系：

```python
from_kg_edges = []
for p in all_problems:
    downstream = get_tail_entity(loader, "propagates_to", p.id)
    if not downstream:
        downstream = get_tail_entity(loader, "triggers", p.id)
    for d in downstream:
        from_kg_edges.append({"from": p.id, "to": d.id, "source": "kg_edge"})
```

然后通过 `get_tail_entity` 链式调用推导传播路径：

```python
# 对每个 problem_id，沿 "addresses" 关系的反向追踪其影响链
def trace_propagation_chain(loader, problem_id, visited=set(), depth=0):
    if depth > 4 or problem_id in visited:
        return []
    visited.add(problem_id)
    # 找到被此问题触发的下游问题
    downstream = get_tail_entity(loader, "addresses", problem_id)  # 解决该问题的论文
    # 再查这些论文还 addresses 了哪些相关问题（间接传播）
    chain = []
    for d in downstream:
        chain.append(d.id)
        chain.extend(trace_propagation_chain(loader, d.id, visited, depth+1))
    return chain
```

构建有向传播图，识别：
- 链式传播：L1 → L2 → L3（每一跳跨一层）
- 跨层跳跃：L1 → L3（直接影响非相邻层）

### Step 4: 计算层级风险指标

```
layer_problem_density[L] = count(problems rooted in L)
layer_paper_density[L]   = count(papers addressing L)
propagation_centrality[L] = out_degree(L in propagation graph)
dependency_amplification[L] = count(layers above L that depend on L)
```

识别以下关键层级类型：
- **风险源点层**：高 `layer_problem_density` + 高 `propagation_centrality`
- **传播放大层**：高 `dependency_amplification`（被多层依赖）
- **研究盲点层**：高 `layer_problem_density` + 低 `layer_paper_density`
- **防御集中层**：低 `layer_problem_density` + 高 `layer_paper_density`（可能研究过度集中）

### Step 5: 对抗性验证：检验层级划分的完备性与传播链的可靠性

**为什么**：层级划分可能将本质上属于同一技术组件的问题人为分裂到不同层，或遗漏了介于两层之间的"中间件层"。传播链也可能因 KG 边稀疏而低估。

执行以下反例检查：
1. 对 `layer: unknown` 的节点，检查其 `description` 是否暗示存在一个当前层级模型未覆盖的技术组件
2. 对跨层传播链，使用 `search_paper_sections` 验证该传播在论文中是否有明确描述：

```python
for chain in cross_layer_propagations:
    verification = search_paper_sections(
        query=f"{chain['from_problem_desc']} causes {chain['to_problem_desc']}",
        paper_ids=all_paper_ids,
        topk=3
    )
    if not verification:
        chain["evidence_status"] = "inferred_no_direct_support"
```

3. 用 `judge` 评估：「当前层级模型中，哪两个相邻层之间的边界最模糊？这种模糊性会导致哪些 Problem 节点的归类不稳定？」

对归类不稳定的节点，在报告中标注 `layer_confidence: low`。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **层级定义必须来源于文献**，通过 `description` 关键词扫描和 `search_paper_sections` 双路验证；若找不到标准分层，从文献 Background 章节归纳，在 `stack_model.source_papers` 字段注明支撑论文。
- 跨层传播路径必须有具体 Paper 的 Security Analysis 章节或 `search_paper_sections` 命中作为证据；**仅凭常识推断的传播链必须标注 `evidence_status: inferred_no_direct_support`**，不得作为确定性结论。
- 若某问题的层级归属无法从文献中确定，必须标记 `layer: unknown`，禁止猜测。
- 「研究盲点层」的识别结论必须附带至少一篇文献中提到该层挑战的引用作为佐证。
- **认知基准面纪律**：技术栈的层级定义（包括层数、层名、层间依赖方向）必须在 Step 1 完成后固化，不得在后续步骤中因归类困难而随意增减层级；若确需调整，须回到 Step 1 重新执行并说明修改理由。
