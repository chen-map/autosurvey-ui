# Skill: A1.6-a 攻防协同演化轨迹绘制

**层级**：P1.6 对抗演化与次生灾害层 · [V3 新增]  
**RQ类型**：问题如何被解法「逼」着进化？（对抗性动态）  
**元认知逻辑**：按时间序列交错分析攻击手法与防御手段的出现顺序，绘制「攻击出现 → 防御封堵 → 攻击变异」的螺旋上升轨迹，揭示攻防博弈的动态演化规律。  
**认知基准面**：以「攻防博弈螺旋追踪」为透镜——将攻防关系理解为军备竞赛而非静态对抗；每一次防御升级都创造了新的攻击面，攻击的变异方向由防御的弱点决定；分析重心不是「谁领先」，而是「博弈螺旋的加速规律和当前前沿缺口」。

---

## Goal

基于 KG 和 Paper Cards 中的时间序列数据，构建攻击-防御的时间交错线，标注每次防御升级后对应出现的攻击变异版本，揭示攻防协同演化的「军备竞赛」动力学模式。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点（攻击/威胁类），含年份
- `knowledge_graph/nodes/methods.json` — KG 方法节点（防御/检测类），含年份
- `knowledge_graph/edges/` — `bypasses` / `evades` / `counters` / `addresses` 类型边
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `paper_cards/parsed/` — Paper Cards，提取攻防描述

---

## Execution Steps

### Step 1: 分离攻击与防御节点并建立时序

**认知目标**：攻击节点和防御节点的分类必须基于 `description` 字段的关键词匹配，而非 KG 节点类型（因为攻击往往存储为 problem 节点，防御存储为 method 节点，但不同研究领域可能有差异）。年份信息必须来自关联论文的实际发表年份，不得使用未经验证的字段。

```python
all_methods = get_entity_by_type(loader, "method")
all_problems = get_entity_by_type(loader, "problem")

# 攻击节点：problem 节点中 description 含攻击语义关键词
attack_keywords = ["attack", "adversarial", "exploit", "bypass", "evasion",
                   "injection", "poisoning", "jailbreak", "manipulation"]
attack_nodes = []
for problem in all_problems:
    desc = problem.get("description", "").lower()
    if any(kw in desc for kw in attack_keywords):
        attack_nodes.append(problem)

# 防御节点：method 节点中 description 含防御语义关键词
defense_keywords = ["detect", "defend", "mitigate", "protect", "filter",
                    "sanitize", "guard", "robust", "shield", "prevent"]
defense_nodes = []
for method in all_methods:
    desc = method.get("description", "").lower()
    if any(kw in desc for kw in defense_keywords):
        defense_nodes.append(method)
```

获取每个节点的「首次出现年份」：

```python
for node in attack_nodes + defense_nodes:
    # 从 origin_paper_id 对应的 papers.json 记录中获取发表年份
    paper_id = node.get("origin_paper_id")
    if paper_id is None:
        evidence_papers = get_evidence_papers(loader, node["node_id"])
        paper_id = evidence_papers[0] if evidence_papers else None
    
    if paper_id:
        paper_meta = get_paper_metadata(loader, paper_id)
        node["first_year"] = paper_meta.get("year", None)
    else:
        node["first_year"] = None  # 标注年份不可确定
```

**必须严格引用具体年份的论文来支撑攻击与防御的时间先后关系，禁止虚构未发生的攻击变种。**

按年份分组，可用 `get_entity_by_constraint` 进行年份过滤：

```python
# 按年份区间过滤节点
nodes_in_year = get_entity_by_constraint(all_methods, "created_at", ">", "YEAR")
```

### Step 2: 构建时间交错线

**认知目标**：时间线的构建不是可视化装饰，而是识别「防御出现时间早于被绕过攻击出现时间」的关键依据——只有确认了时序，才能建立因果关系（防御的出现激发了攻击变异）。时序不明的节点不得纳入三元组分析。

按年份排列所有攻击节点和防御节点，构建双轨时间线（Attack Track 和 Defense Track）：

```
时间轴: 2018  2019  2020  2021  2022  2023
攻击:  [A1]  [A2]        [A3]  [A4']
防御:        [D1]  [D2]  [D3]        [D4]
```

对每个防御节点，查找其发布之后出现的攻击节点，以及两者之间是否存在 `bypasses`/`evades` 类型边：

```python
for defense in defense_nodes:
    defense_year = defense["first_year"]
    if defense_year is None:
        continue  # 年份不确定，跳过
    
    defense_id = defense["node_id"]
    # 找到所有 bypasses 或 evades 该防御的攻击节点
    out_edges = get_relation(loader, defense_id, "in")  # 入边中找 bypasses/evades
    bypass_edges = [e for e in out_edges
                    if e["edge_type"] in ["bypasses", "evades"]]
```

### Step 3: 识别「出现-封堵-变异」三元组

**认知目标**：三元组的构建必须同时满足两个条件：①存在 `bypasses`/`evades` 类型边（KG 的结构性证据）；②攻击节点的年份晚于防御节点的年份（时序性证据）。仅有时序没有边，只能说明「防御出现后攻击出现」；仅有边没有时序，无法说明是「应对性变异」还是「早期攻击」。两个条件缺一不可。

```python
coevolution_triples = []
for defense in defense_nodes:
    defense_year = defense.get("first_year")
    if defense_year is None:
        continue
    
    defense_id = defense["node_id"]
    # 找到 bypasses/evades 该防御的攻击节点
    inbound_edges = get_relation(loader, defense_id, "in")
    bypass_attacks = [e for e in inbound_edges
                      if e["edge_type"] in ["bypasses", "evades"]]
    
    for edge in bypass_attacks:
        attack_id = edge["source_node_id"]
        attack_node = get_node_by_id(loader, attack_id)
        attack_year = attack_node.get("first_year")
        
        # 时序验证：攻击出现在防御之后（变异性攻击）
        if attack_year and attack_year > defense_year:
            triple = {
                "attack_id": attack_id,
                "attack_name": attack_node.get("canonical_name"),
                "defense_bypassed_id": defense_id,
                "defense_name": defense.get("canonical_name"),
                "bypass_year": attack_year,
                "defense_year": defense_year,
                "bypass_mechanism": edge.get("evidence", ""),
                "evidence_paper": edge.get("context_paper_id", "")
            }
            # 获取完整的绕过机制上下文
            bypass_context = search_paper_sections(
                paper_cards_root="paper_cards/parsed",
                query=edge.get("evidence", "")[:80],
                paper_ids=[edge.get("context_paper_id")],
                topk=2
            )
            triple["bypass_context_snippet"] = bypass_context[0] if bypass_context else None
            coevolution_triples.append(triple)
```

计算「防御被绕过率」：被绕过的防御数 / 总防御数。

统计每次防御后的绕过响应时间（`bypass_year - defense_year`），用于评估博弈加速趋势。

### Step 4: 识别演化模式

**认知目标**：演化模式的识别需要至少 3 个时间节点的数据，时间序列过短时必须声明置信度低。模式识别的目的不是给博弈贴标签，而是预测「当前攻防前沿的下一步演化方向」——不同模式对应不同的研究优先级。

基于三元组序列，识别演化模式类型：
- **线性军备竞赛**：攻击和防御交替升级，无明显加速
- **防御瓶颈突破**：某一防御手段长期有效，直到被某攻击突破引发连锁反应
- **攻击收敛**：攻击手法逐渐标准化，变种减少
- **防御饱和**：防御手段密度高但效果边际递减

```python
# 计算绕过响应时间的趋势
response_times = [t["bypass_year"] - t["defense_year"] for t in coevolution_triples]
if len(response_times) >= 3:
    trend = "accelerating" if response_times[-1] < response_times[0] else "stable"
else:
    pattern_confidence = "low"  # 时间序列过短
```

识别「当前无对应防御的攻击」——这些是防御前沿的空白：

```python
# 找到出现时间最新的攻击，检查是否有防御 addresses 其导致的 problem
for recent_attack in recent_attack_nodes:
    attack_problem_id = get_attack_target_problem(loader, recent_attack["node_id"])
    existing_defenses = get_head_entity(loader, "addresses", attack_problem_id)
    if not existing_defenses:
        open_attack_without_defense.append(recent_attack)
```

**若时间序列 < 4 年，必须标注 `pattern_confidence: low`。**

### Step 4a: 对抗性验证「无对应防御」清单

**认知目标**：「无对应防御」的声明风险在于 KG 收录可能不完整——某攻击在 KG 中没有 addresses 它的防御方法，不代表现实中无防御研究。必须通过直接文献检索进行验证，防止过度夸大防御空白。

```python
for open_attack in open_attack_without_defense:
    # 直接检索文献，看是否有论文讨论了针对该攻击的防御
    defense_search = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"defend against {open_attack['canonical_name']} detection mitigation",
        topk=5
    )
    if defense_search and max(s["score"] for s in defense_search) > 0.6:
        open_attack["coverage_incomplete"] = True
        open_attack["potential_defense_paper"] = defense_search[0]
    else:
        open_attack["coverage_incomplete"] = False
```

### Step 5: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **每个「防御被绕过」三元组必须同时满足两个条件**：①KG 中存在 `bypasses`/`evades` 类型边；②攻击节点年份晚于防御节点年份。仅满足时序不满足边，禁止构造三元组。
- 年份信息必须来自 `knowledge_graph/nodes/papers.json` 的实际发表年份，不得使用 KG 中未经验证的年份字段。
- 「无对应防御的攻击」清单必须经过 Step 4a 的文献直接检索验证，若可能存在 KG 未收录的防御研究，标注 `coverage_incomplete: true`。
- 演化模式的识别需要至少 3 个时间节点的数据，若时间序列过短（< 4 年），必须标注 `pattern_confidence: low`。
- 禁止虚构「假设性攻击变种」，所有三元组的两端节点必须在 KG 中有对应的真实节点。
- **认知坐标纪律**：攻防分类（attack_keywords vs defense_keywords）基于 `description` 字段内容，不得基于节点的 KG 类型（method/problem）做简单映射，因为不同研究领域的节点类型使用方式可能不一致。
