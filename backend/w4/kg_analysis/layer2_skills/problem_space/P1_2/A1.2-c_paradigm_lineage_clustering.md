# Skill: A1.2-c 范式和谱系聚类

**层级**：P1.2 认知框架层 · Conceptualization & Taxonomy  
**RQ类型**：怎么划分？（维度分解 / 演化规律）  
**元认知逻辑**：不直接使用文献中碎片化的分类维度，而是归纳所有维度的「最大公约数」，识别底层元维度，建立谱系树，揭示各种分类方案是同一元维度的不同特例。  
**认知基准面**：将所有分类方案视为同一深层认知结构的不同投影——每种分类方案都是研究者从某个视角对元维度空间的一次切片；分析任务是找到这个元维度空间本身，而非在投影之间做取舍。

---

## Goal

收集文献中所有用于划分 Problem Space 的分类维度，通过聚类分析提炼出底层元维度，建立 2-3 层谱系树，解释不同研究者采用不同分类方案背后的共同认知逻辑。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点，含多种分类标签
- `knowledge_graph/nodes/concept_nodes.json` — 概念节点（分类维度本身）
- `paper_cards/parsed/` — Paper Cards，提取各论文的分类方案描述
- `analyze_report/design_report.md` — RQ 定义
- `working_memory/rq_{id}/A1.2-a_taxonomy_report.json`（可选）— 上游正交重构结果

---

## Execution Steps

### Step 1: 收集文献中的所有分类方案

**为什么**：元维度归纳的质量取决于输入分类方案的完整性。遗漏某些分类方案会导致归纳出的元维度偏向于被收集到的方案，产生系统性偏差。

从每篇 Paper Card 的 Taxonomy / Classification / Background 章节提取该论文对问题空间的分类方式：

```python
taxonomy_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="taxonomy classification categorize type category dimension",
    paper_ids=all_paper_ids,
    topk=25
)

all_dimensions = []
for snippet in taxonomy_snippets:
    dim = judge(
        f"Extract the classification dimension from: '{snippet.paragraph_snippet}'\n"
        f"Return: dimension_name (the axis of classification), "
        f"value_set (the discrete labels on this axis), paper_id."
    )
    all_dimensions.append({**dim, "paper_id": snippet.paper_id, "section": snippet.section})
```

去重合并：语义相同但表述不同的维度合并为同一条目（如 "attack surface" 和 "threat vector" 可能指同一维度）：

```python
for i, dim_a in enumerate(all_dimensions):
    for j, dim_b in enumerate(all_dimensions[i+1:], i+1):
        similarity = judge(
            f"Are these two classification dimensions semantically equivalent?\n"
            f"Dim A: {dim_a['dimension_name']} with values {dim_a['value_set']}\n"
            f"Dim B: {dim_b['dimension_name']} with values {dim_b['value_set']}\n"
            f"Answer: yes/no + reasoning."
        )
        if similarity.answer == "yes":
            # 合并为同一条目，保留所有来源论文
            merge_dimensions(dim_a, dim_b)
```

### Step 2: 通过 KG 边直接提取谱系关系

**为什么**：语义相似度计算是对谱系关系的间接推断；KG 中的 `extends` 边是范式间谱系关系的直接编码，应作为首选证据来源，远比语义猜测可靠。

从 KG 中直接读取范式/维度间的继承关系：

```python
# 获取所有概念节点（分类维度本身）
concept_nodes = get_entity_by_type(loader, "Concept")

lineage_edges = []
for concept in concept_nodes:
    # 找到扩展自该概念的下游概念（谱系子节点）
    extensions = get_head_entity(loader, "extends", concept.id)
    for ext in extensions:
        lineage_edges.append({
            "parent": concept.id,
            "child": ext.id,
            "relation": "extends",
            "source": "kg_edge"
        })
    
    # 找到该概念扩展自哪个上游概念（谱系父节点）
    parent = get_tail_entity(loader, "extends", concept.id)
    for p in parent:
        lineage_edges.append({
            "parent": p.id,
            "child": concept.id,
            "relation": "extends",
            "source": "kg_edge"
        })
```

同时检查其他可用的谱系边类型：`generalizes`、`specializes`、`inherits_from`：

```python
for rel_type in ["generalizes", "specializes", "inherits_from", "derived_from"]:
    for concept in concept_nodes:
        related = get_tail_entity(loader, rel_type, concept.id)
        for r in related:
            lineage_edges.append({"parent": concept.id, "child": r.id,
                                   "relation": rel_type, "source": "kg_edge"})
```

对 KG 边未覆盖的维度对，才退而使用语义相似度（标注 `source: semantic_inference`）。

### Step 3: 聚类识别元维度

**为什么**：元维度的识别是归纳推理，目标是找到能解释所有具体分类方案的最小共同抽象。聚类的数量不能太少（丢失重要区分）也不能太多（元维度失去抽象意义）。

基于 Step 2 的谱系边和 Step 1 的语义相似度，构建维度相似度图，执行层次聚类：

```python
# 构建维度相似度矩阵
# 若两个维度之间有 KG extends 边 → 相似度设为 0.9（高相关但有层级）
# 若两个维度有语义相似度 → 使用计算值
# 若无任何关系 → 相似度设为 0

# 层次聚类（Ward 方法）
# 元维度数量控制在 3~6 个
```

对每个聚类，用 `judge` 归纳元维度的命名：

```python
for cluster in clusters:
    meta_dim_name = judge(
        f"These classification dimensions belong to the same cluster: {cluster.member_dimensions}\n"
        f"What is the common abstract concept that unifies them all? "
        f"The name must appear in at least one of the source papers."
    )
    # 验证：元维度名称必须能在文献中找到对应描述
    name_verification = search_paper_sections(
        query=meta_dim_name,
        paper_ids=all_paper_ids,
        topk=3
    )
    if not name_verification:
        # 退而使用最高引用频率的成员维度名称作为元维度名称
        meta_dim_name = max(cluster.members, key=lambda d: d.usage_count).dimension_name
```

元维度的命名必须能被文献中某篇综述文章的分类框架所验证，不得纯靠 LLM 抽象命名。

### Step 4: 构建谱系树

**为什么**：谱系树的每个节点都代表一个有文献支撑的认知实体，不能存在悬空节点（无文献支撑的纯推断节点）。KG 边给出的直接谱系关系应优先于从语义推断的层级关系。

建立 2-3 层谱系结构：
- **L1（根节点）**：研究对象的最高抽象问题域
- **L2（元维度节点）**：3~6 个底层元维度（来自 Step 3 聚类结果）
- **L3（具体分类标签）**：各元维度下的具体取值/子类

```python
lineage_tree = {"root": domain_name, "L2_nodes": []}

for meta_dim in meta_dimensions:
    l2_node = {
        "meta_dimension_id": meta_dim.id,
        "name": meta_dim.name,
        "first_appeared_year": min(d.first_appeared_year for d in meta_dim.members),
        "supporting_papers": [d.source_paper for d in meta_dim.members],
        "L3_nodes": []
    }
    
    for member_dim in meta_dim.members:
        for label in member_dim.value_set:
            # 验证该标签有文献支撑
            supporting_paper = member_dim.source_papers[0] if member_dim.source_papers else None
            
            l3_node = {
                "label": label,
                "parent_dimension": member_dim.dimension_name,
                "supporting_paper": supporting_paper,
                "unsupported": supporting_paper is None
            }
            l2_node["L3_nodes"].append(l3_node)
    
    lineage_tree["L2_nodes"].append(l2_node)
```

**谱系树的每一个分支节点必须至少有一篇输入文献支撑，禁止生成悬空分类。**

### Step 5: 分析维度演进逻辑

**为什么**：谱系树的静态结构只展示了「是什么」，时间维度的分析展示了「为什么」——某些元维度早期出现而某些是近年引入，这种时序模式揭示了研究社区认知框架的演进方向。

结合 A1.1-d 的时间序列分析（若已执行），分析谱系树各分支的出现时序：

```python
for meta_dim in meta_dimensions:
    # 统计该元维度下各成员维度的首次出现年份
    timeline = [(d.dimension_name, d.first_appeared_year) for d in meta_dim.members
                if d.first_appeared_year is not None]
    timeline.sort(key=lambda x: x[1])
    
    meta_dim.evolution_pattern = judge(
        f"These classification dimensions appeared in this order: {timeline}\n"
        f"What does this temporal pattern reveal about how the research community's "
        f"understanding of {meta_dim.name} evolved?"
    )
```

### Step 6: 对抗性验证：检验谱系树的稳健性

**为什么**：谱系树的结构可能因聚类方法的选择而不同。必须主动寻找「不符合谱系树预测」的维度或分类方案，检验是否存在需要并列处理的根本冲突。

执行以下反例检查：
1. 对每对在谱系树中处于不同元维度的成员维度，验证其 `intersect` 结果：

```python
for l2_node_a, l2_node_b in combinations(lineage_tree["L2_nodes"], 2):
    papers_a = union(*[d.source_papers for d in l2_node_a.members])
    papers_b = union(*[d.source_papers for d in l2_node_b.members])
    
    cross_citing = intersect(papers_a, papers_b)
    if len(cross_citing) / min(len(papers_a), len(papers_b)) > 0.4:
        # 高度交叉引用说明这两个元维度在文献中常被同时使用，可能不是真正独立的
        flag_as_entangled(l2_node_a, l2_node_b, cross_citing)
```

2. 检查是否存在根本性冲突的分类方案（两种分类方案逻辑上互斥）：

```python
conflicting_pairs = []
for dim_a, dim_b in combinations(all_dimensions, 2):
    conflict_check = judge(
        f"Are these two classification schemes logically incompatible "
        f"(i.e., accepting one requires rejecting the other)?\n"
        f"Scheme A: {dim_a}\nScheme B: {dim_b}"
    )
    if conflict_check.answer == "yes":
        conflicting_pairs.append((dim_a, dim_b, conflict_check.reasoning))
```

**若不同论文的分类方案存在根本性冲突，必须在报告中并列展示，不得强行合并。**

### Step 7: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **谱系树每个 L3 节点必须至少有一篇论文支撑**，若支撑论文数为 0，该节点标记 `unsupported: true`，需人工审查后决定保留或删除。
- 元维度的命名必须能被文献中某篇综述文章的分类框架所验证，不得纯靠 LLM 抽象命名。
- 若不同论文的分类方案存在根本性冲突（两种分类方案逻辑上互斥），必须在报告中并列展示，不得强行合并。
- 语义相似度计算若无向量工具可用，可退化为 LLM 判断，但必须标注 `similarity_method: llm_judgment`；KG `extends` 边直接给出的谱系关系优先级高于任何语义推断。
- 谱系树深度超过 3 层时，必须说明增加层数的理由，防止过度细分。
- 范式聚类必须优先使用 KG 中的 `extends`、`generalizes`、`inherits_from` 等谱系边，通过 `get_head_entity(loader, "extends", paradigm_id)` 直接读取继承关系，而非依赖语义猜测。
- **认知基准面纪律**：整个分析过程必须坚持「所有分类方案都是同一元维度空间的投影」这一视角，不得因某种分类方案更流行或更直觉而优先对待；当发现某个分类方案无法纳入当前元维度框架时，应首先质疑元维度的完整性，而非强行压缩该方案。
