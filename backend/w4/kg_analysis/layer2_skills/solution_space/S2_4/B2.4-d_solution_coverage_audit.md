# Skill: B2.4-d 解药-痛点映射与覆盖率审计

**层级**：S2.4 效能对比层 · Comparative Efficacy & Trade-offs  
**RQ类型**：优劣势如何？（闭环验证）  
**元认知逻辑**：构建「Problem Space 问题清单 × Solution Space 解法清单」的覆盖矩阵，计算每个解法的问题覆盖率，并对 A1.6-b 识别为次生灾害来源的高风险解法执行 0.5 权重惩罚，输出经风险校正的真实覆盖率。  
**认知基准面**：覆盖率审计不只是统计「谁覆盖了哪些问题」，而是识别「哪些问题在整个 Solution Space 中没有任何方法能可靠覆盖」——这些空白才是真正的研究缺口，而非当前方法的排名差异。

---

## Goal

实现 Problem Space 与 Solution Space 的闭环对齐审计：量化 Solution Space 对 Problem Space 的总体覆盖率，识别哪些问题仍无解法覆盖（研究缺口），并对引入次生风险的解法执行风险加权惩罚。

---

- `working_memory/rq_{id}/A1.1-a_matrix_report.json` 或 `A1.1-b`（Problem Space 问题清单，强依赖）

## Execution Steps

### Step 1: 构建问题-解法覆盖矩阵（KG 边驱动）

**为什么这样做**：如果只依靠手工阅读每篇论文来判断「是否解决了某问题」，会引入阅读覆盖不完整和主观判断的偏差。正确做法是以 KG 的 `addresses` 边作为主索引，确保不遗漏任何已建立的覆盖关系。

```python
all_problems = get_entity_by_type(loader, "problem")

coverage_matrix = {}
for problem in all_problems:
    problem_id = problem["id"]
    coverage_matrix[problem_id] = {}

    # 通过 KG addresses 边找到所有声称解决该问题的方法
    covering_methods = get_head_entity(loader, "addresses", problem_id)

    for method in covering_methods:
        method_id = method["id"]
        # 获取该方法的证据论文，判断覆盖是否有实验支撑
        evidence_papers = get_evidence_papers(loader, method_id)
        # 检查该覆盖声明是否在 B2.3-c 中被标注为不可信
        is_reliable = check_reliability(method_id, problem_id)  # 来自 B2.3-c
        coverage_matrix[problem_id][method_id] = {
            "raw_score": 1.0 if (evidence_papers and is_reliable) else 0.5,
            "coverage_basis": "experiment_verified" if (evidence_papers and is_reliable) else "claimed_only"
        }
```

覆盖分数定义：
- `matrix[P][M] = 1.0`：方法 M 宣称解决了问题 P 且有实验验证
- `matrix[P][M] = 0.5`：方法 M 宣称解决了问题 P 但无实验验证（Claimed but unverified）
- `matrix[P][M] = 0`：方法 M 未涉及问题 P

补充检查：对覆盖分数为 0 的 (P, M) 对，检查是否存在传递覆盖——`get_relation(loader, problem_id, "in")` 查看未覆盖问题是否归属于某个已被覆盖的问题集群（可能被间接覆盖）。

**若文献仅宣称解决某痛点但无实验证明，需标记为 `Claimed but unverified`。**

### Step 2: 联动 A1.6-b 执行风险惩罚（精确追溯到原始证据）

**为什么这样做**：高风险解法的覆盖分数应该被折扣，因为它们「解决了问题 A 但创造了问题 B」。但惩罚必须可追溯——不能因为 A1.6-b 的一个标签就惩罚，必须找到 A1.6-b 引用的原始文献来确认次生灾害的存在。

```python
from A1_6_b_report import high_risk_solutions  # 加载 A1.6-b 报告

for high_risk_method_id in high_risk_solutions:
    # 验证：该方法确实在 A1.6-b 中有文献支撑的次生灾害记录
    secondary_disaster_evidence = get_secondary_disaster_evidence(high_risk_method_id)
    if not secondary_disaster_evidence:
        # 缺乏原始证据 → 不执行惩罚，标注为「待验证高风险」
        continue

    # 对该方法的所有覆盖分数（针对所有问题）执行 0.5 惩罚
    for problem_id in coverage_matrix:
        if high_risk_method_id in coverage_matrix[problem_id]:
            original = coverage_matrix[problem_id][high_risk_method_id]["raw_score"]
            coverage_matrix[problem_id][high_risk_method_id]["adjusted_score"] = original * 0.5
            coverage_matrix[problem_id][high_risk_method_id]["risk_penalized"] = True
            coverage_matrix[problem_id][high_risk_method_id]["penalty_evidence"] = secondary_disaster_evidence
```

风险校正公式：
```
adjusted_coverage[P][M_high_risk] = original_coverage[P][M_high_risk] × 0.5
```

**惩罚规则**：若某方法同时解决多个问题但被列为高风险，其每一个覆盖分数均需乘以 0.5，不得仅对部分问题应用惩罚。

### Step 3: 计算覆盖率统计

```python
for problem_id in coverage_matrix:
    adjusted_scores = [
        entry.get("adjusted_score", entry["raw_score"])
        for entry in coverage_matrix[problem_id].values()
    ]
    problem_coverage_rate[problem_id] = max(adjusted_scores) if adjusted_scores else 0.0

overall_coverage_rate = (
    count(P for P in problems if problem_coverage_rate[P] > 0.5)
    / len(problems)
)
```

识别：
- **已有效覆盖的问题**（最高覆盖分数 ≥ 1.0，且来自 experiment_verified）
- **仅有声称覆盖的问题**（最高分数 = 0.5，claimed_only）
- **完全无覆盖的问题**（最高分数 = 0）

### Step 4: 识别研究缺口（风险加权后的真实空白）

**为什么这样做**：「无覆盖的问题」和「有高风险解法覆盖但无低风险替代的问题」都是研究缺口——后者容易被忽视，因为表面上看问题有解法，但风险校正后实际等同于无可靠解法。

```python
for problem_id in problems:
    max_adjusted = max(
        entry.get("adjusted_score", entry["raw_score"])
        for entry in coverage_matrix[problem_id].values()
    ) if coverage_matrix[problem_id] else 0.0

    if max_adjusted == 0:
        gap_type = "uncovered"
    elif max_adjusted <= 0.5 and all_solutions_penalized(problem_id):
        gap_type = "risk_exposed_gap"  # 有解法但全部是高风险，风险校正后无可靠覆盖
    elif max_adjusted == 0.5:
        gap_type = "claimed_only_gap"
```

「完全无覆盖」的高危问题（来自 A1.4-c 的高危场景）是最紧迫的研究缺口：
- `gap_type: too_recent`：近一年新出现的问题，区别于长期被忽视的缺口
- `gap_type: structural_gap`：长期存在且无任何覆盖的深层问题

### Step 5: 输出风险校正后的解法排名

**排名逻辑**：按「经风险惩罚后的总覆盖问题数」对解法进行排名，区分原始排名和校正排名。排名变化（原始 vs 校正）必须在报告中突出展示，让读者清晰看到风险惩罚的实际影响。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **覆盖计算必须严谨**：`experiment_verified` 分数 = 1.0，`claimed_only` 分数 = 0.5，这是硬性区分，不得主观升降。
- A1.6-b 的高风险解法惩罚必须携带完整证据（`evidence_paper`），仅凭 B2.4-d 引用 A1.6-b 报告本身不足以触发惩罚，惩罚依据必须追溯到 A1.6-b 中引用的原始文献。
- 「完全无覆盖」问题中，若有些问题在研究时间内本就出现很晚（如近一年新威胁），需标注 `gap_type: too_recent`，区别于长期被忽视的缺口。
- 若某方法同时解决多个问题但被列为高风险，其每一个覆盖分数均需乘以 0.5，不得仅对部分问题应用惩罚。
- 排名变化（原始 vs 校正）必须在报告中突出展示，让读者清晰看到风险惩罚的实际影响。
- **KG addresses 边是覆盖矩阵的主索引**：必须先通过 `get_head_entity(loader, "addresses", problem_id)` 枚举所有覆盖关系，再补充文本验证；不得仅依靠阅读论文来构建覆盖矩阵。
- **认知坐标纪律**：核心产出是「风险校正后的真实研究缺口图」，而非解法排名列表。若报告中覆盖率看起来很高，必须检查是否因为大量 claimed_only 或高风险解法撑起了数字——表面覆盖率 ≠ 实际问题解决率。
