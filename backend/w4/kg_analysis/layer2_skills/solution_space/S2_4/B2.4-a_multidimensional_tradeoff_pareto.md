# Skill: B2.4-a 多维权衡与边界分析

**层级**：S2.4 效能对比层 · Comparative Efficacy & Trade-offs  
**RQ类型**：优劣势如何？（代价权衡）  
**元认知逻辑**：提取多个效能维度（精度/效率/成本/鲁棒性），对每个解法分析其在多维空间中的取舍关系，绘制帕累托前沿，识别「没有任何方法在所有维度上同时最优」的必然权衡结构。  
**认知基准面**：真正的洞察不是找到谁最好，而是找到哪些维度组合在物理上不可同时最优——每个帕累托前沿点揭示的是一种价值选择，而非技术优劣。

---

## Goal

基于文献中的实验数据，在多维效能空间中为每个解法绘制性能向量，识别帕累托前沿（在任意维度提升必须以其他维度为代价的方案集合），揭示领域内的根本性权衡约束——那些「不可能三角」。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点
- `paper_cards/parsed/` — Paper Cards，提取 Experiment / Result 章节的数值数据
- `working_memory/rq_{id}/B2.3-a_eval_meta_report.json` — 评估元分析（获取统一指标）
- `working_memory/rq_{id}/B2.3-c_baseline_fairness_report.json` — 基线公平性（过滤不可信数据）

## Execution Steps

### Step 1: 定义效能维度集合（KG驱动，非主观选择）

**为什么这样做**：维度选择如果主观进行，会引入分析者偏见——只分析自己关心的维度。正确做法是让KG数据告诉我们社区认为重要的维度：被多篇论文独立测量的指标，代表着该领域的共识。

从KG中提取所有 `metric` 节点：

```python
all_metrics = get_entity_by_type(loader, "metric")
# 对每个 metric，计算有多少方法通过 measured_by 边连向它
for metric in all_metrics:
    methods_using_metric = get_head_entity(loader, "measured_by", metric["id"])
    metric["usage_count"] = len(methods_using_metric)

# 筛选社区认可的核心维度：≥3 个方法测量过该 metric
endorsed_dimensions = [m for m in all_metrics if m["usage_count"] >= 3]
```

从 `endorsed_dimensions` 中选取 3~5 个作为分析维度（如：F1、FPR、推理时间、内存消耗、训练成本）。

对方向相反的指标（越高越好的 F1 vs 越低越好的 FPR），统一归一化为「越高越好」：归一化公式 `normalized = 1 - (raw / max_value)` 用于「越低越好」指标。

**决策条件**：若某维度 usage_count < 3，说明社区尚未就此维度形成共识，不纳入帕累托计算，但在报告中记录为「新兴维度」。

### Step 2: 收集方法性能向量（基于KG边追踪）

**为什么这样做**：直接从 Paper Cards 手工提取数字，容易遗漏或错读。正确做法是通过 KG 的 `measured_by` 边系统化枚举每个方法测量了哪些指标，再定向提取数据。

```python
all_methods = get_entity_by_type(loader, "method")
for method in all_methods:
    method_id = method["id"]
    # 获取该方法的所有 metric 节点
    metric_nodes = get_tail_entity(loader, "measured_by", method_id)
    # metric 节点的 description 字段通常包含测量值范围
    for metric_node in metric_nodes:
        value_hint = metric_node.get("description", "")
        # 记录到性能向量
```

对每个方法，从对应 Paper Card 的 Result 表格中提取在各维度上的性能值：
- 若某维度数据缺失，标注 `data: N/A`
- 若数据来自不可信对比（B2.3-c 标注为 Major 问题），标注 `data: unreliable`

**必须引用文献中的具体图表编号或实验数据片段来支撑取舍关系分析。**

**决策条件**：若某方法在 >50% 的核心维度缺数据，将其降级为「数据不足方法」，排除出帕累托计算，但保留在报告中供读者参考。

### Step 3: 计算帕累托前沿（显式支配关系判断）

**为什么这样做**：「哪个方法最好」是错误问题。正确问题是「哪些方法构成了权衡边界」——前沿上的每个点都是一种不同的价值权重选择，不存在客观上的「最好」。

对所有方法的性能向量，计算帕累托前沿（Pareto-optimal set）：

```python
def dominates(A, B, dimensions):
    """A 支配 B：在所有维度上 A ≥ B，且至少一个维度 A > B"""
    at_least_one_better = False
    for dim in dimensions:
        if A[dim] < B[dim]:  # A 在某维度劣于 B → A 不支配 B
            return False
        if A[dim] > B[dim]:
            at_least_one_better = True
    return at_least_one_better

pareto_frontier = []
for method_A in methods_with_data:
    dominated = False
    for method_B in methods_with_data:
        if method_B != method_A and dominates(method_B, method_A, dimensions):
            dominated = True
            break
    if not dominated:
        pareto_frontier.append(method_A)
```

**决策条件**：若帕累托前沿包含 >70% 的所有方法，说明维度选择可能不足以区分方法，需重新检查维度独立性（是否存在高度相关维度被重复计入）。

### Step 4: 分析核心权衡模式（寻找「不可能维度对」）

**为什么这样做**：帕累托分析的核心价值不是列出前沿方法，而是识别哪些维度之间存在根本性的负向权衡——这才是揭示技术约束的洞察。对每对维度，用文献证据验证权衡是否真实存在。

```python
for dim_pair in combinations(endorsed_dimensions, 2):
    D1, D2 = dim_pair
    # 在论文中搜索明确讨论该权衡的段落
    tradeoff_evidence = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"tradeoff between {D1} and {D2}|improving {D1} degrades {D2}|{D1} at the cost of {D2}",
        topk=5
    )
    # 同时检查帕累托前沿上的方法是否表现出该权衡的负相关趋势
```

对帕累托前沿上的方法，分析其权衡模式：
- 哪些维度之间存在强负相关（提升一个必然损害另一个）？
- 是否存在「万能方法」假象（在某数据集上全面领先，但可能存在数据集偏差）？

### Step 5: 识别各应用场景的最优推荐

根据不同应用场景对维度的权重偏好（如：医疗场景高优先 FPR，实时场景高优先速度），给出条件性最优推荐。

**推荐逻辑**：在帕累托前沿上，找到在该场景优先维度上得分最高的方法。推荐必须说明：「该方法在 [优先维度] 上表现 X，但代价是 [被牺牲维度] 降低了 Y」——没有代价说明的推荐是不完整的。

### Step 6: 对抗验证步骤（输出前必须执行）

**为什么需要对抗验证**：帕累托分析最常见的错误是遗漏关键维度，导致「前沿」实际上是局部前沿。在输出前，必须主动尝试推翻自己的结论。

对每个声称位于帕累托前沿的方法：
```python
for frontier_method in pareto_frontier:
    # 检查该方法的 limitation 节点
    limitations = get_tail_entity(loader, "has_limitation", frontier_method["id"])
    for lim in limitations:
        # 判断该 limitation 是否涉及已分析的某个效能维度
        # 如果是，该 limitation 可能意味着该方法在某条件下退出前沿
        evidence = get_evidence_papers(loader, lim["id"])
```

**决策条件**：若某前沿方法有 limitation 直接涉及分析维度，在报告中标注「条件性前沿」：该方法仅在特定条件下位于前沿。

### Step 7: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3

```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **性能数值必须精确引用来源**（`source: paper_id, Table X`），禁止估算或合并不同论文的数字。
- 跨论文的数字比较前，必须确认指标定义一致（如不同论文对 F1 的正类定义是否相同）。
- `data: unreliable` 的方法必须排除在帕累托计算之外，但仍在报告中保留标注。
- 若方法集合中 > 50% 缺少某维度数据，该维度必须从帕累托分析中移除，并在报告中声明。
- 「万能方法」（在所有维度全面领先）结论需高度警惕：若出现，必须检查是否存在数据集偏差（参考 B2.3-b）并执行 `has_limitation` 对抗检查。
- **效能维度的选取必须通过 KG 的 `measured_by` 边覆盖计数来驱动**，不得主观选择维度，`usage_count < 3` 的指标不得纳入核心帕累托计算。
- **认知坐标纪律**：本技能的核心产出不是「谁最好的排名」，而是「哪些权衡在当前技术条件下是不可逃避的」——如果分析结果只有排名而无权衡约束识别，分析是不完整的。
