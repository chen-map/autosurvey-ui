# Skill: B2.6-a 硬性资源与成本剖析

**层级**：S2.6 资源、可复现性与反馈核算层 · [V3 新增]  
**RQ类型**：花多少钱？能复现吗？（算力/数据/人力成本）  
**元认知逻辑**：从文献中提取方法的显式成本实体（GPU 时长、参数量、API 调用量、数据标注成本），构建可量化的成本画像，解决领域内的「成本黑盒」问题，为实用性评估提供经济维度。  
**认知基准面**：成本数据的缺失不只是报告不完整——它是「可部署性不透明」的信号；帕累托前沿上高性能但高成本的方法是部署瓶颈，不是技术成功。

---

## Goal

对 KG 中每个解法，系统性提取其训练和推理阶段的资源消耗数据，构建「成本画像」，对比不同方案的成本-效能比，识别高成本瓶颈和成本报告缺失问题，并将成本分析与帕累托前沿方法联动，判断哪些性能优秀的方法因成本问题无法实际部署。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点
- `paper_cards/parsed/` — Paper Cards，提取 Implementation / Training Details / Efficiency 章节
- `working_memory/rq_{id}/B2.4-a_pareto_report.json` — 帕累托分析（用于成本-效能联合分析）

## Execution Steps

### Step 1: 系统性扫描成本数据（全文搜索为主）

**为什么这样做**：成本数据散布在论文的各个章节（Training Details、Implementation、Appendix 等），仅查阅固定章节会大量遗漏。正确做法是用关键词全文搜索覆盖所有可能出现成本数据的位置。

```python
# 搜索计算成本的定量数据
compute_cost_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="GPU hours|training cost|A100|V100|RTX|CUDA|training time|inference latency|milliseconds per query",
    topk=15
)

# 搜索模型规模数据
model_scale_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="parameters|billion parameters|model size|7B|13B|GPT-4|number of parameters",
    topk=15
)

# 搜索 API 成本数据
api_cost_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="API cost|API calls|GPT-4 API|cost per query|tokens|OpenAI API",
    topk=10
)

# 搜索内存和数据规模
memory_data_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="memory requirement|GB RAM|training data|dataset size|annotation cost|human hours",
    topk=10
)
```

提取以下成本数据类型：
- **计算成本**：GPU 型号 × 数量 × 训练时间（如「8 × A100，24h」）；推理延迟（ms/query）
- **模型参数量**：参数总量（B 为单位）
- **数据规模**：训练数据量（样本数/Token 数/GB）
- **API 调用成本**：若使用商业 LLM API，调用次数或估算费用
- **人力成本**：人工标注/审查所需工时（若有）

### Step 2: 识别成本黑盒（无成本数据的方法）

**为什么这样做**：成本黑盒是一个领域性问题，不只是单个论文的遗漏。统计黑盒比例，可以量化领域的「部署透明度」——高黑盒率意味着实践者无法基于文献做成本预算，这是工业落地的系统性障碍。

```python
all_methods = get_entity_by_type(loader, "method")

cost_black_boxes = []
for method in all_methods:
    method_id = method["id"]
    # 获取该方法的所有证据论文
    evidence_papers = get_evidence_papers(loader, method_id)

    # 在每篇论文中搜索成本数据
    has_cost_data = False
    for paper in evidence_papers:
        cost_check = search_paper_sections(
            paper_cards_root="paper_cards/parsed",
            query="GPU|training time|parameters|memory|cost|latency",
            paper_ids=[paper["id"]],
            topk=3
        )
        if cost_check:
            has_cost_data = True
            break

    if not has_cost_data:
        cost_black_boxes.append(method_id)
        method["cost_reporting"] = "unreported"
```

**「成本黑盒」判断标准**：通过 `get_evidence_papers(loader, method_id)` 获取该方法的所有证据论文，在每篇论文中都找不到任何成本数据 → 成本黑盒。

**成本数字必须精确到论文中的 Table 或 Text，禁止估算或臆造。**

若完全未提及，标注 `Cost Unreported`；若仅有定性描述（如「高性价比」），标注 `Cost Qualitative`。

### Step 3: 统计成本报告状况（领域透明度评估）

```python
total_methods = len(all_methods)
full_reporting = count(m for m in all_methods if m["cost_reporting"] == "full")
qualitative_only = count(m for m in all_methods if m["cost_reporting"] == "qualitative_only")
unreported = count(m for m in all_methods if m["cost_reporting"] == "unreported")

full_reporting_rate = full_reporting / total_methods
unreported_rate = unreported / total_methods
```

**决策条件**：若 `unreported_rate > 0.6`，必须在报告中发出「领域成本透明度严重不足」的警示，并建议未来综述要求成本报告。高「成本未报告」比例是领域透明度问题的信号。

### Step 4: 构建成本-效能矩阵（联动帕累托前沿）

**为什么这样做**：成本分析的最高价值不是「哪个方法贵」，而是「哪些帕累托前沿方法因成本太高无法实际部署」——这些是部署瓶颈，是工业落地的关键障碍。

```python
# 加载 B2.4-a 的帕累托前沿方法
pareto_frontier_methods = B2_4_a_report["pareto_frontier"]

# 对有完整成本数据的方法，计算成本-效能比
for method in methods_with_full_cost_data:
    performance = get_performance_score(method["id"])  # 来自 B2.4-a
    normalized_cost = normalize_cost(method["compute_cost"])

    if performance and normalized_cost:
        method["efficiency_score"] = performance / normalized_cost

# 识别帕累托前沿上的高成本瓶颈
for frontier_method in pareto_frontier_methods:
    if frontier_method in methods_with_full_cost_data:
        if frontier_method["compute_cost"] > high_cost_threshold:
            frontier_method["deployment_bottleneck"] = True
            # 这是一个「技术上优秀但成本上不可行」的方法
```

结合 B2.4-a 的性能数据，对有完整成本数据的方法，计算成本-效能比：
```
efficiency_score = performance_metric / normalized_cost
```

识别「高效能低成本」的帕累托最优解法（成本效率前沿）。

**成本-效能比计算只对同时有成本数据（非 qualitative）和效能数据（非 unreliable）的方法执行，其他情况不得强行计算。**

### Step 5: 识别高成本瓶颈（成本驱动因素分析）

识别成本最高的组件（如「训练数据标注是主要成本来源」），分析是否有替代方案降低该成本（弱监督/合成数据）。

**成本瓶颈的分类**：
- `compute_bottleneck`：GPU 计算是主要成本驱动
- `data_bottleneck`：标注数据是主要成本驱动
- `api_bottleneck`：商业 API 调用是主要成本驱动
- `latency_bottleneck`：推理延迟阻碍实时部署

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **所有成本数字必须精确引用来源**（`paper_id, Table X` 或 `paper_id, Section X.X`），禁止任何形式的估算或合并不同实验的数字。
- `Cost Qualitative` 标注必须在正文中注明作者的原始表述（如「our method is 3× faster」），不得将定性描述转化为数字。
- API 成本若仅有调用次数无费用估算，只记录次数，不得将其换算为美元成本（因 API 定价会变化）。
- 成本-效能比计算只对同时有成本数据（非 qualitative）和效能数据（非 unreliable）的方法执行，其他情况不得强行计算。
- 若 > 60% 的论文成本数据为 `unreported`，必须在报告中发出「领域成本透明度严重不足」的警示，并建议未来综述要求成本报告。
- **成本黑盒识别必须通过 `get_evidence_papers(loader, method_id)` 追溯所有证据论文**，在每篇论文中都确认无成本数据才能标注为黑盒；不得仅因某篇论文无成本数据就标注整个方法为黑盒。
- **帕累托前沿 × 成本的联合分析是强制步骤**：必须明确哪些帕累托前沿方法因成本问题成为部署瓶颈，这是本技能对 B2.4-a 分析的核心增值。
- **认知坐标纪律**：成本分析的终极结论不是「平均成本是多少」，而是「将性能帕累托前沿与成本约束叠加后，实际可部署的方法集是什么」——这才是对实践者有价值的答案。
