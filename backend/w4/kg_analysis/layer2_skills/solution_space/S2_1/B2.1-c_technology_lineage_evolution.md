# Skill: B2.1-c 技术谱系演化分析

**层级**：S2.1 方案范式层 · Solution Paradigms & Frameworks  
**RQ类型**：用什么方案？（工具/框架演进）  
**元认知逻辑**：将技术流派（元范式）按年份绘制演化气泡图，标注关键工具/框架的出现节点，分析各流派的兴起、高峰、衰退时间段，识别范式迁移的时间拐点与驱动因素。  
**认知基准面**：谱系演化的真正信号不在于年度计数的高低，而在于 `extends` 链的方向性和 `contradicts` 边的集聚——当多篇同年论文的 `contradicts` 边指向同一旧范式时，那就是范式迁移的精确时间戳。

---

## Goal

基于 KG Method 节点的时间戳数据和 B2.1-a 的范式分类结果，构建技术流派的时间演化视图，识别「什么时候」哪个范式占主导，以及「是什么」驱动了范式迁移。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点，含年份信息
- `working_memory/rq_{id}/B2.1-a_paradigm_report.json` — 上游元范式分类（强依赖）
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `paper_cards/parsed/` — Paper Cards，提取范式迁移动机描述

---

## Execution Steps

### Step 1: 从 KG 边直接构建谱系图

**推理目标**：为什么从 KG 边出发而不是从年份统计出发？因为年份统计只能告诉你「什么时候有更多论文」，而 `extends` 和 `contradicts` 边能告诉你「论文之间的继承和否定关系」——后者才是演化结构，前者只是频率信号。

**操作流程**：

对每个方法节点，获取其出向边，过滤出谱系相关边：
```python
all_methods = get_entity_by_type(loader, "method")

for method in all_methods:
    out_edges = get_relation(loader, method["node_id"], "out")
    extends_out = [e for e in out_edges if e["edge_type"] == "extends"]
    contradicts_out = [e for e in out_edges if e["edge_type"] == "contradicts"]
    # extends_out: 该方法继承自哪些方法（其祖先）
    # contradicts_out: 该方法明确否定哪些方法/范式
```

`extends` 边构成的有向图即为谱系图（lineage graph）。其中：
- 每条 `extends` 边的 `evidence` 字段包含改进声明（evolution delta）——这是演化的「增量内容」，提取并记录为该继承关系的核心贡献
- `contradicts` 边的集聚点（被多个方法否定的节点）是旧范式的标志性代表

**决策条件**：若某方法既有 `extends` 边也有 `contradicts` 边（继承某些方法，同时否定另一些），该方法是范式过渡节点，需要特别标注。

### Step 2: 为每个方法分配年份并统计范式年度分布

**推理目标**：年份必须来自论文的实际发表年份（`papers.json` 中的 `year` 字段），而非方法节点中可能不准确的时间字段。方法的「首次出现年份」= 提出该方法的论文的发表年份。

**操作流程**：

从 `papers.json` 获取每个方法关联论文的年份：
```python
# 通过 proposes 边找到提出该方法的论文
proposing_papers = get_head_entity(loader, "proposes", method_id)
method_year = min([p["year"] for p in proposing_papers])  # 取最早发表年份

# 按范式统计年度分布
for paradigm in meta_paradigms:
    paradigm_methods = [m for m in all_methods if m["paradigm_id"] == paradigm["paradigm_id"]]
    yearly_counts = {}
    for m in paradigm_methods:
        year = method_year[m["node_id"]]
        yearly_counts[year] = yearly_counts.get(year, 0) + 1
```

同时，使用 `get_entity_by_constraint` 按 `created_at` 年份字段构建逐年范式种群计数，用于交叉验证：
```python
# 按年份过滤方法节点，构建年度快照
methods_in_year = get_entity_by_constraint(
    all_methods, "created_at", "startswith", str(target_year)
)
```

**时间数据质量检查**：若某方法的 `context_paper_id` 对应论文在 `papers.json` 中无 `year` 字段，标注 `year: unverified`，不得估算年份。

### Step 3: 识别范式兴衰阶段

对每个范式，通过论文数的时间序列识别阶段特征：
- **兴起期**：年论文数首次 > 2 篇的起始年份
- **高峰期**：年论文数最大的 2~3 年区间
- **衰退期**：连续 2 年以上年论文数下降 > 50%（单年下降不足以定论）
- **复苏/平台期**：下降后重新上升或维持稳定

**重要**：若分析时间跨度 < 3 年，标注 `temporal_analysis: insufficient_data`，演化结论可信度低，不得据此声称任何范式的兴衰趋势。

### Step 4: 用 `contradicts` 边集聚检测范式迁移拐点

**推理目标**：范式迁移不是渐变，而是突变——当一个年份段内多篇论文同时用 `contradicts` 边指向同一旧范式的代表方法时，这个集聚现象就是迁移的精确时间戳，比年度计数变化更可靠。

**操作流程**：

统计每个旧范式代表方法被 `contradicts` 的频次和时间分布：
```python
for old_method in paradigm_representative_methods:
    in_edges = get_relation(loader, old_method["node_id"], "in")
    contradicts_in = [e for e in in_edges if e["edge_type"] == "contradicts"]
    # 统计各年份的 contradicts 边数量
    contradiction_years = [get_paper_year(e["source_paper_id"]) for e in contradicts_in]
```

若某旧方法/范式在同一年份段（2年内）收到 ≥ 3 条 `contradicts` 边，标记为「范式迁移拐点」，记录该年份和指向该旧范式的新方法集合。

进一步验证：对新方法论文，搜索其对旧范式的批评文本：
```python
paradigm_shift_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="unlike previous|in contrast to|fails to handle|cannot address|prior work ignores|we argue against",
    paper_ids=[new_method_paper_ids_in_transition_year],
    topk=5
)
```

### Step 5: 标注关键里程碑方法

**推理目标**：什么是「里程碑方法」？不是被引用次数最多的方法，而是「催化了后续演化方向的方法」——具体表现为：大量后续方法通过 `extends` 边指向该方法，且这些后续方法分布在多个不同的子分支。

**操作流程**：

统计每个方法被 `extends` 的入度（有多少方法继承了它）：
```python
for method in all_methods:
    in_edges = get_relation(loader, method["node_id"], "in")
    extends_in = [e for e in in_edges if e["edge_type"] == "extends"]
    downstream_count = len(extends_in)
    # 若 downstream_count >= 5，候选里程碑方法
```

对候选里程碑方法，追溯其在文献中的原始引用：
```python
evidence_papers = get_evidence_papers(loader, milestone_method_id)
```

确认这些下游方法是否分布在不同的研究方向（不同的 paradigm_id），若下游方法都集中在同一范式内，则该方法是范式内的重要工作，而非跨范式里程碑。

### Step 6: 识别范式迁移驱动因素

**推理目标**：驱动因素的分类（技术驱动 vs 问题驱动 vs 效果驱动）必须来自文献原文的 Introduction / Motivation 章节，而不是后验推断。

**操作流程**：

对每个识别出的范式迁移拐点，从新兴范式的代表论文中搜索动机描述：
```python
motivation_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="motivated by|the emergence of|driven by the need|recent advances in|the advent of",
    paper_ids=[transition_paper_ids],
    topk=3
)
```

驱动因素分类：
- **技术驱动**：Motivation 中明确提及新基础技术/模型的出现
- **问题驱动**：Motivation 中明确提及新威胁/新场景的出现
- **效果驱动**：Motivation 中明确提及旧范式性能不足（需有数字支撑）

若搜索结果不足以支撑任何驱动因素分类，标注 `driver_type: undetermined`，不得由 LLM 构造迁移叙事。

### Step 7: 对抗性验证——反事实检验

**推理目标**：演化叙事最容易犯的错误是「幸存者偏差」——只关注成功的范式迁移，忽略「曾经被预测会替代旧范式但最终没有成功」的案例。对抗性验证要求主动寻找反例。

**操作流程**：
- 找出在某年份有 `contradicts` 边指向旧范式，但其自身后来也进入衰退（近 2 年无论文）的方法
- 这些「失败的挑战者」是演化叙事的重要修正——旧范式的替代并非必然
- 在输出中记录 `failed_challengers` 列表，避免将演化描述为线性单向的必然进程

### Step 8: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **年份数据必须来自 `knowledge_graph/nodes/papers.json` 的实际发表年份**，不得使用 KG 节点中未经验证的时间字段。
- 范式「衰退」判断需连续 2 年以上数据支撑，单年下降不足以定论。
- 关键里程碑方法的「催化作用」声明需有下游 `extends` 引用数据支撑（`downstream_extends_count`），不得仅凭直觉声称某方法具有里程碑意义。
- 范式迁移驱动因素的识别必须引用相关论文的 Introduction / Motivation 章节描述，不得由 LLM 构造迁移叙事。
- 若分析时间跨度 < 3 年，必须标注 `temporal_analysis: insufficient_data`，演化结论可信度低。
- **`extends` 边的 `evidence` 字段是 evolution delta 的唯一可信来源**，不得从方法描述中推断演化增量。
- 每次执行必须包含失败挑战者的反事实检验，避免将演化描述为线性单向进程。
- **认知坐标规则**：每次执行在 Checkpoint Output 第一行记录认知坐标，格式为 `[认知坐标: S2.1 · 谱系边驱动的演化重建 · <本次分析的时间跨度和范式集合>]`。
