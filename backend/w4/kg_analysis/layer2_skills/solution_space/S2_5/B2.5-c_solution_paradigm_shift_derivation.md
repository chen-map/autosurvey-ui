# Skill: B2.5-c 范式转移推导（解决域）

**层级**：S2.5 成熟演进层 · Maturity & Engineering Challenges  
**RQ类型**：离实用多远？（进化方向）  
**元认知逻辑**：在 Solution Space 内识别当前解法范式的「失效点」（天花板），引入跨域概念作为下一代解法的底层逻辑，构建跃迁路线图，说明新范式如何突破当前硬性约束。  
**认知基准面**：范式转移的客观触发器是：当前范式中存在「无任何方法有 relaxes 边指向」的 assumption 节点——这是硬性约束；新范式 = 引入一个外部变量，使该 assumption 不再是必要前提。

---

## Goal

基于 B2.4-c（系统性缺陷天花板）和 B2.5-a（工业落地断层）的分析结论，结合 A1.5-c 在 Problem Space 识别的跨域新概念，为 Solution Space 构建「下一代解法范式」的雏形和跃迁路线图。

## Execution Steps

### Step 1: 从 KG 识别硬性约束（无 relaxes 边的 assumption 节点）

**为什么这样做**：「范式失效约束」不能靠主观判断，必须有客观标准。客观标准是：在 KG 中，存在一个 assumption 节点，所有当前范式内的方法都 `requires` 它，而没有任何方法有 `relaxes` 边指向它。这就是数学意义上的硬性约束——当前范式无法在自身框架内突破它。

```python
all_assumptions = get_entity_by_type(loader, "assumption")

hard_constraints = []
for assumption in all_assumptions:
    assumption_id = assumption["id"]
    # 依赖该假设的方法（requires 边）
    dependent_methods = get_head_entity(loader, "requires", assumption_id)
    # 尝试松弛该假设的方法（relaxes 边）
    relaxing_methods = get_head_entity(loader, "relaxes", assumption_id)

    if len(dependent_methods) >= 2 and len(relaxing_methods) == 0:
        # 有多个方法依赖，但没有任何方法成功松弛 → 硬性约束
        assumption["is_hard_constraint"] = True
        assumption["dependent_count"] = len(dependent_methods)
        assumption["dependent_methods"] = [m["id"] for m in dependent_methods]
        hard_constraints.append(assumption)
```

**决策条件**：若 `hard_constraints` 为空（所有约束都有对应的松弛方法），则当前范式尚未到达天花板，本技能必须在报告中声明「当前范式尚未到达硬性天花板，新范式推导缺乏必要性」，并停止分析。

### Step 2: 分析硬性约束的底层机制（从约束到范式核心假设）

**为什么这样做**：仅知道「存在硬性约束」不够，需要理解「该约束为什么在当前范式框架内不可突破」。这需要追溯该约束在当前范式的角色——它是保证方法 correctness 的前提，还是保证 efficiency 的条件，还是保证 generalizability 的假设？

对每个硬性约束：
```python
for hard_constraint in hard_constraints:
    # 从 B2.4-c 获取该约束对应的失败模式
    associated_failures = lookup_failures_by_assumption(
        hard_constraint["id"],
        B2_4_c_report["common_failure_patterns"]
    )

    # 搜索文献中对该约束本质的讨论
    constraint_nature_snippets = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"assumes|requires|relies on {hard_constraint['name']}|fundamental assumption",
        paper_ids=[p for m in hard_constraint["dependent_methods"]
                   for p in get_evidence_papers(loader, m)],
        topk=5
    )
```

对每个硬性约束，明确：
- 该约束来自当前范式的什么核心假设？
- 该假设在什么新技术/新环境下将不再成立？

**提出的跨域概念必须具备逻辑推演过程（Why it works），禁止罗列空洞的流行词。**

### Step 3: 发现可溶解约束的外部变量（文献信号 + 推测分层）

**为什么这样做**：外部变量的识别需要区分「文献已经发现了这个方向」（高置信度）和「我们推测这个方向有潜力」（低置信度）。混淆两者会让路线图失去可信度——必须明确标注每个外部变量的置信层级。

```python
# 从 Paper Cards Future Work 章节找文献已提及的突破方向
future_signals = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="future work if|would enable|paradigm shift when|when X becomes available",
    topk=10
)

# 搜索已有方法开始探索的新方向
emerging_approaches = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="recent advances in|emerging approach|new paradigm|promising direction",
    topk=10
)
```

同时，从 A1.5-c 的候选跨域概念列表中，筛选与硬性约束相关的概念。

对每个识别到的外部变量：
- `confidence: literature_hinted` — 文献中有直接信号
- `confidence: speculative` — 基于逻辑推演，无直接文献支撑

**若所有外部变量均为 `speculative`，新范式蓝图整体置信度降级为 `speculative`，不得声称为确定性预测。**

### Step 4: 构建下一代解法范式蓝图

**约束消解逻辑**：新范式 = 当前范式 + 外部变量引入 - 被溶解的硬性约束。

对最有潜力的外部变量，构建新范式蓝图：
- 新范式的核心架构变化（与当前范式的关键差异）
- 新范式下哪些当前方法的组件可以复用（部分继承）——必须是已有具体实现的组件
- 新范式需要什么新的基础设施/工具（工程前提条件）

**「可复用组件」必须是当前范式中已有具体实现的组件（可引用具体论文），不得声称抽象概念可复用。**

### Step 5: 绘制跃迁路线图（依赖序排列）

**为什么这样做**：路线图的价值在于「哪个里程碑是其他里程碑的前提」——这个依赖序决定了实际研究的先后顺序。不考虑依赖的路线图只是愿望清单，不是工程路径。

```python
# 识别里程碑之间的依赖关系
milestones = [
    {"id": "M1", "description": "建立新范式所需的基准评估集", "type": "benchmark",
     "prerequisite": None, "timeframe": "near_term_1-2y"},
    {"id": "M2", "description": "实现外部变量的集成原型", "type": "tool",
     "prerequisite": "M1", "timeframe": "near_term_1-2y"},
    # ...
]

# 按依赖序排列，确保「哪个约束消解使其他约束消解成为可能」的顺序正确
ordered_milestones = topological_sort(milestones, key="prerequisite")
```

给出从当前范式到新范式的迁移路径，包括：
- 关键里程碑（如「首先需要建立 X 基准」）
- 技术依赖（先有 A 才能有 B）
- 预期时间（近期 1~2 年 / 中期 3~5 年 / 远期 > 5 年）——必须基于文献中的技术成熟度描述，不得凭 LLM 主观估计

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **跨域概念「Why it works」推演是强制要求**，不可仅写「引入 X 技术可以提升效果」，必须解释 X 的哪个机制解除了哪个约束。
- 外部变量若为 `speculative`，新范式蓝图整体置信度降级为 `speculative`，不得声称为确定性预测。
- 时间框架估计（近/中/远期）必须基于文献中的技术成熟度描述，不得凭 LLM 主观估计；若无文献支撑，标注 `timeframe_basis: inferred`。
- 「可复用组件」必须是当前范式中已有具体实现的组件（可引用具体论文），不得声称抽象概念可复用。
- 若 B2.4-c 的失效约束数量为 0（无范式级缺陷），必须在报告中说明当前范式尚未到达天花板，新范式推导缺乏必要性。
- **硬性约束的客观判据**：必须通过 `get_entity_by_type(loader, "assumption")` 枚举所有 assumption 节点，筛选「dependent_count ≥ 2 且 relaxing_count = 0」的节点作为硬性约束候选；不得通过主观判断直接声明某约束是「硬性约束」。
- **认知坐标纪律**：本技能的核心产出是「新范式如何通过引入外部变量溶解具体 assumption 节点」的精确映射，而非模糊的「未来方向」描述——若路线图只有愿景而无约束溶解的机制，分析是不完整的。
