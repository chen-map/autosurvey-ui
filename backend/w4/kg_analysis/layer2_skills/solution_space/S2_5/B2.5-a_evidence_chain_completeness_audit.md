# Skill: B2.5-a 证据链完整性审计

**层级**：S2.5 成熟演进层 · Maturity & Engineering Challenges  
**RQ类型**：离实用多远？（工业适配）  
**元认知逻辑**：将研究生态视为「理论→算法→工具→工业应用」的完整证据链，标记每级的文献质量与数量，定位证据链的薄弱环节（如：理论丰富但工具稀缺），将缺失环节定义为工业落地障碍。  
**认知基准面**：研究成熟度 = 理论到工业部署的距离；两级之间的断裂点 IS 当前最大的工程瓶颈——量化它，而不只是描述它。

---

## Goal

对 Solution Space 中的每个解法（及解法集群），绘制从理论模型到工业部署的证据链，识别哪些层级文献充足、哪些层级存在断层，量化「工业就绪度」（TRL 类似指标），并精确定位断裂点处的工程阻碍。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点，含论文类型标签
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `paper_cards/parsed/` — Paper Cards，提取 Evaluation / Implementation / Deployment 章节
- `analyze_report/design_report.md` — RQ 定义

---

## Execution Steps

### Step 1: 定义三级证据链（标准明确化）

- **L1 理论层**：提出形式化模型/算法/证明的论文，发表于顶级学术会议（如 S&P、CCS、ICSE 等）
- **L2 工具层**：有开源实现、可复现实验、工具论文（如 TSE、ISSTA 等）
- **L3 工业层**：在真实工业数据集/生产环境测试的论文或工业报告（venue 为工程实践类或有企业合作者）

**分级的底层逻辑**：L1→L2 的跨越是「能不能用」，L2→L3 的跨越是「能不能在真实规模下用」。断裂点定位要回答「卡在哪一步」。

### Step 2: 将文献分级（KG 数据驱动 + 文本搜索双轨）

**为什么这样做**：单纯依靠 venue 标签分级会遗漏大量信息——很多 L2 工具论文发表于 L1 会议，很多 L3 工业应用埋在 Related Work 段落中。正确做法是同时使用 KG 结构特征和全文搜索。

**L2 分级（工具层识别）**：

```python
# 方法 1：KG 结构特征 — code_url 属性存在
l2_by_code_url = get_entity_by_constraint(
    papers, "description", "contains", "code available"
)
# 或者 description 中包含 "open source"
l2_by_open_source = get_entity_by_constraint(
    papers, "description", "contains", "open source"
)

# 方法 2：全文搜索
l2_text_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="code available at|open source|github.com|implementation available|tool released",
    topk=20
)
l2_papers = union(l2_by_code_url, l2_by_open_source, l2_text_evidence)
```

**L3 分级（工业层识别）**：

```python
# 搜索工业部署的明确证据
l3_deployment_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="production environment|industrial deployment|real-world system evaluation|deployed at scale",
    topk=10
)
l3_enterprise_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="company|enterprise|deployed at|industry partner|in practice at",
    topk=10
)
l3_papers = union(l3_deployment_evidence, l3_enterprise_evidence)
```

**L1 分级**：未归入 L2/L3 特征的理论论文，默认从 venue 和 abstract 特征判断。

**决策条件**：一篇论文可同时属于多个级别（如同时有理论证明和开源代码 = L1+L2）。**工业应用的证据必须包含真实的工业级数据集测试或企业部署报告，不得仅凭大数据集测试推断为 L3。**

### Step 3: 绘制各方案集群的证据链（基于范式交集分析）

**为什么这样做**：证据链分析应该在范式层面进行，而不是针对单个方法。范式层面的 L1/L2/L3 比例，揭示的是整个技术路线的成熟度，而不是个别论文的特点。

```python
# 对每个范式（来自 B2.1-a 的分类），计算其 L1/L2/L3 论文数
for paradigm in paradigms_from_B2_1_a:
    paradigm_method_papers = get_paradigm_papers(paradigm["id"])

    l1_in_paradigm = intersect(paradigm_method_papers, l1_papers)
    l2_in_paradigm = intersect(paradigm_method_papers, l2_papers)
    l3_in_paradigm = intersect(paradigm_method_papers, l3_papers)

    paradigm["evidence_chain"] = {
        "L1_count": len(l1_in_paradigm),
        "L2_count": len(l2_in_paradigm),
        "L3_count": len(l3_in_paradigm)
    }

    # 断裂点识别：密度骤降的层级
    if paradigm["L1_count"] > 3 and paradigm["L2_count"] <= 1:
        paradigm["rupture_point"] = "L1_L2"  # 理论丰富但工具稀缺
    elif paradigm["L2_count"] > 1 and paradigm["L3_count"] == 0:
        paradigm["rupture_point"] = "L2_L3"  # 工具存在但无工业验证
    else:
        paradigm["rupture_point"] = "none"
```

### Step 4: 量化工业就绪度，并定位断裂点处的工程障碍

**为什么这样做**：就绪度数字本身没有价值，除非我们能回答「为什么卡在这个分数」。断裂点处的工程障碍才是报告的核心价值——这直接指向下一步研究需要解决的工程问题。

基于证据链分布，给出每个方案集群的工业就绪度评分（0~5）：
- 0：仅有理论
- 1：有算法实现
- 2：有开源工具
- 3：有学术规模评估
- 4：有工业规模评估
- 5：已在生产环境部署

**对断裂点处的工程障碍进行深入分析**：若断裂点在 L1→L2（理论丰富但工具稀缺），需找出 L1 方法的哪些 limitation 阻碍了工具化：

```python
for l1_method in l1_in_paradigm:
    if l1_method not in l2_in_paradigm:
        # 该 L1 方法未能产出 L2 工具，找原因
        engineering_blockers = get_tail_entity(loader, "has_limitation", l1_method["id"])
        # 筛选涉及工程实现的 limitation（如内存消耗、运行时间、依赖复杂性）
```

### Step 5: 对抗验证步骤（防止虚假 L3 声明）

**为什么需要对抗验证**：「工业部署」是容易被夸大的声明——很多论文将「在公开数据集上大规模测试」描述为工业应用。对抗验证的任务是：对声称 L3 的论文，找到明确的部署证据，而非仅有规模声明。

```python
for claimed_l3_paper in l3_papers:
    # 验证：是否有明确的「生产环境」或「真实用户」描述
    verification_snippets = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query="evaluated on production|real users|deployed system|in production since",
        paper_ids=[claimed_l3_paper["id"]],
        topk=3
    )
    if not verification_snippets:
        # 未找到明确的部署证据 → 降级为 L2（有工具但无工业验证）
        claimed_l3_paper["level"] = "L2"
        claimed_l3_paper["l3_claim_unverified"] = True
```

### Step 6: 识别最紧迫的落地障碍

对就绪度 ≤ 2 的方案，识别其从当前级别提升到下一级别的主要障碍，并链接到 B2.4-c 的天花板分析（若障碍是范式级的，则工业化本身也是范式问题）。

### Step 7: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **L3 工业证据必须包含真实工业数据或企业部署**，仅在大数据集上测试不等于工业级验证，需有企业合作者或明确的「生产环境」描述。
- **L2 判断必须使用 KG 数据和文本搜索双轨验证**：先用 `get_entity_by_constraint(papers, "description", "contains", "open source")` 和代码链接查询，再用全文搜索补充；不得仅凭 venue 标签推断 L2。
- 工业就绪度评分必须基于证据链数据，不得凭 LLM 对某方法「感觉成熟度」主观评分。
- 若某论文同时满足 L1/L2/L3 标准，在各级别计数中均计入，不限制为单级别归属。
- 断裂点的识别需要量化依据：若 L1 有 10 篇但 L2 仅有 1 篇，标注断裂点，并在报告中解释这意味着什么工程挑战。
- **对抗验证 L3 是强制步骤**：对每个归类为 L3 的论文，必须执行 `search_paper_sections` 验证「production environment|real users|deployed system」关键词，未找到明确证据的需降级为 L2 并标注 `l3_claim_unverified: true`。
- **认知坐标纪律**：本技能的核心产出是「断裂点处的工程障碍清单」，而非就绪度分数列表。若报告只有分数而无「为什么卡在这一级」的工程分析，分析是不完整的。
