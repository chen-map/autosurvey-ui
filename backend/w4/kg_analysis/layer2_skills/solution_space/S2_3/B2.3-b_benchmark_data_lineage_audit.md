# Skill: B2.3-b 基准审计与数据谱系审查

**层级**：S2.3 验证度量层 · Evaluation Metrics & Benchmarks  
**RQ类型**：效果好不好？（实验设计）  
**元认知逻辑**：不信任论文报告的数字，而是追溯这些数字来自哪些数据集，审查数据集的「血统」（来源、构建方式、覆盖范围），识别数据集缺陷对结论可信度的影响。  
**认知基准面**：数据集偏差的危险性不在于单篇论文的结论失真，而在于当整个领域都用同一有偏数据集时，所有「SOTA」比较都在一个失真的坐标系中进行——识别这类系统性偏差需要跨数据集的横向审计，而不是逐篇论文的独立审查。

---

## Goal

对 Solution Space 评估中使用的所有基准数据集进行系统性谱系审查，揭示数据集构建的隐性偏差，评估这些偏差对方法性能声明的可信度影响。重点识别「被广泛使用但存在系统性偏差」的数据集——这类数据集对领域评估结论的影响最大。

---

## Inputs

- `knowledge_graph/nodes/dataset_nodes.json` — KG 数据集节点
- `knowledge_graph/edges/` — 论文与数据集的 `evaluated_on` 边
- `paper_cards/parsed/` — Paper Cards，提取 Dataset / Evaluation Setup 章节
- `working_memory/rq_{id}/A1.4-b_evaluation_audit_report.json`（可选）— Problem Space 侧的审计结果

---

## Execution Steps

### Step 1: 以 KG dataset 节点为基础枚举所有评估数据集

**推理目标**：为什么从 KG dataset 节点出发而不是从 Paper Cards 的 Dataset 章节出发？因为 `get_entity_by_type(loader, "dataset")` 能枚举 KG 中所有经过规范化的数据集节点，避免因论文中数据集名称表述不一致（如缩写 vs 全名）导致的重复计数或遗漏。

**操作流程**：

```python
all_datasets = get_entity_by_type(loader, "dataset")
# 每个 dataset 节点有 node_id, canonical_name, description, label 字段
```

对每个 dataset 节点，统计有多少论文以其作为评估基准：
```python
for dataset in all_datasets:
    papers_using_dataset = get_head_entity(loader, "evaluated_on", dataset["node_id"])
    usage_count = count(papers_using_dataset)
    # 高 usage_count = 事实标准基准（de facto standard benchmark）
    # 低 usage_count = 小众或新兴数据集
```

筛选被 ≥ 2 篇论文使用的数据集作为主要审计对象。仅被 1 篇论文使用的数据集标注 `benchmark_status: single_use`，列入附录。

**优先审计顺序**：usage_count 最高的数据集优先审计，因为其偏差影响面最广。

### Step 2: 执行数据谱系审查

**推理目标**：谱系审查的目标不是列出数据集属性，而是追问「这个数据集能代表真实部署场景吗？」——来源、标签方式、覆盖度这三个维度共同决定了数据集的代表性边界。

**操作流程**：

从 Paper Cards 的 Dataset 章节提取谱系信息：
```python
for dataset in priority_datasets:
    origin_papers = get_head_entity(loader, "evaluated_on", dataset["node_id"])
    origin_paper_ids = [p["context_paper_id"] for p in origin_papers]
    
    lineage_snippets = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query="dataset collected from|data source|annotation process|labeling methodology|we collected|constructed from|crawled from",
        paper_ids=origin_paper_ids,
        topk=3
    )
```

审查维度表：

| 审查维度 | 要提取的信息 | 高风险信号 |
|---------|------------|---------|
| **来源** | 真实程序/生成的合成样本/人工构造/历史漏洞库 | 合成样本代表性不足 |
| **标签来源** | 人工专家标注/自动化工具/弱监督/论文作者自标 | 作者自标 = 高偏差风险 |
| **标签粒度** | 函数级/文件级/项目级/提交级 | 粒度与任务不匹配 |
| **语言/平台覆盖** | 单语言/多语言，覆盖几个 CWE 类别 | 单语言数据集用于多语言方法评估 |
| **时效性** | 数据集创建年份，是否包含近期漏洞/威胁 | 创建年份距今 > 5 年 |
| **规模** | 样本数量，正负样本比例 | 正负比 > 10:1 或 < 1:10 |

若文献未披露数据集来源，强制标注为 `source_type: unknown`，这是高风险信号，相关论文结论可信度至少标记为 `moderate` 降级。

### Step 3: 识别高风险偏差类型

对每个审查维度，判断是否存在会导致评估结果虚高或失真的偏差：

**标签噪声**：
- 自动化工具标注 → 误标率通常 10%~30%，需搜索论文中的噪声讨论
- 作者自标 → 确认偏差风险，论文作者可能无意识地标注对自己方法有利的样本

**分布偏移**：
- 数据集构建时的分布 vs 真实部署环境的分布
- 特别关注：时间偏移（旧数据集中的模式是否仍然代表当前现实）

**正负不平衡**：若正负样本比 > 10:1 或 < 1:10，分析其对各评估指标的扭曲效应：
- 极度不平衡 → Accuracy 虚高（全预测多数类即可达到高 Accuracy）
- 需检查论文是否使用了 Balanced Accuracy 或 MCC 等平衡指标

**数据泄露**：需有具体证据（如同一数据集同时出现在训练集和测试集的描述中），不得基于猜测声明数据泄露。

### Step 4: 问题分类法覆盖度交叉检验

**推理目标**：即使单个数据集内部没有偏差，如果评估中使用的所有数据集只覆盖了 problem 分类法的子集，整体评估结论对未覆盖的 problem 类型是无效的。这是数据集层面的「领域覆盖盲区」。

**操作流程**：

从 A1.1-a（若已执行）获取 problem 分类法；若未执行，从 KG 的 problem 节点类型重建：
```python
all_problems = get_entity_by_type(loader, "problem")
problem_categories = cluster_by_canonical_name(all_problems)
```

对每个数据集，检查其 `description` 和 Paper Card 描述中覆盖的 problem 类型：
```python
coverage_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="covers|includes|contains|focuses on|limited to|only includes",
    paper_ids=dataset_origin_paper_ids,
    topk=2
)
```

将数据集覆盖的 problem 类型与完整 problem 分类法对比，识别覆盖缺口（coverage_gap）：
- 若某 problem 类型在分类法中存在，但没有任何数据集覆盖它 → 绝对覆盖盲区
- 若某 problem 类型只有一个数据集覆盖 → 单点依赖，该类型的评估结论可靠性低

### Step 5: 评估偏差对各论文结论的影响

对每篇使用了有问题数据集的论文，判断该数据集偏差是否会系统性地夸大其方法的性能：

**影响程度评估**：
- **major**：使用了有标签噪声 + 分布偏移 + 正负不平衡三重问题的数据集，或来源未披露（`source: unknown`）的数据集
- **moderate**：存在其中一到两个问题，但作者未在论文中讨论该偏差
- **minor**：存在偏差但作者在 Discussion/Limitation 章节明确讨论了该偏差（作者已知悉，读者可自行判断）

**特殊处理**：若某论文在 Dataset 章节明确讨论了数据偏差，该论文的置信度无需额外降级（作者已知悉并讨论了局限）。

### Step 6: 对抗性验证——事实标准基准的系统性偏差审查

**推理目标**：使用最广泛的数据集（de facto standard benchmark）最需要深度审查，因为其潜在偏差会传播到最多论文的结论中。对抗性验证要求专门针对高频数据集执行最严格的谱系审查。

**操作流程**：
- 找出 usage_count 最高的前 3 个数据集
- 对这 3 个数据集，搜索所有引用它们的论文中对该数据集的批评性描述：
```python
benchmark_critique = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="limitation of this dataset|benchmark does not|dataset bias|not representative|dataset is limited",
    paper_ids=all_paper_ids_using_top_benchmark,
    topk=5
)
```
- 若高频数据集存在已知偏差但社区仍广泛使用，标注为「高风险共识基准」（high_risk_consensus_benchmark），这是一个需要在最终报告中突出的重要发现

### Step 7: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **`get_entity_by_type(loader, "dataset")` 是数据集枚举的主要来源**，必须在 Step 1 执行；不得仅从 Paper Cards 文本统计数据集使用情况。
- 所有审查结论必须来源于 Paper Cards 的 Dataset 章节；若某数据集的谱系信息完全无法从文献中获取，必须在所有使用该数据集的论文标注 `dataset_provenance: unknown`。
- `label_source: undisclosed` 是高风险信号，必须在报告中突出，相关论文的结论置信度至少标记为 `moderate` 降级。
- 正负样本比例若 > 10:1 或 < 1:10，必须分析这对精确率/召回率评估的扭曲效应。
- 「数据泄露」风险的识别需要有具体证据，不得基于猜测声明数据泄露。
- 若某论文在 Dataset 章节明确讨论了数据偏差，该论文的置信度无需额外降级。
- **高频使用数据集（usage_count Top 3）必须接受最严格的对抗性审查**，包括专门的批评性文献搜索。
- 问题分类法覆盖缺口分析是必选步骤——必须将数据集覆盖的问题类型与完整 problem 节点集合对比。
- **认知坐标规则**：每次执行在 Checkpoint Output 第一行记录认知坐标，格式为 `[认知坐标: S2.3 · 数据集谱系偏差传播审计 · <本次审计的数据集集合和重点偏差类型>]`。
