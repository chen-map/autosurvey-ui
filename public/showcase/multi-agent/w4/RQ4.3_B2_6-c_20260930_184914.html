摘要

本报告针对 RQ4.3「现有防护机制（鲁棒聚合、对抗检测、隐私约束）在协作编排层面是否可组合，缺口在哪里」进行系统性证据分析。核心结论是：三类防护机制在协作编排层面**仅能实现单层局部组合，无法形成端到端的可组合防线**，系统性缺口集中在编排层（orchestration layer）。

证据显示，轻量对抗防御只能降低而不能消除攻击——TAMAS 基准中 delimiter 防御对直接提示注入的 ASR 仅下降 5.2 个点，paraphrasing 防御虽移除 94% 注入指令却破坏 48% 良性查询，monitor-based 检测则频繁假阳性且决策不稳定[1]；TRiSM 综述将「Agent orchestration」列为被现有防护共同忽视的独立威胁面，其被攻陷或错误配置会触发级联失败[2]；MCPXKIT 实证表明 MCP 共享上下文缺乏隔离，成为攻击传导通道[3]。隐私侧证据（iDLG 可从梯度以 100% 准确率提取标签[4]）与鲁棒聚合侧证据（FedDANE 在异质下稳定劣于 FedAvg[5]；鲁棒性仅随良性/恶意 agent 比例上升而增强[6]）共同揭示隐私—鲁棒—检测三角张力。最优干预点是编排层的统一策略执行点与通信通道内建鲁棒性。

核心发现一：单层检测有效但不可组合

TAMAS 是首个系统评测多智能体 LLM 系统安全性的基准，包含 300 个对抗场景与 100 个良性场景，覆盖 5 个高风险域与 6 类攻击[1]。其防御实验揭示了一个关键矛盾：检测类防护一旦与协作流程耦合，会把「安全增益」转化为「可用性损耗」[1]。

具体而言，delimiter 防御对直接提示注入仅带来 5.2 个点的 ASR 下降；paraphrasing 虽在 94% 情况下移除注入指令，却在 48% 的实例中同时删除了良性指令本身，导致「表面防御成功实为任务移除」[1]。monitor-based 防御虽能停止系统执行，但触发大量假阳性，且同一 trace 在不同步骤的判定相互矛盾（先判危险后判安全）[1]。作者自述这些防御「只能降低而非消除漏洞」[1]。这种可用性损耗会倒逼系统引入更多 agent 或更多轮交互来补偿，从而扩大攻击面，构成反馈回路的起点。

核心发现二：编排层是被共同忽视的盲区

TRiSM 综述明确列出「Agent orchestration」为 Agentic AI 的独立威胁面：集中式或分布式 orchestrator 中介角色与工作流，其被攻陷或错误配置会导致信息错路并触发级联失败[2]。同一综述指出，Agentic AI 系统「攻击面大于传统 agent，需要分层防御保护数据、执行、通信与模型鲁棒性」，但现有机制「针对多智能体设定的一致性不足」[2]。

MCPXKIT 的实证进一步印证该盲区。它系统归类了 31 种 MCP 攻击（四大类：直接工具注入、间接工具注入、恶意用户攻击、LLM 固有攻击），并给出四条关键洞察：MCP agent 盲目依赖工具描述（「盲目服从」）；共享上下文缺乏隔离导致链式攻击（感染式攻击可将漏洞复制到新工具）；agent 难以区分外部数据与可执行指令[3]。其攻击效能量化表显示，SQL 注入/API 窃取、文件注入、工具覆盖等攻击成功率高达 90–100%[3]。现有防御（MCP-Scan 扫描器、MCP Guardian 中间件、defense-in-depth 策略）仅沿「服务端扫描」与「交互监控」两条单一路径，彼此未在编排层做联合决策，MCPXKIT 将「设计动态防御框架」列为未来工作[3]。

TAMAS 亦发现：面对 Byzantine agent、Colluding agents、Contradicting agents 这类**编排层特有**攻击，系统整体「高度脆弱」；提示注入类攻击跨模型基本一致（model-agnostic），交互式攻击成功率随配置在 27.4%–56.4% 波动[1]。这说明检测与聚合机制都没有把「交互拓扑」本身当作防护对象。

核心发现三：隐私—鲁棒—检测三角张力

在联邦/分布式协作中，三类机制存在可量化的内在张力。

隐私侧：iDLG 证明可从交叉熵损失对正确标签激活的梯度符号（位于 (−1,0) 区间）与错误标签（位于 (0,1) 区间）的相反规律中，**以 100% 准确率**提取真实标签，并据此显著提升数据提取保真度[4]。这证明隐私约束无法与「明文梯度可见的聚合」共存，必须引入加密或扰动。

鲁棒侧：FedDANE 旨在处理统计异质与低参与，虽有凸与非凸收敛保证，但经验评估显示其「稳定地劣于 FedAvg 与 FedProx」，作者将原因归于梯度校正项的代价与统计异质[5]。这印证异质感知聚合本身已很脆弱。Tu et al. 的对抗通信实验给出更强约束：系统鲁棒性**仅随良性/恶意 agent 比例上升而增加**；单一攻击者随良性 agent 增多而减弱，但多攻击者可协同优化扰动增强攻击，且迁移攻击需对齐中间表示分布[6]。

检测侧：上述鲁棒性依赖参与规模与交叉验证信号，而隐私约束（最小化数据交换、去中心化）恰恰限制了这些信号；鲁棒性的不足又需更强检测；而更强检测需要更多运行时遥测与数据暴露[2]。三者叠置形成闭合张力。TRiSM 指出 SMPC 可用于跨组织联合计算而无数据泄漏，但同态加密「计算昂贵」，且侧信道仍是未解难题[2]。

对证据矩阵论文的定位

本子问题冻结的证据矩阵论文主要提供协作编排框架与安全防御的上下文，而非直接回答可组合性问题：

- MultiAgentESC[7] 提出三阶段（对话分析、策略审议、响应生成）免训练协作框架，局限性为难以区分相似策略与策略使用偏置——均属任务性能层面，未涉及安全防护组合。

- LONGAGENT[8] 采用 leader-member 协作处理 128k 长文档问答，其错误主要源于成员 agent 在 chunk 无相关信息时虚构答案（成员幻觉），通过共享文本块缓解——这一幻觉传播机制正是编排层「错误级联」的实例，佐证编排层风险传导，但原文未做安全防御分析。

- NADER[9]、MCCD[10] 分别提出神经架构设计、组合扩散生成的多智能体协作框架，其局限性（推理开销随对象数增加、探索低效）亦与安全无关。

- OSINT 框架[11] 与 Agentic AI 供应链防御[12] 涉及工具编排层与安全（BFT 共识、区块链安全账本），是最接近「编排层防护」的正面案例，但聚焦单一域、未做跨机制组合评测。

这表明：协作框架论文普遍聚焦任务性能，其局限性均不涉及防护机制可组合性，佐证「编排层防护组合」为系统性文献空白。

分析局限性

其一，**缺乏联合评测基准**。尚无任何基准同时评测「鲁棒聚合+对抗检测+隐私约束」的组合效果。TAMAS 自认「仅评测攻击，防御基线非常有限、不作全面防御研究」[1]；MCPXKIT 将「动态防御框架」列为未来工作[3]；TRiSM 仅给出防御纵深的概念清单与治理对照表，未做组合实验[2]。因此「可组合性」判定部分依赖间接证据。

其二，**反馈回路严重度无法定量累加**。由于缺乏可比的严重度数据，FL-1「总风险是否超过原始问题」只能声明为「可能超过」，属不确定性结论。

其三，**跨社区外推风险**。多智能体 LLM 协作安全（TAMAS/MCPXKIT/TRiSM）与联邦学习安全（iDLG/FedDANE/Tu et al.）分属两个证据社区，二者交集——即在 LLM 多智能体编排上同时施加 FL 式隐私与鲁棒聚合——在 132 篇语料中缺乏直接实验证据，本报告中该部分为跨社区外推，置信度较低。

其四，**回路证据强度不均衡**。FL-1 的最弱边（假阳性→可用性下降）仅有定性描述，闭环长度超过 4 跳的可信度阈值。

其五，**因果方向验证仅部分完成**。部分因果边依赖单篇论文的叙述性证据，缺乏多源交叉验证。

上述局限使本分析的 `answer_completeness` 评为 `partial`（部分回答）。

结论

RQ4.3 的核心答案是：现有防护机制（鲁棒聚合、对抗检测、隐私约束）在协作编排层面**仅能实现单层局部组合，无法形成端到端的可组合防线**，缺口集中在未被任何单一机制覆盖的**编排层**。

三条证据主线支撑该结论：(1) 单层检测有效但不可组合，检测与协作流程耦合会把安全增益转化为可用性损耗[1]；(2) 编排层（orchestrator、共享上下文、工具调用）是被现有防护共同忽视的独立威胁面，恰是次生风险的传导节点[2][3]；(3) 隐私约束、鲁棒聚合与对抗检测在目标上存在可量化的内在张力，三者交集在编排层为空，形成隐私—鲁棒—检测三角张力[4][5][6]。

可识别的反馈回路 FL-1（检测→假阳性→可用性下降→增补 agent→攻击面扩大→再依赖检测）长度为 5，方向部分验证、证据强度中等，其最弱因果边即最优干预点。改进优先级为：高优先级——编排层统一策略执行点（Policy-as-code）[2] 与通信通道内建鲁棒性[6]；中优先级——上下文隔离设计约束[3]；低优先级——末端隐私加固[4][2]。

最终判断：跨机制防护的组合成效**尚无任何基准联合评测**，编排层的可组合防护是本领域最突出的系统性空白，也是以最小代价打断反馈回路的关键着力点。
