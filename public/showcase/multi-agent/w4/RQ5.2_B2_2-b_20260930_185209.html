摘要

本报告针对研究问题 RQ5.2「通信工程约束（latency、bandwidth、dedicated control channels、delay-free 假设）在协作架构中被如何处理或简化」，对证据矩阵冻结的六篇论文执行了 IPO（Input-Process-Output）数据流拆解与 I→P、P→O 边界信息损耗审计。核心结论是：在这六篇协作架构论文中，通信工程约束的处理呈现明显的三分格局——仅 Who2com [1] 把带宽作为一等设计目标显式建模并量化优化；6G 多智能体论文 [2] 把约束工程性转移为「调度/计算延迟优化」而非信道建模；其余四篇（NADER [3]、MCCD [4]、DesignGPT [5]、MACRec [6]）则完全默认消隐 latency、bandwidth、信道与 delay-free 等约束，将智能体间通信视为零成本、瞬时、无差错的信息传递。

换言之，本批多智能体协作架构处理通信约束的主流范式是「假设理想信道 + 用架构设计间接规避」，而非「显式信道建模」。这一发现与经典 Comm-MADRL 领域对通信约束的系统性分类（[7] 的 limited bandwidth / noisy / cost 维度）形成鲜明的方法论落差。图谱结构亦佐证该结论：KG 中确实存在 Perfect control channels、TDMA scheme、Packet erasure channel 等精细通信工程假设节点，但它们归属于无线 MAC 协议学习论文 [8][9]，与本次六篇冻结论文之间不存在 requires 边，说明本批架构论文在知识图谱建模层面即缺失通信工程假设。

核心分析一：显式带宽建模——Who2com 的孤例价值

Who2com [1] 是六篇中唯一把「带宽敏感通信」（problem_bandwidth_sensitive_communication）明确列为问题的方法。其 I→P 边界是将多智能体 RGB/深度图像与 pose 通过 message/key/value 三类生成器解耦编码，P→O 边界则解耦为「低维 request message + 匹配分数 + 高维特征图」的非对称输出。作为知识图谱中显式标注的 targets 边，该方法直接针对 bandwidth_sensitive_communication 问题 [1]。

关键量化结果：在语义分割任务上，Who2com 以「约四分之一带宽（a quarter of the bandwidth）」达到与中心化方法可比的精度，相对 CatAll 基线整体精度提升 16.51%，相对 Compression 基线提升 20.06%，mIoU 相对提升 29.49% [1]。消融实验显示 message size=4、key size=8/1024 的非对称配置即饱和性能，message 与 key 无需传输的特性使其带宽随智能体数量扩展时增长有界 [1]。

然而，Who2com 亦显式声明并简化了一条通信约束——「我们假设智能体间链路成本相等（equal cost links）」，把 per-link cost 差异留作未来工作 [1]。这意味着它只建模了「传多少」，未建模「传到哪里成本更高」，其带宽模型仍是同质信道假设。

核心分析二：工程性转移——6G 论文的延迟规避

6G 多智能体论文 [2] 是六篇中最接近通信工程语境的方法，但其约束处理属于「工程性转移」而非「信道建模」。I→P 边界将多模态感知（视频、点云、信号）投射为标准化向量与自然语言意图；处理逻辑是双环结构（外环任务分解、内环 LLMCompiler 并行工具调用），P→O 输出为 DAG 拓扑的工具调用方案 [2]。

[2] 把 latency 作为可测量指标，通过并行工具拓扑 + 调度 offloading「降低任务执行延迟」，实验显示并行拓扑相对顺序 ReAct 方案在云执行与边缘协作两种模式下均降低延迟，多设备协作优于单点执行 [2]。但关键在于：其优化对象是计算与调度延迟，而非信道传输延迟；智能体间消息传递被默认为内部、可靠、瞬时。带宽与信道问题被整体推入「Open Challenges」章节——论文明确承认多轮推理涉及私有数据与执行参数交换会带来「excessive communication overhead」与信息泄露风险，需通过 key information extraction、routing、加密通信等未来机制解决 [2]。这本质上是对延迟约束的工程化规避，把信道代价外部化为「未来工作」。

核心分析三：默认消隐——四篇通用协作框架的隐性假设

NADER [3]、MCCD [4]、DesignGPT [5]、MACRec [6] 均把智能体间通信实现为无约束的自然语言对话或共享记忆，未提出任何带宽、延迟或信道假设。NADER 的 Reader/Proposer/Modifier/Reflector 通过「multi-round dialogue」协作 [3]；MACRec 的 Manager/Analyst/Reflector/Searcher 通过对话式 inter-agent communication 协作 [6]；DesignGPT 用「chat room style interface」模拟设计公司会议 [5]；MCCD 的 conductor/evaluator 协调六类 agent 做前向 CoT 与后向反馈 [4]。

这些方法的「通信成本」只以隐式形式出现。MCCD 自陈「推理开销随物体/边界框数量增加而增加」，即延迟以对象数量为代理被间接感知，并将高效推理优化列为未来工作 [4]。MACRec 将通信实现为共享对话历史，未量化 token 或传输成本 [6]。依据 [7] 的 Comm-MADRL 分类体系，这些方法实质落在「Unconstrained communication」类别——通信信道、消息内容、是否通信均未被显式限制。

值得强调的是：图谱结构本身构成证据。KG 中存在「Perfect control channels」（控制消息无差错）、「TDMA scheme」、「Packet erasure channel（TBLER 建模）」等精细通信工程假设节点，但它们归属于无线 MAC 协议学习论文 [8][9]，与六篇冻结论文之间没有 requires 边。即本批协作架构在知识图谱建模层面即缺失通信工程假设，这与正文的「默认消隐」结论相互印证。

IPO 边界信息损耗审计

I→P 边界损耗方面：Who2com 的输入是图像特征，处理是端到端可微压缩，损耗表现为几何 warping 误差与匹配误差——论文提及不准确 pose 下 BIS 下降但方法仍鲁棒 [1]。6G 论文的输入含多模态感知，处理前的 denoise/align 步骤是信息损失的来源，但论文未量化 [2]。四篇对话式框架的 I→P 边界损耗集中在「自然语言 → 结构化动作」的转换：NADER 的 Architect 图表示故意剥离文本样式与格式以聚焦结构，属选择性丢弃 [3]；DesignGPT 用 BLIP 把图片转文本描述再拼入 prompt，是二次信息损失 [5]。

P→O 边界损耗方面：MCCD 的处理内部有丰富的中间表示（六 agent 多轮解析 + 评估反馈），但输出压缩为边界框 + 描述文本，丢失了不确定性信息 [4]。6G 论文输出为 DAG 工具调用拓扑，但信道代价在输出层完全不可见 [2]。These 边界损耗大多未在 KG 中被 has_limitation 边覆盖——仅 MCCD 的「推理开销随对象数增加」被显式建模为 limitation 节点，其余通信相关的边界损耗均为本报告新识别的隐性局限。

输入表示与处理算法的适配规律

基于六篇样本，可观察到输入表示与处理范式之间的关联规律（样本量小，仅作方向性观察）：6 篇中 1 篇（16.7%）采用感知特征输入并使用可微压缩处理（Who2com [1]）；1 篇（16.7%）采用多模态感知 + 意图输入并使用分层调度处理（6G [2]）；4 篇（66.7%）采用自然语言/结构化文本输入并使用对话式多智能体协作处理（NADER [3]、MCCD [4]、DesignGPT [5]、MACRec [6]）。

进一步的规律是：凡采用「对话式自然语言通信」范式的 4 篇，其通信约束均默认消隐、通信成本均不可测量；唯一涉及物理信道成本的两篇（Who2com、6G）分别来自具身感知与通信网络领域，而非通用 LLM 协作领域。这暗示「约束是否被建模」与「方法所处的应用领域」强相关——面向物理层的架构不得不处理信道代价，而面向应用层的 LLM 协作架构则系统性地将其消隐。

分析局限性

本报告存在以下局限与不确定性：

（1）结构性证据缺失：六篇中五篇（NADER [3]、MCCD [4]、DesignGPT [5]、MACRec [6]、6G [2]）在 KG 中未挂载任何 latency/bandwidth 相关的 assumption 节点（仅 MCCD 有推理开销 limitation），其通信约束处理只能从原文间接推断，缺乏结构化图谱证据支撑。

（2）缺乏可比通信成本指标：仅 Who2com 报告 bandwidth（kpbf）、6G 报告延迟-工具数曲线，其余四篇无任何通信成本量化，导致无法在同一量纲下横向对比「约束处理程度」。

（3）delay-free 假设的量化违背缺乏直接实验：冻结集内没有一篇通过实验测量 delay-free 假设被违背的后果，本报告对该点的论证依赖外部锚点论文 CoDe [10]，其论断非直接针对六篇。

（4）样本量限制：仅六篇样本，上述分布与关联规律（如图 1、适配规律）仅作方向性观察，不具备统计泛化力。

（5）KG assumption 节点归属核查基于边查询结果：Perfect control channels 等节点与冻结集无 requires 边，但不能完全排除原文中存在未被 KG 建模的通信假设表述。

结论

RQ5.2 的答案可凝练为「三分格局 + 主流消隐」：

① 显式建模是极少数派——仅 Who2com [1] 把带宽作为一等目标，以四分之一带宽实现与中心化可比的精度（相对 CatAll 提升 16.51%、mIoU 相对提升 29.49%），但仍假设 equal cost links。

② 工程性转移是过渡形态——6G 论文 [2] 把延迟约束转化为调度/计算延迟优化，信道与带宽被推入 Open Challenges，实质是外部化而非建模。

③ 默认消隐是主流——NADER [3]、MCCD [4]、DesignGPT [5]、MACRec [6] 四篇（占比 66.7%）完全将智能体间通信视为零成本、瞬时、无差错，属于 [7] 定义的 Unconstrained communication；其中仅 MCCD 以对象数量为代理间接感知延迟。

④ 图谱与外部文献双重佐证：KG 中精细的通信工程假设节点（Perfect control channels、TDMA、Packet erasure channel）均归属 [8][9] 而非冻结集，冻结集与这些 assumption 节点无 requires 边；外部论文 CoDe [10] 直接批判既有协作研究普遍假设 delay-free communication。

⑤ 抽象层面的关键缺口：三种处理策略（显式建模 / 工程转移 / 默认消隐）概念互不可通约，本批协作架构尚未把通信工程约束抽象为统一的、可复用的协作设计维度——这正是父问题 RQ5 所追问的「约束如何被抽象为可复用设计维度」在本子问题上的核心障碍。建议后续工作显式引入信道成本、延迟、控制信道可靠性等约束维度，并报告可比的通信成本指标，以弥合物理层协作与应用层 LLM 协作之间的方法论断层。
