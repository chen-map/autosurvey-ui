摘要

本报告针对子问题 RQ3.2——「常用指标（Accuracy、Success rate、Pass@1、Completeness、Executability、Efficiency 等）的语义定义是否对齐，是否存在同名异义或同义异名？」——进行了系统性的知识图谱（KG）证据分析。分析基于 278 个 Metric 节点、454 个 Problem 节点、380 个 Method 节点、243 个 Dataset 节点、170 个 Limitation 节点、119 个 Assumption 节点，结合 6 篇冻结证据论文与多篇对照论文的原文段落核查，共完成 42 次工具调用、18 篇论文深读。

核心结论：**六类常用指标的语义定义系统性未对齐，同名异义与同义异名并存。** 以「Success rate」为例，同一 KG 节点（metric_metric_success_rate_dff5583d94）被 31 条以上 measured_by 边指向，但其定义在精确串匹配、操作可执行正确率、物理无碰撞/超时三类互斥语义间漂移 [1][2][3][4]；「Executability」在三个框架中分别为二值比例、1–4 序数量表、编译通过百分比，跨越两种测量层级 [5][6][7]；代码生成任务中 Pass@1、Success rate、Generation accuracy、Executability、Pass@5 实为同义异名 [5][14][7]。这一碎片化已被多篇综述明确承认为结构性缺陷 [8][9][10][11]。

发现一：同名异义（same-name-different-meaning）— 最突出的病灶

同名异义是本问题最严重且最具迷惑性的缺陷。KG 中「Success rate」作为单一节点，被 31 条以上 measured_by 边指向，说明论文群体普遍复用了同一标签，但定义彼此冲突。[1]（0203）将其定义为「A task is deemed successful only if its output exactly matches the ground-truth answer」（精确串匹配）；[2]（0337 LAFA）将其表述为「The percentage of generated FA operations that are executable and correct」，本质是执行计划（DAG）完成率，报告值在 95–100% 高位，而 zero-shot 仅 10–15%；[3]（0884）等机器人协作论文定义为「A task is considered failed if there are collisions, interferences between agents, or if the task times out」——把碰撞/超时计为失败；[4]（0892）更细化为五类失败条件（token 超限、未达成共识、语法检查迭代超限、规划迭代超限、碰撞）。同一标签，一处是精确串匹配，一处是操作可执行性，一处是物理无碰撞，语义不可通约。

「Executability」的异义跨越了测量层级这一更严重的鸿沟：[5]（0401 NADER）定义为「percentage of successfully executable modified architectures」（二值比例）；[6]（3810 MetaGPT）定义为「this metric rates code from 1 (failure/non-functional) to 4 (flawless)」（四阶序数量表）；[7]（3819 Croto）定义为「percentage of software that compiles without errors」（编译通过百分比）。同一个词在三处分别是比例、序数、比例，尺度与量纲完全不同，任何跨论文数值比较都失去意义。「Accuracy」节点关联约 50 条边，定义涵盖实体链接正确比例 [12]、分类准确率、二值响应正确性 [13]、数值精度 [14] 等多类任务。

发现二：同义异名（synonymy）— 相同定义使用不同标签

与同名异义相反，同义异名指多个不同标签实为同一底层度量。在代码生成任务中，Pass@1、Success rate、Generation accuracy、Executability、Pass@5 均在度量「生成产物是否通过语法 + 功能测试」这一事件，却使用不同名称。[5]（0644 MAHL）原文明确：「when we measure the pass rate, we only count it as a success when it passes both the syntax and functional tests」——这与 [7]（3819）的 Executability 定义（编译通过）与 [14]（0980）的 Task Success Rate（binary success/failure）指向同一底层事件。[5] 同时使用 Pass@1（简单 RTL 设计成功率）与 Pass@5（真实 chiplet 生成精度，从 0 提升至 0.72）两个标签，前者被 [16]（0283）称为 generation accuracy，又被 [3] 称为 success rate。

在软件质量维度上，同义异名体现为分解方案冲突：[7][8] 采用 Completeness–Executability–Consistency–Quality 四元组，而 [6]（MetaGPT）采用 Executability(1-4)–Cost–Code Statistics–Productivity–Human Revision Cost 五元组。二者共享 Executability，但其余维度几乎无交集，「软件质量」因此被两种不可比的方式分解。类似地，数据可操作性度量中，[2]（LAFA）用 Completion ratio + Operation count，[16]（NL2SQL）用 Execution accuracy + Validation efficiency + Cost per query（$0.0085），[17]（0210）用 Accuracy–Cost per Prompt–Latency 三维 Pareto 前沿，[18]（0523）用 Task accuracy + Transmission overhead + Robustness。

发现三：文献明确承认 taxonomy 缺失（重构动机的一手证据）

指标语义未对齐并非孤立现象，而是被多篇综述明确承认为结构性缺陷，这构成重构统一框架动机的文献级证据。[8]（0102 综述）直接针对 problem_problem_fragmented_landscape_of_llm_and_agent_evaluation_ca1b59cfad 指出：「The landscape of evaluation benchmarks, frameworks, and collaboration protocols for LLMs and autonomous AI agents is fragmented and lacks a unified taxonomy」，并以 Systematic review and unified framework 方法回应。[9]（3825）精准定位了「成功」的多义性：「The definition of success is often unclear as it can refer to either from the user perspective or from the environment/system，as users may not fully know what happens behind-the-scenes」——据此提出 Overall/Supervisor/User-side/System-side 四种 Goal Success Rate（GSR）以显式消歧。[10]（3827 具身智能综述）指出「lacking standardized evaluation criteria ... Existing benchmarks focus on task-specific metrics」。[11]（3831 TRiSM 综述）给出五维评估框架（Trustworthiness/Explainability/User-Centered/Coordination/Composite），并警告「scalarization can hide critical failures」，建议报告完整 metric vector 而非单一加权标量。

关键证据：[8] 明确使用「lacks a unified taxonomy」表述，是本 RQ 重构动机最直接的文献锚点；[9] 用 87–100% 的人工标注一致性验证了其四类 GSR 消歧方案的有效性（Table 10，agreement ratios 0.87–1.00），说明显式操作化定义可以恢复指标可比性。

发现四：语义漂移的量纲后果 — 跨任务数值不可比

指标语义未对齐的直接后果是跨任务数值不可比。以 Success rate 为例：[1]（0203）报告三个 agent 框架在 34 个编程任务上的成功率约 50%（TaskWeaver 58.82%、MetaGPT 50.00%、AutoGen 50.00%）；[2]（LAFA）报告 completion ratio 达 95–100%；[4]（0892）报告成功率随机器人数量增加先升后降。这三个数字看似同一指标，实则：前者失败判定基于 ground-truth 精确匹配，中者基于 DAG 结构有效性，后者基于五类物理/对话条件。直接比较会产生严重误导。

效率维度的量纲差异同样显著：[16]（0283）的 Validation efficiency（VES）= 51.05%，是将正确率与执行效率合并的复合指标；[2]（LAFA）的 Operation count 是 6 类 FA 操作的绝对计数（Acce/Enc/Aggr/DP/Dec/Cal）；[17]（0210）的 Cost per Prompt 以美元计；[18]（0523）的 Transmission overhead 以传输数据量计。四者分属比值、计数、货币、字节四种量纲，无法在同一坐标轴上比较。

分析局限性

本分析的证据覆盖存在若干不足，需审慎对待。第一，KG 中多数 Metric 节点的 origin_paper_id 字段为空，无法全量回溯每个定义的具体来源论文，因此「同名异义」的统计广度（如 Success rate 关联 31 条边 vs Accuracy 关联 50 条边）是基于抽样而非全量枚举。第二，本分析聚焦 6 篇冻结论文 + 12 篇对照论文，虽已覆盖六类指标全部命中同名异义/同义异名，但可能存在采样偏差——未被抽样的论文或许使用了更一致的定义。第三，对 Pass@k 在强化学习训练场景（如 [20] 1151 的 GRPO 训练）与推理场景的语义差异覆盖不足，而这两种场景下 Pass@k 的计算语义本就不同。第四，部分结论（如 Completeness 的异义）依赖单篇论文定义，置信度相对较低（0.85）。第五，指标对齐的「应然」标准本身在文献中存在分歧：[19]（0298）侧重定性分析，[21]（0204）ChaosEater 甚至声明「rather than creating a benchmark that focuses on quantitative metrics, we evaluate ... qualitatively」，这类立场与统一量化框架的诉求相冲突，说明重构统一框架面临方法论层面的阻力。

认知基准面纪律：本分析以「约束满足」为判断标准——指标定义只要满足跨任务可映射性与语义互斥性即合格，无需额外证明其直觉合理性；反之，直觉合理但跨论文数值不可通约的定义（如 Success rate 的三重语义）必须被标记为对齐失败。

结论

针对 RQ3.2，本分析的结论是明确的：**常用指标的语义定义系统性未对齐，同名异义与同义异名并存，且这一缺陷已被多篇综述明确承认为结构性 taxonomy 缺失。** 六类指标（Accuracy、Success rate、Pass@1、Completeness、Executability、Efficiency）无一例外存在跨任务、跨论文的语义漂移，其中 Success rate 与 Executability 的同名异义最为严重，跨越了比例/序数两种测量层级。

跨任务不可比的根因因此可以定位为：评测体系缺少「度量对象 × 操作化定义」的正交分解。文献中的消歧尝试提供了可借鉴的方向：[9]（3825）通过区分 user-side/system-side 视角提出四类 GSR；[11]（3831）主张报告完整 metric vector 而非标量复合，以避免「scalarization can hide critical failures」。

面向统一评测框架的构建，本 RQ 的启示是：应对每个指标强制执行「操作化定义登记」，将度量对象（产物正确性 / 过程有效性 / 资源代价）与测量尺度（比例 / 序数 / 计数 / 货币）作为两个正交维度固定下来，方能使跨任务数值具备可比性。后续 RQ 可聚焦于该正交分解的自动化归一化机制设计。
