摘要

针对 RQ4.1「多智能体 LLM 系统面临哪些被明确命名的对抗与安全威胁（adversarial risks、attacker capabilities、background knowledge）」，本分析基于冻结证据矩阵（3835 / 0689 / 1454 / 0210 / 0415 / 1692）及其在知识图谱中被明确扩展、对比或综合的相关节点，归纳出五类被明确命名、且攻击者能力与背景知识被系统形式化的威胁面：通信信道威胁、元数据/工具投毒威胁、隐蔽信道与数据泄露威胁、时序漂移威胁、可追溯性与问责性威胁 [1][2]。

分析采用二维认知坐标系——「攻击面/攻击者作用位置」× 「威胁性质（机密性/完整性/可用性/可问责性）」进行正交映射，结果显示热点区集中于提示注入与冒充、工具投毒、隐蔽信道三个象限，而「问责性×问责性」及「联邦学习×多智能体」交叉面则构成认知冷区，后者成因被判定为证据盲区（unknown_blind_spot）。整体回答判定为 answered，但联邦学习交叉子面为 partial。

数据来源与规模

本分析从知识图谱中系统提取了七类节点数据，覆盖问题（454 个节点，预览 30）、方法（380 个，预览 30）、论文（186 个，预览 30）、局限性（170 个，预览 30）、假设/约束（119 个，预览 30）、评估指标（278 个，预览 30）、数据集基准（243 个，预览 30）。

在实体分析之上，对 13 篇关键论文执行了 14 次 search_paper_sections 语义检索，深度精读其原文段落，包括冻结矩阵的六篇核心论文（Agent Drift 3835、Adversarial Attacks on Multi-Agent Communication 0689、MCPXKIT 1454、Traceability and Accountability 0210、Specification and Evaluation 0415、Whispering Agents 1692）以及被它们扩展/综合的相关论文（TAMAS 1728、AiTM 1719、MCP-TDP 0382、TRiSM 3831、Constraint Drift 3836、协议安全综述 3832、LLM 钓鱼 0235）。总工具调用次数 44 次。

认知坐标系与维度选择

维度选择不采用先验假设，而是从 KG 节点 description 字段的结构性模式归纳。所有威胁节点均以「攻击注入位置 + 危害后果」双属性被明确形式化（例如 TAMAS 的 prompt/agent/environment 三层攻击面 + 攻击目标；MCPXKIT 的 attack entrance + risk level + persistent impact scope），两维之间不存在因果或包含关系，正交性成立，故选定为坐标轴：

维度 A（攻击面/攻击者作用位置）：prompt-level、agent-level、environment-tool-level、communication-channel-level、temporal-drift；

维度 B（威胁性质）：confidentiality、integrity、availability、accountability。

核心发现一：通信信道威胁面

TAMAS [1] 在 Threat Model 章节首次把多智能体攻击者拆解为三要素：目标（使良性任务失败或触发恶意动作）、背景知识（知道各 agent 的角色与可用工具，但不知道 LLM 参数、对齐策略与架构细节）、能力（可在 prompt/agent/environment 三层注入）。其核心论断是「即便这种有限知识也足以打击系统最弱环节，被攻陷 agent 的输出会对抗性地在系统中传播」[1]。

在通信层面，AiTM（Agent-in-the-Middle）[6] 把威胁从「攻陷 agent」推进到「拦截并操纵消息」：攻击者不改变 agent profiles 与 capabilities，仅操纵受害者 agent 收到的消息，即实现全场景 >40%、多数实验 >70% 的攻击成功率，并在 MetaGPT/ChatDev 上造成实质破坏。

底层机制由 [5] 提供：当 agent 共享中间特征表示时，ε-有界的对抗消息即可严重降级感知性能（2 个 agent 时 AP@0.7 由 82.09 降至 0.90），白盒攻击在 agent 少时最强、随良性 agent 增多而减弱，迁移攻击需经域自适应（ADDA）对齐中间表示分布方能生效。

核心发现二：元数据/工具投毒威胁面

MCPXKIT [2] 把 MCP 生态攻击系统化为 4 大类 31 种命名攻击（File-Based Injection、Rug Pull、Shadowing、Tool Preference Manipulation、Infectious Attack、Privilege Escalation、Token Theft 等），并用四维攻击效能度量（S 成功率 / L 风险级 / I 持久影响 / D 实现难度）量化，显示 File-Based Injection、Malicious Tool Coverage、SQL/API Theft、Malicious Tool Enforce Execute 等可达 100% 成功率。

MCP-TDP [3] 将此类攻击命名为 Tool Description Poisoning（TDP），把攻击者能力形式化为「可在工具供应链发布/接管工具但不接触模型权重、仅修改 description 字段」，在 8 个 LLM 上取得 ASR>82%（顶级模型 >88%），并揭示「Firewall Fallacy」——关键词护栏对 LLM 仅降 15.3% ASR、对 Gemini 反而使 ASR 上升。

核心发现三：隐蔽信道与数据泄露威胁面

由于 A2A 只保护消息内容、不保护「通信行为本身」，[4] 把隐私威胁明确命名为针对 surveillance 与 traffic analysis 的漏洞，将攻击者能力形式化为「无处不在、可观测完整事件 Trace 的计算有界 Warden」，提出 Covert Event Channel（Storage/Timing/Behavioral 三维）；其实验中判别隐蔽事件的 LLM Warden 的 AUC 仅 0.503（等同随机猜测），证明该类威胁在现有监控下几乎不可检测。

TRiSM 综述 [11] 进一步把 AgentLeak 类数据泄露、记忆投毒（memory poisoning）、上下文操纵、语义欺骗、collusion/mode collapse 组织为 AMAS 特有威胁分类，并指出共享记忆与 agent 间通信会显著增加敏感信息非预期披露的概率。其延伸工作 [8] 用 AgentLeak 的 4,979 条轨迹证明「最终输出看似合规、而内部消息/工具调用/记忆写入仍在泄露敏感信息」。协议安全综述 [12] 则定义了经共享知识库与记忆模块的「内部/外部数字环境污染 + 慢性投毒」级联感染面。

隐蔽信道威胁的特殊性：标准 A2A 加密保护的是「消息内容」而非「通信行为」。当 agent 间存在频繁、并发、高度自动化的交互时，观察者即便无法读取内容，仅凭交互模式本身即可泄露战略信息（如物流 agent 与多艘自主舰船的加密通信模式可暴露资产调度）。[4]

核心发现四：时序漂移威胁面

Agent Drift [7] 命名了一个无需参数更新、无外部攻击者即可自发发生的威胁，分化为 semantic drift（意图偏离）、coordination drift（共识退化）、behavioral drift（策略涌现）三态，直接挑战以训练期目标为中心的 alignment 范式。关键机制在于：漂移无需重训练或微调，其根源在于上下文的累积条件化与采样过程，形成自反式反馈回路，近似于 specification gaming / reward hacking。

其直接延伸 [8] 将威胁命名为 Constraint Drift——安全关键约束在多智能体轨迹（摘要、委派、工具调用、记忆更新）中丢失操作性强制力，并明确区别于 prompt injection 与 reward hacking，属系统级保持失效。治理方案 Constraint State Governance（CSG）要求约束作为带签名的状态在委派中继承、关键动作前校验、事后可审计。

核心发现五：可追溯性与问责性威胁面

[9] 把威胁定义为「错误在串行管线中静默级联、最终输出错误却难以归因」的透明度丧失/调试困难问题。其研究采用 Planner→Executor→Critic 管线，量化角色特异风险：LLM Sonnet 4 作为 Executor 的 repair rate 达 10.01%（最高），Gemini 2.5 Pro harm rate 仅 0.25%（最低），LLM 作为 Critic 的 harm rate 最高（1.90%）。结构化 handoff 可防止失败级联、在 PythonIO 上提升超过 36 点准确率，代价是成本增加 2–3×、延迟从约 2s 升至 20–25s（8–10×）。

[10] 则提供了以规格语言 + 执行栈对多智能体系统进行评测的基础设施，把网络安全/服务器安全任务作为可自动评估的应用，用于威胁评测而非威胁本体。

热点区与冷区分析

热点区（密度前列）：① prompt-level × integrity（提示注入/冒充）；② environment-tool-level × integrity（工具投毒）；③ communication-channel-level × confidentiality（隐蔽信道/中间特征扰动）。这三类威胁均有成熟的命名分类体系与大量实证量化，是当前研究的密集地带。

冷区：① accountability × accountability（可追溯/问责，仅 2 篇且以评测基础设施为主）；② federated-learning × multi-agent 交叉面（证据缺口，成因判定为 unknown_blind_spot/数据集缺失）。[5] 仅在 Related Work 指出 FL 采用不同的 threat model（data/model poisoning），未对 LLM 多智能体给出 FL 对抗结论；[11] 对 FL 启发式隐私通信仅作展望。

分析局限性

其一，RQ4 父问题强调「多智能体协作 × 联邦学习」交叉地带，但冻结矩阵中直接刻画 FL 场景隐私/投毒攻击的节点很少，该交叉子面的对抗证据以推断性关联为主，标记为 partial，置信度受到限制。

其二，[7] 为仿真/理论建模研究，其 42% 等量化值为 projected，作者明确自承漂移与性能退化为相关而非因果，且最长观测窗仅 18 个月。

其三，[1] 的结论主要基于 AutoGen/CrewAI 两框架，泛化性受限；[2][3] 的沙箱评测规模有限；[5] 的结论基于 V2VNet/ShapeNet 感知任务，向 LLM 文本多智能体的迁移性未直接验证。

其四，[8] 作为 [7] 的延伸引用，未列为 RQ4.1 冻结核心论文，其结论应视为补充证据而非核心证据。

结论

多智能体 LLM 系统面临的对抗与安全威胁可被明确收敛为五大命名威胁面：①通信信道攻击（TAMAS 攻击者模型、AiTM 消息拦截、中间特征对抗扰动）[1][6][5]；②元数据/工具投毒（MCPXKIT 31 种命名攻击、Tool Description Poisoning）[2][3]；③隐蔽信道与数据泄露（Covert Event Channel、记忆投毒、AgentLeak）[4][11]；④时序漂移（Agent Drift 三态、Constraint Drift）[7][8]；⑤可追溯性与问责性失效（错误静默级联）[9]。

关键共识是：多智能体协作引入了单智能体场景不存在的涌现性风险——即便攻击者背景知识有限（仅知角色与工具、不知模型参数），也能通过弱链接与级联传播造成系统性破坏 [1]。防御层面普遍暴露出「外围护栏失效」（Firewall Fallacy）[3] 与「问责代价高昂」[9] 的两难。最大的认知缺口在于联邦学习与多智能体安全交叉地带，建议后续以 A1.1-c 分层堆栈分析补充该维度。
