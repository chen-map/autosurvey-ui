摘要

本报告针对 RQ2.2——集中式（SOP/固定角色）与去中心化（演化协调）路线在任务类型、可扩展性、鲁棒性上的权衡证据——进行了系统性的知识图谱（KG）多维效能分析。分析的核心结论是：两条路线之间不存在客观上的「最优」，而是一个条件性的帕累托权衡结构。集中式系统在任务准确性与可追溯鲁棒性上系统性占优：Flow-of-Action 用 SOP flow 将 RCA 准确率从 ReAct 的 35.50% 提升至 64.01%[1]，MetaGPT 的 SOP 装配线在代码生成上取得 85.9%/87.7% Pass@1[2]，Chatlaw 的固定角色 RA-MoE 在 LawBench 上较 LLM 提升 7.73%[3]。去中心化系统则在规模化扩展性与跨组织适应性上占优：AgentNet 以 DAG 路由与 RAG 内存构建自组织、容错架构[4]。

分析识别出一个不可逃避的三元约束（「不可能三角」）：无法同时最大化任务准确性、最小化成本/延迟、并实现 agent 数无上限线性扩展。集中式结构化的代价可量化——可问责管线成本增加约 2–3×、中位延迟从约 2s 升至 20–25s（约 8–10× 变慢）[5]。三篇直接对照实验（0892 的四框架比较[6]、AgentNet 的规模依赖实验[4]、MACNET 的缩放律[7]）一致指向混合/条件性方案而非任一路线全面胜出，其中混合架构（如 HMAS-2、异构可问责管线 CBA）在多数对照中落在帕累托前沿。

1. 研究背景与分析框架

本分析遵循 B2.4-a 多维效能空间帕累托分析方法，从 KG 中以 measured_by 边覆盖计数驱动效能维度选取，而非主观选择。核心问题不是「哪条路线更好」，而是「哪些权衡在当前技术条件下不可逃避」。分析通过 KG 一跳关系查询、六类节点（problem/method/paper/dataset/metric/limitation/assumption）的系统枚举，以及 14 段论文原文语义检索，为每个方法构建性能向量并识别帕累托前沿。

纳入分析的效能维度包括：任务准确性/成功率（多篇论文覆盖，usage_count 高）、成本（cost per prompt）、中位延迟（median latency）、token 消耗（token consumption）、通信成本（communication cost）。鲁棒性相关指标（error rates、fault detection rates）仅由单一论文[8]覆盖，usage_count<3，按分析纪律标注为「新兴维度」，不纳入核心帕累托计算。

3. 任务类型维度的权衡证据

结构化、有既定诊断/合规流程的任务强烈偏向集中式 SOP 编排。Flow-of-Action 将 SRE 标准操作流程显式编码为 SOP flow，把 ReAct 的 35.50% 准确率提升到 64.01%（LLM）；消融实验显示移除 SOP 知识后平均准确率从 54.06% 崩至 15.39%、移除 SOP flow 后定位准确率从 54.22% 跌至 15.11%，证明固定流程是准确性的决定性来源[1]。MetaGPT 将软件工程 SOP 编码为 prompt 序列，在 HumanEval/MBPP 上取得 85.9%/87.7% Pass@1[2]。Chatlaw 以模拟律所 SOP 的 RA-MoE 架构在 LawBench 上较 LLM 提升 7.73%[3]。

相反，当任务开放、无既定流程时，固定角色反而受限。AgentNet 明确批评静态预定义工作流「无法适应 agent 表现的实时波动与快速变化的任务需求」[4]。MetaGPT 作者亦承认其 SOP 装配线「难以满足真实世界应用的多样复杂需求」、无法覆盖 UI 与前端场景[2]。

4. 可扩展性维度的权衡证据

最直接的证据是 0892 的四框架对照实验。它在集中式 CMAS、去中心化 DMAS、混合 HMAS-1/HMAS-2 四种通信框架上，对 4–32 个机器人、四个协调依赖任务做了系统比较。结论是：混合框架 HMAS-2（中央规划 + 局部反馈）在全部四任务上取得最高成功率（3/6 机器人下达 100% 且步数最少）；去中心化的 DMAS 使用最多 API 调用与 token 且成功率最低——去中心化 agent 反复重述彼此观点、稀释关键上下文；纯集中的 CMAS 在小规模有竞争力，但随 agent 数显著退化，对复杂 Warehouse 任务在所有规模下都劣于 HMAS-2[6]。

MACNET 的协作缩放律显示性能随 agent 数呈 sigmoid 饱和（约 2^4 节点为合理点），集中式拓扑超过 30 个 agent 时频发上下文爆炸[7]。具身 LLM 团队实验发现 9 个 agent 的性能（60.67±15.06）反而不如 7 个（43.00±2.16），通信成本近乎线性增长[9]。但去中心化的规模优势是有条件的：AgentNet 自身实验显示 3 个 agent 时完全同质最优（0.86），引入多样性反而降到 0.81，只有到 5 个 agent 时异质性才转为优势（0.85 vs 0.79）[4]。

5. 鲁棒性维度的权衡证据

集中式 SOP 通过软约束降低幻觉：Flow-of-Action 将 SOP 作为关键节点的软约束（而非 FastGPT 式硬约束）以引导正确轨迹，同时在无匹配 SOP 时以 generate_sop 动态生成，保留了灵活性[1]。0210 证明结构化 handoff 能阻止失败级联，在 PythonIO 上把准确率从 61.42% 提升至 97.64%（+36.22 点）；但同一研究也测得严格 handoff 有时反而限制后续 agent 灵活性导致小幅准确率下降[5]。

集中式的鲁棒性代价可量化且高昂：可问责管线成本增加约 2–3×、中位延迟从约 2s 升至 20–25s（约 8–10× 变慢）[5]；集中编排器本身构成单点故障[4]。去中心化路线以牺牲部分协调确定性换取容错与隐私：AgentNet 用 DAG 路由构建「自组织、容错」架构，并通过 RAG 内存机制保护跨组织隐私[4]。AgentDropout 则证明动态节点/边消除在 layered/random 多种初始拓扑下都能稳定提升性能与 token 效率，即「结构鲁棒性」[10]。

6. 核心权衡模式与「不可能三角」

跨论文一致浮现「准确性–成本/延迟–可扩展性」三元约束。0210 显式给出准确率-成本-延迟的帕累托前沿，并确认「没有单一最优配置，选择取决于任务」，其结论明确将「异构管线」列为常处帕累托前沿的均衡选择[5]。3842 的 Puppeteer 用 RL 编排器同时改善性能与 token 效率，但需以 λ 权重在准确率与成本间可调，且其方案仍是集中式（与 AgentNet 的去中心化直接矛盾）[11]。3829 显示更强的 LLM 编排器带来更高准确率但成本同步上升[12]。

可辨识的「不可能三角」是：无法同时（1）最大化任务准确性、（2）最小化成本/延迟、（3）实现 agent 数无上限线性扩展。SOP/结构化增强准确率但增成本延迟（[1][5]），动态/去中心化增强扩展性但增协调开销与不确定性（[4][6]）。

分析局限性

（1）鲁棒性对照证据最薄弱：本子问题冻结矩阵指定的 0287 仅为研究计划（multivocal review + GitHub 分析），尚未产生集中式 vs 去中心化的定量鲁棒性结果[8]，故「哪条路线更鲁棒」在矩阵内缺乏直接对照实验。（2）跨论文数字比较受限：1665/0210/3810/0892 使用不同基准（GoogleOnlineBoutique/PythonIO/HumanEval/BoxNet）与不同指标定义（Location Accuracy vs Pass@1 vs success rate），不可直接合并排序；本报告中的数字均在各自论文上下文内引用，未做横向合并。（3）方法论共性局限：0210 指出结论基于多选基准、blame 依赖 ground-truth 标签[5]；1665 依赖历史 incident 匹配[1]；0892 的混合优势仅在 warehouse 类任务上验证，泛化性待检验[6]。（4）维度覆盖不足：鲁棒性作为正式效能维度因 usage_count<3 被排除在核心帕累托计算外，属「新兴维度」。（5）路线之争在文献中直接对立（3842[11] vs 3840[4] vs 0892[6]），冲突可能源于任务差异而非架构本质，本报告将其作为分歧点如实标注。

认知坐标纪律：本分析的核心产出不是「谁最好的排名」，而是「哪些权衡在当前技术条件下不可逃避」。分析识别出的根本约束是「准确性 × 成本/延迟 × 可扩展性」三元权衡——任何路线都必须显式选择牺牲维度。混合架构（HMAS-2、异构管线 CBA）在多数对照实验中落在帕累托前沿，提示「演化角色 + 中央协调」的组合可能是当前实践中的稳健折衷，但其证据仍限于特定任务域。

结论

针对 RQ2.2，文献证据给出的是一个条件性、无单一赢家的结论。集中式（SOP/固定角色）在任务准确性与可追溯鲁棒性上系统性占优[1][2][3][5]，去中心化（演化协调）在规模化扩展性与跨组织适应性上占优[4][6]。二者受制于「准确性 × 成本/延迟 × 可扩展性」这一不可逃避的三元约束，不存在客观意义上的最优路线。

最直接的对照实验证据（0892 的四框架比较[6]、AgentNet 的规模依赖实验[4]、MACNET 缩放律[7]）一致指向混合/条件性方案：混合架构 HMAS-2 在全部四个任务上取得最高成功率并最佳扩展[6]，异构可问责管线 CBA 常处成本-准确率帕累托前沿[5]，而固定 SOP 装配线在开放复杂任务上暴露边界[2]。

因此，路线选择应遵循条件性判据：结构化高合规任务选集中式 SOP，大规模/跨组织/动态任务倾向去中心化或混合，且任何路径都必须在准确性与成本-可扩展性之间做显式取舍。领域当前的核心证据缺口在于——集中式与去中心化在鲁棒性维度缺乏同基准对照实验（0287 尚未产出定量结果[8]），这是后续研究最值得填补的空隙。
