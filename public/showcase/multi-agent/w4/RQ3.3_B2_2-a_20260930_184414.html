摘要

本报告针对 RQ3.3「构建多智能体协作统一评测框架需要哪些维度、现有工作提供了哪些可复用组件」，对知识图谱中 186 篇论文（含评测基准、防御框架、工程脚手架、协议与安全五类文献）进行系统分析。结论：文献证据支持把统一评测框架拆解为 **六个正交维度**——任务类型、协作规模、错误容忍/鲁棒性、成本，以及 RQ 未列但证据反复出现的通信/协调效率、信任-安全-可解释维度。现有工作已沉淀出一批可复用组件（可配置任务图、断言式评测 harness、时序图异常检测器、双 agent 验证循环、对抗攻击基准、token 效率优化器、协议比较框架、MCP 安全工具箱），但它们分属评测、防御、工程三类文献，**没有任何一个工作把它们整合成端到端跨任务可比的框架**——这正是 RQ3 所述碎片化格局的技术根源 [1][2][3]。

按证据交叉验证，六个维度中「错误容忍/鲁棒性」是唯一已出现即插即用组件的维度（Guardian 异常检测器 [4] + TAMAS 对抗基准 [5]）；「成本」维度已拆解为成本倍数/延迟/token 三个可测子指标并有现成优化器（AgentDropout [6]、payload referencing [7]）；「协作规模」虽有三套可量化探针（DynTaskMAS [8]、AgentNet [9]、Guardian [4]）但缺乏统一报告协议；「任务类型」有可操作分类骨架（通信中心两层框架 [1]、基准元数据横评 [3]）但彼此不共享字段定义。综合判定完整性为 partial：维度可枚举、组件可复用、框架未闭合。

数据来源与规模

本分析基于 KG 结构化数据与论文原文语义检索两层证据。KG 节点规模：problem 454 个、method 380 个、paper 186 篇、dataset/benchmark 243 个、metric 278 个、limitation 170 个、assumption 119 个，覆盖六类节点。分析共执行 44 次工具调用，对六类节点均做了针对性查询（problem/method/paper/dataset/metric/limitation/assumption）。使用 search_paper_sections 对 19 篇关键论文做了原文精读，其中证据矩阵冻结论文 4 篇（1765 Marco、3839 Guardian、0798 Hallucination-Free AQG、2121 Hybrid Transceiver），扩展关键论文 15 篇（3828、0210、3825、0102、3827、3831、1728、1713、1695、1454、1805、1771、3818、3840、0571 等）。通过 get_relation 对 Marco、Guardian 两篇做了完整一跳关系边抽取，其余通过 search_paper_sections 与 get_candidate_entity 定位原文段落证据。

认知坐标：S2.2 · IPO数据流解剖 · 通用骨架 v1（基于证据矩阵 6 篇 + 扩展 13 篇，覆盖 LLM-MAS 评测/防御/工程脚手架/协议/安全五类文献）。证据矩阵中被冻结的 2121（多跳 MIMO 混合收发机优化）属物理层通信，其「统一 objective 下的解耦优化」是可迁移元模式而非 LLM-MAS 评测组件，已在结论中作为异质文献处理。

维度一：任务类型——已有可操作骨架但不共享字段

通信中心综述提出「系统级通信（架构/目标/协议）+ 系统内部通信（策略/范式/对象/内容）」两层分析框架，覆盖 flat/hierarchical/team/society/hybrid 五类架构与合作/竞争/混合三类目标，并系统对比 MCP、A2A、ANP 三种协议 [1]。全面综述用「多模态/任务多样性/推理/agentic」四列元数据横评约 60 个 2019–2025 基准：GAIA 人类准确率 92% vs LLM 仅 15%；MultiAgentBench 覆盖研究写作、Minecraft 建造、数据库错误分析等六域，测试 star/chain/tree/graph 拓扑，规划带来 3% 里程碑提升，但增加 agent 反而降低性能 [3]。涌现编排研究把拓扑细分为 chain/tree/graph 三型六子型，并证明拓扑会随演化从链式收敛为带环图 [10]。这些骨架彼此不兼容，直接印证碎片化。

维度二：协作规模——已出现可量化探针但未标准化

多条限制证据明确指出方法「仅测试到最多 6 个 agent」「主要聚焦两 agent 系统」[11][12]；具身协作综述直陈「当前参与协作的 agent 数量仍很小，规模化会带来计算、通信、协调、任务分配与资源管理的复杂度」[2]。现有可复用探针包括：DynTaskMAS 的 4→16 agents 吞吐近线性增长（12.3→42.7 tasks/s），32 agents 出现次线性（8×agent 仅 6.21×吞吐）；AgentNet 的规模×异质性实验显示 3 agents 时同质配置最优（0.86），5 agents 时异质配置反超（0.85），说明异质性仅在大团队获益；Guardian 在 MATH 上测 3–7 agents 及连接稀疏度 25%/50%/75%，准确率分别为 52.2%/56.1%/57.3%。

维度三：错误容忍/鲁棒性——唯一出现即插用组件的维度

Guardian 把协作建模为离散时间属性图（节点=agent、边=通信），用无监督编码器-解码器 + 信息瓶颈做异常检测，无需修改 LLM 即达 SOTA：异常检测率平均 >80%（FEVER 上 94.74%），FDR 最低 8.32%，靠协作天然冗余做到「每轮只移除一个 agent」的优雅降级；在 MATH 上连接稀疏度 25%/50%/75% 均优于基线。TAMAS 提供对抗鲁棒性协议：300 对抗 + 100 良性场景、5 域（教育/金融/医疗/法律/新闻）、6 类攻击、4-agent 系统，测 10 个 backbone 模型，并提出 Effective Robustness Score（安全×效用调和平均）与 ARIA 四级分类。二者构成「错误注入协议 + 错误检测缓解组件」的可复用组合。此外 MCPXKIT 提供 MCP 安全的四维 31 类攻击分类（直接/间接工具注入、恶意用户、LLM 固有权）与统一可复现攻击框架 [13]。

维度四：成本——已拆解为可测子指标并有现成优化器

可问责流水线量化了协作的代价：可问责流水线相对单体基线成本增加约 2–3×、中位延迟从 ~2s 升到 20–25s（约 8–10×），并得出「准确率-成本-延迟权衡依任务而定，异构流水线常处于 Pareto 前沿」[15]。AgentDropout 通过优化通信图邻接矩阵动态剔除冗余 agent/边，prompt token 降 21.6%、completion token 降 18.4%，同时性能提升 1.14 分 [6]。企业级 MAC 证明 payload referencing 在代码密集任务上相对提升 23%、通信开销降 27%，GSR 达 90% [7]。双 agent 验证循环用廉价 LLM（成本仅 o3-mini 的 1/11）即把幻觉降 >90% [14]。

补充维度：通信/协调效率 与 信任-安全-可解释

通信/协调效率维度：TRiSM 提出 Component Synergy Score（CSS）度量一个 agent 对同伴下游表现的使能程度（例：Planner 使 Coder 提速 35%、Tester 达 92% 覆盖率，单链路 CSS≈0.32），并用 Tool Utilization Efficacy（TUE）把工具调用分解为选择/参数/执行/结果/效率五分量 [16]。信任-安全-可解释维度：TRiSM 给出信任度指数 T = wacc·A + wrob·R + walign·L，并主张报告完整指标向量 M=(MT,ME,MU,MCo) 而非加权标量，以避免掩盖单维度失败与 Goodhart 效应；MCPXKIT 的四维攻击分类量化「agent 盲信工具描述」「共享上下文链式攻击」等漏洞 [13]；协议层 MCP/A2A/ANP/ACP 的架构-发现-格式-安全四字段对比表亦可复用 [1][17][18]。

核心分析结果：可复用组件清单

综合五个来源类别的证据，现有工作可被提炼为九类可复用组件。它们分别对应六个维度的不同环节，但缺乏统一接口，无法直接被一个端到端框架组装。

跨任务可比性的关键证据

支撑「跨任务可比」的三条核心证据：其一，Marco 的三层解耦使同一框架支持 RTL/DRC 代码生成、时序分析、布局优化等异构任务，是现有最接近跨任务骨架的组件 [19]。其二，可问责流水线在 AgiEval/PythonIO/LogiQA 三个基准上得出「结构化 handoff 使 PythonIO 准确率提升 >36 分、planner 质量主导（最佳 7.35% 错误率 vs 最差 40.49%）」的结论，并主张用「玻璃箱」而非「黑箱」评测 [15]。其三，TRiSM 明确指出标量化会掩盖单维度失败，应报告完整向量 M=(MT,ME,MU,MCo) 并用阈值/Pareto 选择模型 [16]。这三条共同指向：跨任务可比需要「解耦的任务骨架 + 不改写轨迹的评测协议 + 向量化报告」三要素，而当前没有任何工作同时满足。

分歧点、证据缺口与不确定性

第一，碎片化被多个工作独立确认为核心痛点——「缺乏标准化评测标准」[2]、「现有评测无法区分聚合强单体 agent 与真正涌现协作的架构」[1]、「单 agent 基准与多 agent 协作基准之间存在明确 gap」[2][20]——但没有任何证据集内工作交付端到端统一可比框架，故本子问题答案形态是「维度可枚举、组件可复用、框架未闭合」。第二，证据矩阵含异质文献：2121（多跳 MIMO 混合收发机）属物理层通信，其「统一 objective 函数下模拟/数字收发机无损解耦」是可迁移的元模式，但不提供 LLM-MAS 评测组件 [21]；这提示用户将其列入证据矩阵可能是想借用其「统一框架+解耦优化」的方法论范式。第三，多数成本/规模数字来自单一研究单任务族（如 2–3× 成本、21.6% token 降幅），跨研究可迁移性未经验证；协作规模维度除 DynTaskMAS/AgentNet/Guardian 三探针外缺乏统一报告协议。

分析局限性

（1）数据覆盖：KG 中 186 篇论文主题高度异质（含无线通信、量子通信、物理层优化等非 LLM-MAS 论文），通用骨架的归纳主要依据其中约 20 篇直接相关的 LLM-MAS 评测/防御/工程文献，可能遗漏证据矩阵外的重要评测工作。（2）推断置信度：六维度集合是跨论文归纳而非任何单一论文原生提出，属综合推断（confidence high 但非直接引用）；成本/规模的具体数值均标注为 medium 置信度，因来自单一研究且跨域迁移性未验证。（3）异质文献：证据矩阵冻结的 2121 属物理层通信，本报告仅将其「统一框架+解耦」作为元模式参考，未纳入 LLM-MAS 组件清单，构成证据边界而非结论。（4）鲁棒性声明的实验证据：TAMAS 与 Guardian 均仅在 Autogen/CrewAI 两框架或 3–7 agent 规模验证，「不兼容」类声明未在本报告中作出（因缺乏理论或实验证据，遵守不凭低共现率推断不兼容的约束）。

结论

针对 RQ3.3，回答分三层：（1）**需要哪些维度**——至少六个正交维度：任务类型、协作规模、错误容忍/鲁棒性、成本，加上证据反复出现的通信/协调效率与信任-安全-可解释维度 [1][2][16]。（2）**现有工作提供了哪些可复用组件**——至少九类：Marco 可配置任务图 [19]、企业级 MAC 断言式评测 harness [7]、Guardian 时序图异常检测器 [4]、双 agent 验证循环 [14]、TAMAS 对抗基准+ERS [5]、AgentDropout token 优化器 [6]、TRiSM 评测模板+CSS/TUE 指标 [16]、MCPXKIT 安全工具箱 [13]、协议对比框架 [1][17][18]。（3）**如何构建跨任务可比框架**——证据指向「解耦的任务骨架 + 不改写轨迹的评测协议（断言/handoff/ARIA）+ 向量化指标报告（非标量）」三要素组合，但当前无一工作同时满足，这正是下一步整合研究的方向。综上，答案完整性判定为 partial：维度可枚举、组件可复用，但端到端统一可比框架尚未闭合。
