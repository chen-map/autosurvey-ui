摘要

本报告针对 RQ5.1「自然语言协调中的歧义与上下文约束（context window size、context availability）如何影响协作正确性？」执行 A1.1-c 分层抽象栈分析。通过对知识图谱中 454 个 Problem、380 个 Method、186 篇 Paper 及 170 个 Limitation、119 个 Assumption、243 个 Dataset、278 个 Metric 节点的系统扫描，并结合对 6 篇冻结证据论文及 5 篇支撑论文原文段落的语义检索，归纳出一个五层技术栈模型（数据/上下文层 → 指令/歧义层 → 智能体推理层 → 通信/协调层 → 任务输出层）。

核心结论是：歧义与上下文约束通过「歧义/上下文缺口 → 幻觉与误解 → 错误级联 → 协作正确性下降」的跨层传播链损害协作正确性。歧义是根因层风险源点，上下文不足是放大器，通信/协调层是传播枢纽。量化证据显示：LongAgent 通过上下文共享使 LLaMA-2 7B 在长文档 QA 上分别较 LLM 提升 16.42% 与 1.63%[2]；可问责的结构化交接使 PythonIO 准确率提升超过 36 个百分点，但成本增加约 2–3 倍、延迟增加约 8–10 倍[5]；ColaCare 缺少外部上下文时死亡率预测 AUPRC 从 54.05 降至 51.57[4]。

核心机制一：歧义作为根因层风险源点

歧义首先在 L2 指令/歧义层产生。AgentCoord 明确指出「自然语言灵活性导致协调策略含糊，需要反复的补救式规定（repeated remedial specification）」，其用户研究记录了自由形式策略使「执行过程中途偏离用户预期并越走越远，甚至陷入无限循环」[1]。作者论证结构化表示能「对齐人与 LLM 的意图、强制双方基于同一套概念与抽象层级沟通，有效减少自然语言歧义导致的相互误解」[1]。

跨域佐证：MetaGPT 采用中间结构化输出（PRD、设计图、流程图、接口规范）「显著提升目标代码生成成功率，因为有助于保持沟通一致性、最小化协作中的歧义与错误」[10]。MultiAgentESC 把歧义的对偶问题——策略选择的「一对多」特性——视为协作正确性核心挑战，用相似案例与多智能体辩论缓解[3]。这些证据表明歧义并非表面措辞问题，而是被结构性重述所针对的根因层缺陷。

核心机制二：上下文约束的「信息丢失—幻觉—级联」三段式放大

L1 数据/上下文层通过上下文窗口大小与可用性约束 L3 推理层。LongAgent 提供最量化证据：处理文档可达 128k token，远超单模型窗口，故采用分治策略将文档切成 chunk（1024/2048 token，显著小于 LLaMA2 的 4096 窗口）分配给成员智能体[2]。论文明确指出错误主要源于一种特定成员幻觉——「当分派给成员的文本块不含与 leader 查询相关的信息时，成员有时会捏造回答」，其缓解机制是成员间 chunk 共享使幻觉成员在收到含正确答案的 chunk 后修正[2]。这直接证明上下文可用性是协作正确性的决定变量。

系统综述进一步将「管理复杂且分层的上下文信息（整体任务上下文、单智能体上下文、智能体间共识知识）」列为多智能体相较单智能体的核心新增挑战，指出「每个智能体可能只掌握关键信息片段，其无缝整合对整体系统性能至关重要」[6]。MiTa 则指出 LLM 多智能体系统存在「记忆不一致导致信息丢失与上下文追踪差」的问题，用情景记忆整合来保留长时程上下文[12]。

核心机制三：L4 通信/协调层的跨层传播与放大

L4 通信/协调层是错误级联的枢纽。在异构具身协作中，1159 通过控制通信量（ACm）与成功率（Suc）证明「通信不足→信息不完整→决策错误」：压缩通信虽降低带宽但「解码压缩消息会丢失有效信息」；仅交换状态因「对其他智能体决策的错误推理与信息交换不完整」而成功率低[7]。

在错误级联方面，0210 用 Planner→Executor→Critic 流水线量化了错误如何「悄悄从一阶段传到下一阶段」，证明「结构化、可问责的交接」能防止失败级联，在 PythonIO 上把准确率提升超过 36 个百分点[5]。ColaCare 在医疗场景提供互补证据：缺少 RAG（即缺少外部上下文）时死亡率预测 AUPRC 从 54.05±4.88 降至 51.57±4.76，缺少 MDT 协作过程则降至 50.63±5.02[4]。

对抗性验证：层级边界与归类稳定性

对层级划分执行反例检查，发现两处边界模糊性：(1) L1 数据/上下文层与 L3 智能体推理层边界模糊——「成员幻觉」在 LongAgent 中被列为推理层症状，但其根因是上下文不可用，导致该问题在 L1/L3 间归类不稳定[2]。(2) L2 指令/歧义层与 L4 通信/协调层边界模糊——「协调策略歧义」既是单条指令的语义问题（L2），也表现为智能体间沟通不一致（L4），AgentCoord 的结构化表示同时作用于两层[1]。

分析局限性

(1) 证据解耦不足：多数协作正确性证据来自长文档 QA、代码生成、医疗预测等特定任务，对「歧义导致的错误」与「上下文不足导致的错误」缺乏解耦度量；LongAgent 将错误基本归于成员幻觉，可视为上下文缺失的下游表现，但二者边界未清晰分离[2]。

(2) 跨层传播链的证据强度不均：除 Heterogeneous Embodied[7] 与 Traceability[5] 有直接实验量化外，L2→L5、L3→L5 部分链条仅有 KG 结构化边或机制推断支撑，标注为 kg_edge / inferred_no_direct_support，尚缺直接因果实验。

(3) 正确性-开销权衡无统一准则：0210 报告可问责流水线成本增加 2–3 倍、延迟 8–10 倍[5]，而 1159 显示最小通信量（IntenComm.）反而正确性差、全量通信（CentralComm./BroadComm.）成本不划算[7]，说明存在未被刻画的中间最优点。

(4) 领域覆盖偏斜：6 篇冻结论文集中于多智能体 LLM 协作，对传统 MARL 通信约束（如带宽受限信道）覆盖较少，MADRL 侧证据多来自补强论文。

结论

RQ5.1 的答案为：歧义与上下文约束通过三条交织机制损害协作正确性。歧义在 L2 指令/歧义层产生，表现为协调策略的反复重述与执行偏离，是根因层风险源点；上下文窗口与可用性约束在 L1 数据/上下文层产生，迫使信息切分、压缩或不可见，触发成员幻觉并使错误沿 L3 推理层与 L4 通信/协调层向上级联至 L5 任务输出层。L4 通信/协调层既是第二个风险源点（高传播中心性），也是最有效的防御着力点——结构化交接、成员间上下文共享与可问责机制均在此层显著提升正确性。

实践含义：缓解歧义应优先在 L2 采用结构化策略表示与标准化中间输出[1][10]；缓解上下文约束应优先在 L1/L4 采用上下文共享与记忆整合机制[2][12]；而任何防御方案都需权衡正确性收益与成本/延迟代价[5][8]。未来工作应建立跨任务的歧义-上下文解耦度量，并刻画通信量/上下文规模的最优点。
