摘要

本报告针对 RQ2.3「角色定义（固定 vs 演化）如何影响协作效率与错误抑制，是否存在可复用的角色设计模式」，在知识图谱（186 篇论文、380 个方法、454 个问题、278 个指标、170 条局限、119 条假设、243 个数据集）上执行多维帕累托权衡分析。核心结论是：固定角色与演化角色并非「谁更优」的二元选择，而是同一条帕累托前沿上的两种价值权重——固定角色以「编排稳定性、可追踪性、错误可归因」换取「对任务漂移的适应力」；演化/动态角色以「自适应效率、异构任务泛化」换取「可解释性与收敛可预测性」。真正不可逃避的权衡约束是：角色自适应粒度上升必然带来协调/通信开销上升、可追踪性与可预测性下降 [1][2][3]。

证据主线一：固定角色的可复用「流水线 + 验证器」模式

固定角色在结构确定性任务中稳居帕累托前沿，并收敛出一类可复用设计模式。[1] 的 Planner→Executor→Critic 固定流水线在结构化交接（blame attribution）下，AgiEval 达 93.54%、PythonIO 达 99.21%、LogiQA 达 85.51%，相比无结构流水线在 PythonIO 上准确率提升超过 36 个百分点；Critic 修复率 5.20%、Executor 修复率 10.01% 显著压低错误级联。MetaGPT [4] 的 SOP 角色链（PM→Architect→Engineer→QA）在 HumanEval 达 85.9%、MBPP 达 87.7% Pass@1，每增一专用角色，人工修订成本从 10 降至 2.5。相同模式在多领域复用：RTL 生成中的 Review Agent（语法检查）+ Verification Agent（功能验证）双角色闭环 [5]、HPC 测试中的 Recipe Agent + Test Agent critique loop [6]，均验证「专职验证角色 = 错误抑制」这一可复用设计模式。Croto [14] 的专职聚合角色移除后质量从 3.083 跌至 2.341，进一步佐证角色分工的价值。

证据主线二：演化角色的自适应收益与代价

[7] AgentDropout 证明动态角色剪枝可同时降低 prompt token 21.6%、completion token 18.4% 并提升性能 1.14——罕见的「双赢」前沿点，但其作者明确标注框架「仍受限于预定义角色与提示」，跨域仍需人工重设。AgentNet [8] 让智能体自主演化专精，MATH 从 77.86 升至 85、BBH 从 76 升至 86、API-Bank 从 23 升至 32，但训练准确率随智能体数仅从 80.38 微升至 81.18，呈明显递减收益；作者还承认 3 agents 时同质配置反而最好，异质引入协调开销。Evolving Orchestration [9] 的 RL 编排器在提升解质量的同时降低 token 消耗，代价是「固定 agent/tool 集合、偶发误协调」。ReSo [15] 用 reward-driven 自组织彻底消除手工角色设计，代表演化路线的极端。

证据主线三：文献级矛盾与混合架构仲裁

固定 vs 演化的结论存在真实矛盾。[8] AgentNet 明确批判静态/SOP 角色造成「单点故障、可扩展性局限、无法适应实时波动」，并直接与 [10][16] 存在 contradicts 关系；而 [9] Evolving Orchestration 又反过来 contradicts [8]，主张中心化可学习编排器更优。关键仲裁证据来自 [10]：其在 3 与 6 机器人上比较中心化（CMAS）、去中心化（DMAS）与两种混合（HMAS-1/2），发现混合 HMAS-2（中心化规划+局部反馈）在全部四类任务上成功率最高（3/6 robots 均 100%）且扩展性最佳——既不同于 [8] 的「去中心化绝对更优」，也不完全等同于 [9] 的「中心化更优」，提示「中心-局部混合」才是鲁棒前沿点。

分析局限性

本分析的证据完整性标注为 partial，不确定性主要来自三方面：(1) 数据集偏差与不可比性——现有数字跨论文、跨数据集、跨 backbone，指标定义不一致（F1 正类定义、GSR 断言定义各异），不能直接合并比较；[8] 的异构优势主要来自 BBH/API-Bank，是否泛化到其他域未验证。(2) 规模证据缺口——多数研究仅在 3–9 个智能体小规模验证，[8] 明确仅测试至 6 agents，大规模（>10 agents）下是否仍占前沿未验证。(3) 纵向证据缺失——演化角色的长期行为漂移缺乏实测，[3][17] 提示需额外治理机制，但其数据部分为模拟而非实证。(4) 对抗验证结果：对所有声称位于前沿的方法执行 has_limitation 检查，均发现具体失效条件（如 [1] 的 construct validity 与成本局限、[7] 的预定义角色局限、[8] 的小团队协调开销局限），故不存在「万能方法」，本报告所有前沿结论均标注 confidence=medium。

结论

对 RQ2.3 的回答：角色定义（固定 vs 演化）对协作效率与错误抑制的影响是条件性的，二者坐落于同一帕累托前沿的不同位置，而非优劣排序。固定角色在结构确定性任务中通过「顺序流水线 + 专职验证角色」实现最高准确率与最强错误抑制（[1] PythonIO 提升 >36pt；[4] HumanEval 85.9%），代价是成本 2–3× 与延迟 8–10×；演化角色在异构、漂移场景中通过动态重分配获得自适应效率（[7] token 降 21.6%、性能 +1.14；[8] MATH +7.14pt），代价是可解释性下降与协调开销。二者的根本权衡约束为：角色自适应粒度 ↑ ⇒ 协调开销 ↑ 且可追踪性 ↓，此「不可能三角」在当前技术条件下不可同时最优。关于可复用角色设计模式，证据支持四类模式：顺序流水线+结构化交接、主管-专家层级+动态路由、专职验证/批判角色、动态剪枝/演化编排。证据最强的仲裁结论是：中心化规划 + 去中心化执行的混合架构（[10] HMAS-2）在成功率与扩展性上同时占优，提示工程实践应优先考虑混合而非极端选择。
