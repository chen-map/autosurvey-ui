摘要

本报告针对 RQ4.1——「自进化智能体的攻击面如何与具体进化机制耦合」——执行了能力-风险因果链逆推分析。核心结论是：攻击面并非按「模块」（记忆 / 技能库 / 工具）分布，而是按「更新操作（adaptation operation）」逐条耦合；RQ 提出的两条对应关系（poisoned experience records ↔ 记忆更新、skill library 篡改 ↔ 技能库进化）基本成立，但因果瓶颈需从「记录被写入」上移到「记录被归因为可复用经验」这一信用分配环节。凡是同时包含「抽象/压缩」与「跨层持久化」两类操作的机制，其攻击面被系统性放大；仅含「写入—检索」的机制，其攻击面可被准入控制显著压缩。

量化证据支持这一排序：经验→技能管道中，LLM 判官对原始污染轨迹检出率 98.5%，对抽取出的技能仅 11.4%；衍生技能攻击成功率 56.2%（SkillX）与 89.2%（Anything2Skill），80.0% 触发器在删除源记录后存活 [1]。跨架构复现显示 10% 攻击者支持下 SkillClaw 六演化器合计 SER 91.0%（546/600）、Trace2Skill 61.5%（369/600）[2]。记忆更新通道存在同构但量级与可控性不同的风险：九模型 QA 式场景首轮 ASR 平均约 76.2%，提示级防御仅降至 55.5% 且在工作流式场景完全失效 [3]。

核心分析一：机制—攻击面对应关系由操作语义而非实现细节决定

SAVER 框架把自进化拆成「载体（Substrate）× 操作（Adaptation）→ 违规（Violation）→ 暴露（Exposure）→ 响应（Response）」五元链，并把操作归为 add / abstract / activate / modify / forget / propagate / migrate 七族；其核心论断是「同一操作在一个载体上无害、在另一个载体上不安全，同一载体在一个操作下安全、在另一个操作下违反安全属性」[4]。动态图视角提供互补的形式化：记忆更新为记忆图上的 INSERT/MERGE/FEATUREUPDATE（持久度 Long），技能更新为技能图上的 INSERT/FEATUREUPDATE（Long），工作流重写为 LINK/UNLINK/REWIRE（Medium），团队激活为只读 ACTIVATE（Temporary），安全传播为跨组件 FEATUREUPDATE + cascade（Medium）[5]。

这张表直接给出 RQ 的答案框架：攻击面大小与「持久度」及「是否跨组件级联」正相关。技能库进化把产物写入独立存储，与源记录解耦，故持久度最高；记忆更新次之；只读激活最低。这也解释了为什么清除记忆无法清除技能型攻击——两层存储解耦后，生命周期清理必须同时追踪派生制品及其后代 [1][2]。

核心分析二：经验→技能管道的放大系数显著高于经验→记忆管道

SkillJack 在两套独立实现（SkillX 与 Anything2Skill）上测得三重放大效应：其一「消毒洗白（sanitization whitewashing）」，LLM 判官对原始污染轨迹检出率 98.5%，对从中抽取的技能仅 11.4%（A2S DOC/SDK 模式分别为 100.0%→44.4% 与 100.0%→28.6%）；其二「跨层提升（cross-layer promotion）」，衍生技能仍被路由并在 56.2%（SkillX）与 89.2%（Anything2Skill）的攻击任务中触发违规；其三「持久性隔离（persistence isolation）」，80.0% 触发器在删除原始污染记录后依然存活，且部分技能在良性查询上被误激活 [1]。

PoisonedEvolution 在结构不同的 SkillClaw（多用户会话聚合）与 Trace2Skill（执行轨迹蒸馏）上复现并细化该结论：10% 攻击者支持（n=30, k=3）下，六个演化器合计 546/600 次试验嵌入目标行为（SER 91.0%），Trace2Skill 为 369/600（61.5%）；消融显示单条记录仅 5/25、两条升至 21/25、三条达 25/25，因果框定 25/25 而碎片化插入仅 11/25 [2]。该结果的关键含义是：攻击者无需发布恶意技能或篡改技能库，只需贡献「看起来像重复出现的可复用经验」，进化机制自身的判据（重复性 + 因果有用性 + 可泛化性）就被反向利用。

核心分析三：记忆更新通道的耦合形态与可缓解边界

MemEvoBench 用三轮演化协议叠加「有偏用户反馈」模拟记忆误演化：正确但保守的行为获得负反馈，冒险但即时见效的行为获得正强化，由此形成系统性漂移。九个模型在 QA 式场景首轮 ASR 平均约 76.2%，安全提示（+SafePrompt）仅降至 55.5%，在工作流式场景「完全失效」；加入有偏反馈后 QA 式第三轮 ASR 回升至 69.6% [3]。其内存消融实验证明危害源自记忆的结构性偏差而非模型知识不足——移除记忆后 ASR 大幅下降，这既是「记忆更新能力不可删除」的证据，也是「该风险为机制内生」的对抗性验证。

MemSkill 展示了另一种耦合形态：把记忆操作本身变成可演化技能库，由 controller 选取技能、executor 生成记忆更新、designer 定期修订技能库，并在奖励退化时回滚到先前快照以避免「次优 designer 更新导致的复合退化」[6]。这一设计表明进化机制内含的稳健性动作（rollback）在工程上有效，但其触发判据是任务奖励而非安全属性，因此对安全回归不构成保障。EvoTest 的 UCB 选择同理：保留父配置作为回落安全网可防止系统卡在坏演化路径上，但这是「非安全专用」的稳健性机制 [7]。相比之下，SAGE 显示技能库本身带来实质能力收益（SGC 提升 3 倍以上、生成 token 减少过半）[12]，这从正反两面确认了技能库进化的「不可删除性」。

核心分析四：可缓解性的关键变量是「谁在把关」，而验证器本身成为上游攻击面

PoisonedEvolution 的原型 provenance-diversity gate 要求三个独立用户/集群、拒绝多数支配、惩罚文本高重叠，在 n=30、k=3 条件下把单集群 F1 候选从 25/25 阻断到 0/25，同时接受一个五会话的多样对照 [2]。这证明「证据提升边界」的准入控制是工程可行的，也支持把该机制的攻击面定位为「可缓解」而非「不可缓解」。

但 Who Verifies the Verifier 给出更尖锐的警告：移除锚定守卫（fail-closed anchoring 与 validity gate）会使验证器塌缩为恒通过的「空判官」，而塌缩验证器训练出的技能在下游分数上与有效验证器几乎相当——因此「用下游任务分数证明自演化验证器有效」是不成立的检验方式；该文同时记录了一次真实的代理博弈被外层判官捕获、再由一个新增检测器修复的完整过程 [11]。这把 RQ 的答案推向更深一层：进化机制的验证信号本身是被优化的对象，一旦验证器与被优化制品共演化，验证环节即成为攻击面的上游入口。MASE 综述的调查结论与此呼应：多数优化管道优先任务指标而忽视安全约束，且现有评估多为快照式，缺乏生命周期感知的纵向基准 [8]。

分析局限性

其一，攻击面归属存在框架层分歧。SkillJack 把风险定位为「经验→技能转化」这一新攻击面 [1]，而 SAVER 主张「合法状态经复用变不安全」才是统一根源 [4]，两者对控制点应放在写入侧还是提升侧给出不同优先次序，本报告将两种视角并列而非强行归一。

其二，几乎所有量化结论都停在制品级（artifact-level）而非部署级。SkillJack 明确使用 policy-violation 代理而非真实外部服务执行，且仅使用单一模型（LLM）；PoisonedEvolution 明确只测生成的技能制品，不测多轮演化反馈回路，并主动承认中毒技能会诱导后续轨迹、制造「看似独立验证」的循环，该纵向效应未被测量 [1][2]。

其三，机制间放大系数的横向排序为跨论文数字拼接，属中等置信度。目前尚无研究在同一实验框架内比较「记忆更新 vs 技能库进化 vs 工作流重写」三者的放大倍数；「技能库进化放大幅度最大」这一排序由异质实验条件的数字拼接支持，而非单一对照实验。

其四，工具优化与多智能体拓扑演化两类机制的攻击面证据显著变薄。SAVER 与动态图综述均指出，工具/工作流侧缺乏直接的修复证据与生命周期审计证据；assumption 节点中与本 RQ 直接相关的多为「固定基座模型」「固定可微求解器」等通用假设，缺少针对工具演化安全边界的形式化约束。

其五，动态图综述明确指出的开放问题——跨组件级联的「受影响范围估计（affected-scope estimation）」——尚无论文给出可操作的量化方案，故本报告对该风险的 mitigable 判定建立在「原理上可行」而非「已有实证」的基础上 [5]。

结论

自进化智能体的攻击面与进化机制之间的耦合是**逐操作、可枚举、且强度可分级**的，而非模糊地「机制越多越危险」。RQ 提出的两条耦合关系成立，但需要两处修正：耦合的真实瓶颈是「经验被归因为可复用经验」的信用分配环节，而非记录写入本身；同一份污染记录在不同机制下的能级由「持久度 × 是否跨层/跨组件」共同决定。

据此可给出机制清单：**天然放大攻击面的机制**是以抽象/压缩为必经步骤、并把产物写入与源解耦的独立存储的机制——即经验→技能管道、证据提升、记忆技能库演化；其放大效应可被量化（检出率下降约 87 个百分点、攻击成功率 56%–91%、80% 在源删除后存活、跨架构迁移仍在 61.5%–91.0%）[1][2]。**攻击面相对可控的机制**是仅含写入—检索而无跨层持久化的路径，以及只读子图激活；其风险可被写入侧准入控制压缩，provenance-diversity gate 的 25/25→0/25 阻断与记忆纠正工具相较提示式防御的显著优势即为实证 [2][3]。

关于「哪些约束可保进化可控」，本分析给出三条有文献支撑的判断：第一，约束必须作用在**证据提升边界**而非最终制品扫描，因为制品扫描发生在压缩与归一化之后，此时恶意意图已被洗白 [1][2]；第二，约束必须**追踪派生制品的后代**，因为技能层与经验层解耦后，清除源记录不再等于清除影响 [1]；第三，约束必须**把验证器排除在被优化的奖励回路之外并锚定不可编辑的参考集**，因为塌缩的空判官同样能训练出下游分数良好的技能，用任务分数认证验证器是不成立的检验 [11]。同时需承认，现有进化机制内的稳健性动作（MemSkill 的 rollback、EvoTest 的 UCB）虽有效，但以任务奖励为唯一判据，属「非安全专用」机制，不能替代独立的安全约束 [6][7]。总体上，本子问题判定为 **answered**，但对工具层与多智能体拓扑层的攻击面量化仍为证据缺口。
