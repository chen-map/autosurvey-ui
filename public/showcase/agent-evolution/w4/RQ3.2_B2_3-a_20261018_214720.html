摘要

本报告针对 RQ3.2 展开元评估层面的系统分析：纵向评估协议（Longitudinal evaluation protocol / EvoTest）与跨会话基准的现状如何，以及为何单会话基准（ALFWorld、WebShop、AppWorld）在结构上无法支撑进化轨迹评估。

核心结论是：KG 中并非不存在纵向协议，而是存在至少四条彼此不可比的纵向评估谱系——EvoTest + J-TTL（K=50 连续 episode + 归一化 AUC）[1]、SEA-Eval（92 条有序任务序列 + token 消耗收敛趋势）[2]、FinEvo-Bench（120 开放式金融任务 / 20 业务场景 / 每场景 6 案 + 配对非进化对照组 score gain）[3]、EvoPathBench（1,800 条任务流 + 只读检查点 + 三维 CEG）[4]，另有 AgentStream 形式化 Isolated / Sequential / Interleaved 三种流式场景 [5]。它们的度量对象（AUC vs token 收敛 vs 配对增益 vs CEG）、状态持久化假设与时间尺度全部不同，且没有任何一条覆盖证据矩阵 4/6 篇论文实际使用的 AppWorld / ALFWorld / WebShop。

单会话基准的失效不是精度问题而是信息结构问题：环境在任务边界不携带状态、奖励为一次性判定，'能力变化'这一被测量在数据生成阶段就被抹除。元评估统计进一步暴露出'有缺陷的共识标准'——Success Rate 拥有约 49 条 measured_by 边（覆盖率最广），却恰好在语义上无法表达变化；而 AUC、Retention、Adaptivity 等纵向维度度量各仅 1–3 条边且多数只被综述收录。

评估维度本体：纵向度量 vs 端点度量的结构性失衡

以 KG metric 节点为基础构建评估维度本体后，最显著的发现是纵向维度与端点维度的极端失衡。端点类指标（Success Rate、Task Goal Completion、Scenario Goal Completion、Average Reward、Score）构成了压倒性的主体；而能够表达'变化量'的纵向指标总数极少，且大部分只有一个来源。

这一失衡在认识论上意味着：社区用最高共识度测量了最不适配 RQ 所问'capability change'的量。Success Rate 是一个无时间导数的单点比率，它无法区分'真正学会'与'一次侥幸成功'，也无法表达'同一能力在后续更新中是否退化'。

纵向/跨会话评估协议谱系：四条互不可比的路线

KG 中的纵向评估并非空白，而是呈现'多路线并存但彼此割裂'的格局。四条主要谱系在协议设计上存在根本性差异：时间尺度从 5 步序列到 120 任务、50 episode 不等；状态假设从'每 episode 重置到同一初始状态'到'跨场景持续累积'；核心信号从归一化 AUC 到 token 收敛趋势再到配对增益。

尤其值得注意的方法论分歧在于对'非平稳性'的处理：EvoTest 明确将环境重置到完全相同的初始状态，以确保性能提升'完全'归因于 agent 内部学习 [1]；而 FinEvo-Bench、SEA-Eval、EvoPathBench 则反其道而行，通过任务顺序、干扰任务、规则反转主动引入非平稳性，理由是真实部署中经验的价值恰在分布漂移下才被检验 [2][3][4]。EvoPathBench 的实测结果倾向支持后者：熟悉条件下取得的增益'在分布漂移下常常减弱'，而'可靠的规则适应仍未确立' [4]。

为何单会话基准无法支撑进化轨迹评估：机制诊断

这是本 RQ 的核心追问，KG 提供了罕见而直接的原文证据。SEA-Eval 在 Limitations of Existing Evaluation Frameworks 一节中直接判定：WebArena、OSWorld、SWE-bench、τ-bench、AgentBench '均以单一任务 episode 作为基本评估单元，只能测量即时执行能力，对跨任务的演化动力学是盲的' [2]；更关键的是它指出'即使 agent 在重复执行结构相似任务后 token 消耗始终不收敛——这恰是进化能力缺失的真实信号——在现有框架下完全不可见' [2]。FinEvo-Bench 的表述同样精确：常规基准'独立评估任务、不在 episode 之间保留先前任务的经验' [3]。EvoPathBench 的表述最具概括力：标准静态基准'在每个任务前重置 agent 状态'，因此'只捕捉当前性能的快照，而不追踪随时间的演化进程' [4]。综述层面亦给出同向判断：自进化智能体的评估'要求从传统 single-shot 打分，根本性转向纵向的、成本感知的轨迹视角' [6]。

失效的机理可归纳为三层：(1) 状态层——环境与 agent 状态在任务边界被重置，跨任务的因果链断裂；(2) 奖励层——ALFWorld 提供二值任务完成奖励、WebShop 提供 0–1 密集奖励 [12]，均为一次性终局判定，无法承载'进化效率'这类过程量；(3) 统计层——即使保留任务序列，若只用聚合分数报告，也会'遮蔽单个能力的变化'，只能说明全局是否变好，无法揭示某能力在后续 artifact 更新下如何演变 [4]。

值得注意的是，KG 中 ALFWorld 拥有 44 条关系边、被 20 篇以上自进化论文作为主评测集使用，WebShop 与 AppWorld 亦各有 30 篇量级的使用者。这使单会话范式不仅是历史遗留，而是当前自进化研究的事实性评测基础设施——盲区的规模因此被指数级放大。

评估盲区的类型学与支撑强度

依据'存在某类 problem 节点但无对应 metric 节点度量其解决质量'的定义，并遵循'至少 3 篇论文支撑方可称为系统性忽视'的约束，识别出四类盲区。其中绝对盲区最为关键：'能力随时间的变化量'这一被测量，在单会话基准的绝大多数使用场景中没有任何度量节点承接。

RSEA 的选择门消融提供了该盲区代价的量化证据：无 held-out 门控的版本在 ALFWorld 上样本内达到 100%，测试仅 66.7%，形成 33 个百分点的训练-测试落差 [17]。换言之，缺失纵向/门控协议的直接后果是'进化过程可以被过拟合伪造'——而这恰恰无法被单会话端点分数识别。

有缺陷的共识指标审查

对抗性审查要求对覆盖率高的共识指标质疑其合法性，而非无条件接受。审查结果指向一个尖锐结论：社区覆盖率最高的指标，恰是语义上最不适配本 RQ 被测量的那一个。

Success Rate 拥有约 49 条 measured_by 边，是全部指标中覆盖率最高的（以 274 篇 paper 为分母粗估覆盖率约 18%，但在'评估类论文'子集中超过 70%）。然而它的定义是'成功完成任务的百分比'——一个无时间导数的单点比率。SEA-Eval 明确将其重新定位为'部署可行性的最低可靠性保证'，而非进化能力信号，并把 token 消耗收敛趋势提升为第一序检测信号 [2]。这是一个明确的元评估判断：高频共识不等于高适配性。

AUC 在 KG 中存在同名不同义的冲突：[1][8] 指学习曲线下面积，[9] 指 ROC-AUC。按分析约束，此类定义不一致必须标注而不得合并统计——这也侧面说明即使纵向指标内部，术语规范尚未建立。

评估不可比性审计

Jaccard 相似度审计显示，纵向协议的评估基本不可比。按任务分组估算的共同指标比例：AppWorld 组约 0.5（TGC/SGC 共享度较高），ALFWorld 组与 WebShop 组各约 0.33（Success Rate 为唯一共享项，但其分母定义在 per-task / per-scenario / per-family 之间不一致），而 Jericho/J-TTL、金融（FinEvo）、混合流式（EvoPath）三组的纵向指标集合几乎完全不重叠，Jaccard 接近 0。

更深一层的问题是：即使同一指标名称，其数值也不可直接比较。ALFWorld 的二值成功奖励与 WebShop 的 0–1 密集奖励语义不同 [12]；TGC 的 @4/@8 是同一时刻的多次 rollout 平均，而非跨时间的序列观测 [13]；FinEvo 的 score gain 是配对差值，与 EvoPathBench 的 CEG 虽同为增益量但基线构造不同 [3][4]。因此本报告明确声明：不同来源的纵向数字不得横向直接比较。

纵向协议自身的效度风险

承认单会话基准的缺陷，并不意味着现有纵向协议已经成熟。KG 数据同时揭示了它们各自的效度风险。SEA-Eval 仅含 32 个原子任务（作者自陈'可能无法充分代表真实任务的复杂性与多样性'），且 Hermes、LLM Code、Codex 在测试时因时间与 token 成本受限而施加 15 分钟超时，可能影响结果 [2]。RSEA 的迁移基准'仅使用单一 seed 的 shuffle 划分且评估规模适中，限制了统计功效'，其 GAIA 使用实时 web 检索带来的 run-to-run 噪声甚至使 ≤1 任务的差距在多次运行中改变符号 [17]。EvoPathBench 则发现更根本的问题：'当前接受规则在区分可迁移改进与过拟合、必要规则修正与有害遗忘方面能力有限'，候选评估（candidate selection）被识别为主要瓶颈 [4]。

这些风险共同指向一个判断：纵向评估的问题已经从'有没有协议'转移到'协议是否可信'。而这恰恰是本 RQ 元评估视角应有的落点。

分析局限性

本报告存在三处需要明确披露的证据限制。第一，最关键的缺口是缺少直接对照实验：没有任何一条纵向协议（EvoTest/J-TTL、SEA-Eval、FinEvo-Bench、EvoPathBench、AgentStream）被用于 ALFWorld / WebShop / AppWorld 这三个证据矩阵论文实际共用的基准。因此本 RQ 追问的'为何单会话基准无法支撑进化轨迹评估'虽有多篇论文的结构性论证与综述背书（支撑论文数达 5 篇，超过 3 篇门槛），但严格意义上属结构性推断而非对照实证——缺少'在同一基准上纵向评测 vs 单会话评测得出分歧结论'的 A/B 证据。

第二，证据来源的冻结范围问题：六篇证据矩阵论文本身全部落在单会话范式内，它们无法为纵向协议的存在性提供正面证据；而支撑本报告纵向协议结论的 SEA-Eval [2]、FinEvo-Bench [3]、EvoPathBench [4]、AgentStream [5] 均为 KG 内非冻结论文，其量化数字取自 abstract / intro 级原文片段，未做表格级逐项复核。

第三，KG 结构统计的固有偏差：metric 节点的 measured_by 边数反映的是 KG 抽取覆盖度，而非文献实际使用频次。纵向指标的低使用数（AUC 3 条、CEG 1 条）可能部分源于抽取遗漏，尤其当原始论文仅在附录或图中呈现学习曲线时。此外，AssumptionConstraint 类型中针对'episodic 评估假设'的定向查询返回空结果，说明 KG 尚未对'单会话评估'建模为显式假设节点——这本身是一个元层面的建模盲区。

结论

对 RQ3.2 的回答可分为三点。

第一，纵向评估协议与跨会话基准已存在但高度碎片化。KG 中可辨识至少四条独立谱系：EvoTest/J-TTL（K=50 episode + 归一化 AUC，平均 0.47/0.50，显著优于 EvoPrompt 0.34/0.36 与在线 GRPO 0.30）[1]、SEA-Eval（92 条有序序列 + token 收敛趋势作为真/伪进化判据）[2]、FinEvo-Bench（120 任务 / 20 场景 + 配对非进化对照，增益 +9.33 至 +19.37 分，后段 rank 比前段多增 6.10–8.70 分）[3]、EvoPathBench（1,800 条流 + 只读检查点，拆解 learning generalization / retention / rule adaptation）[4]，以及 AgentStream 的三种流式场景形式化 [5]。它们的度量对象、状态假设与时间尺度互不兼容，Jaccard 在多数任务组接近 0，构成评估不可比性。

第二，单会话基准无法支撑进化轨迹评估是结构性的，而非可通过调参或扩数据弥补的。三项机制同时失效：状态层（任务边界重置状态，跨任务因果链断裂）、奖励层（ALFWorld 二值 / WebShop 密集终局奖励，无法承载过程量）[12]、统计层（聚合分数遮蔽个体能力变化）[4]。SEA-Eval 对此的判词最为直接：主流基准'以单一任务 episode 为基本评估单元，对跨任务演化动力学是盲的'，且 token 不收敛这一'进化缺失的真实信号'在现有框架下'完全不可见' [2]。ALFWorld 44 条关系边、20+ 篇自进化论文的渗透度表明，这一盲区的规模远超个别基准的局限。

第三，元评估层面的核心问题是'有缺陷的共识标准'：Success Rate 以约 49 条 measured_by 边成为覆盖率最高的指标，却恰在语义上无法表达能力变化；而真正能表达变化的纵向度量（AUC、CEG、Retention、Adaptivity）各仅 1–3 条边，多数只被综述收录而非原始实验采用 [6]。这意味着社区不仅在度量上滞后，更在'什么值得被测量'的共识层面停留在单会话时代。

最后，纵向协议自身尚未成熟：SEA-Eval 仅 32 任务且受限超时 [2]，RSEA 单一 seed 且统计功效不足 [17]，EvoPathBench 的规则适应效应经校正后无一显著 [4]。因此本 RQ 的完整答案应是：单会话基准在结构上无法支撑进化轨迹评估（证据充分），纵向协议虽已出现但彼此不可比且效度未稳（证据充分），而'纵向 vs 单会话在同一基准上的直接对照'仍是空白（证据缺口，属本子问题最大的不确定性）。
