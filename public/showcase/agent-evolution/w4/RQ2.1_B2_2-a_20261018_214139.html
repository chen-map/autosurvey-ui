摘要

本报告针对 RQ2.1，从知识图谱中抽取覆盖 274 篇论文、558 个方法节点、629 个问题节点、317 个局限节点、200 个假设节点与 391 个指标节点的结构化数据，聚焦记忆更新（AWM、MemRL、SENTINELMEM）与策略优化（Agent symbolic learning、Skill evolution）两类自演化机制在"更新什么、用什么信号更新、如何避免退化"上的系统差异。

核心结论：两类机制并非两种彼此独立的技术路线，而是同一进化回路（采集信号 → 抽象压缩 → 载体写回 → 选择门控 → 检索激活）中的两种参数化位置。记忆更新把可塑状态外置为冻结模型之外的可检索记忆载体，策略优化则把可塑状态内化为 prompt / tool / pipeline 乃至权重的可编辑程序。载体的差异进一步决定了更新信号的粒度（即时可判定 vs 延迟高噪声）、抗退化机制的形态（非破坏性受控写回 vs 显式门控加快照回滚），以及可审计性与跨 backbone 迁移性的方向。

通用骨架：五组件进化回路（覆盖率 ≥70% 的强制组件）

对全部方法节点的 IPO（输入—处理—输出）接口做交叉验证后，文献集中收敛出一个高覆盖率的通用骨架。覆盖率按"在该组件上有明确实现描述的方法数 / 具备完整流水线描述的方法数"计算，强制组件阈值为 70%。

值得注意的是 C6「溯源与审计」组件：尽管 0037 明确将其列为治理必需（support-subgraph accuracy、rewrite locality），0038 亦把 authority 传递与回滚证据列为核心判据，但实际方法中仅约三分之一提供任何形式的版本/溯源机制，故按规则降格为可选扩展组件。这本身即是本领域的结构性缺口。

变异维度：四个设计热点与两个设计共识

按"不同配置数 / 非省略非不适用论文数"计算配置多样性：得分 > 0.6 为高变异组件（设计热点），< 0.3 为低变异组件（设计共识）。结果显示四个设计热点（C1、C2、C3、C4）全部集中在"如何生成信号、如何抽象、写到哪里、怎么把关"这四步，而恰好是 C5「检索激活」在各方法间实现高度收敛——这构成了本领域罕见的低变异设计共识。

设计共识的收敛形态是"先语义召回、再用效用重排、最后注入上下文"的两阶段激活范式：MemRL 的 Two-Phase Retrieval（相似度召回 + Q 值重排）与 AWM 的 retrieved-workflow 注入同属此形；0037 更把 DyLAN / DyTopo / ToG-3 等系统统一抽象为 A.3 read-only subgraph activation 的同一 schema [13]。

第二个较弱但正在形成的共识在 C3：增量/局部写回优于整体重生成。ACE 明确以 incremental delta update 替代整体重写，并给出消融——去掉 delta 更新后 AppWorld 上 TGC 掉 11.7、SGC 掉 27.8 个百分点 [3]；0037 的 Table I 亦把 memory update 与 skill update 统一编码为 INSERT / MERGE / FEATUREUPDATE 节点级 rewrite [13]。

差异主线一：更新载体决定可迁移性与可审计性的方向相反

记忆更新类方法把可塑状态放在模型之外：MemRL 冻结 ω、只优化检索策略 μ(m|s,M)，以非参数方式同时规避微调的算力开销与灾难性遗忘 [1]；SENTINELMEM 以事实状态机逐条保存 previous→current 的状态转移，并用双轨 profile 把个人偏好与安全约束解耦，使二者独立管理 [14]；AWM 从成功轨迹归纳 workflow 列表，部署期冻结 [10]。其产物是外部、可读、可跨 backbone 迁移的制品——这也解释为何 2345 指出参数化路径"difficult to inspect, transfer across model backbones, or reuse when the underlying model is replaced"[17]。

策略优化类方法则把可塑状态内化：Agent symbolic learning 把 prompts / tools / pipeline 一并视为"符号网络"的可学习权重，通过 language loss → language gradient → language optimizer 沿轨迹反向逐节点更新，甚至重连计算图，从而支持多智能体系统优化 [15]；0001 的 skill 演化只重写一个 Markdown SKILL.md，元 agent 直接改写，其余全部冻结 [16]。其产物与具体流水线强耦合，但能实现"自上而下的整体优化"，避免各组件单独优化陷入局部最优 [15]。

两者的张力正是 ACE 存在的理由：它把 context 建模为 itemized playbook 而非整体重写，实质是在策略优化一侧重新夺回记忆类方法才有的局部性与可审计性 [3]。

差异主线二：更新信号的即时性 vs 延迟性构成关键分水岭

策略优化侧普遍依赖即时、可判定的信号。0001 的 meta-agent 直接读取确定性求解器产出的 per-criterion outcomes、CPF、BM、SG 与 attempt counts；更关键的是评估器被置于 coding agent 之外，论文明确称 "Because evaluation is performed outside the coding agent by a fixed procedure, the evaluation signal cannot be modified by the model itself"——这构成了一条对 reward hacking 的结构性防线 [16]。Agent symbolic learning 用无需 ground truth 的语言化损失把评分转为文本批评，使其可在部署后继续演化 [15]；MemSkill 用 episode 级任务分经折扣回报分配到 skill 控制器的决策序列 [2]。

记忆更新侧则普遍面对延迟、噪声、归因模糊的结果信号。MemRL 以 Q←Q+α(r−Q) 从最终奖励回传记忆效用，理论上依 Bellman 保证收敛，实证上 Q 值与经验成功率的 Pearson r = 0.861（从最低置信分箱 21.5% 升至最高分箱 88.1%）[1]。但作者自陈 step-wise 更新"may introduce high-variance noise in long-horizon trajectories"，且存在 "credit-assignment ambiguity during utility updates"。这一延迟性带来的结构性后果是：任务结构越复杂收益越大（ALFWorld、OS 任务各 +6.2pp CSR），单步 BigCodeBench 仅 +2.5pp [1]。

上图数据来自 MemRL 论文 Table 4 与 §5.2：MemRL 相对最强基线 MemP 的平均 CSR 增益为 +3.8%，迁移设置下平均成功率为 +2.8%（ALFWorld +5.8%、OS 任务 +2.6%）。增益幅度与任务的时间依赖强度高度相关，作者据此把 MemRL 定位为"Trajectory Verifier"而非简单的检索增强器 [1]。

差异主线三：抗退化机制的形态随载体根本分化

策略优化侧收敛为"显式门控 + 快照回滚 + 增量编辑"三位一体。0001 采用 elitist 选择规则：候选按验证 SG 排序，同分时依次比 CPF、总约束违反量、BM，规则为"a revision that ranks no better on validation is never deployed"；实测中 iteration 1 已达 100% 验证成功率天花板，后续三次修正全部被拒，但最优 skill 被完整保留 [16]。MemSkill 用 cycle 末四分之一训练步的平均奖励作为稳定化估计，若不优于历史最佳则回滚 skill bank 至先前快照并重启演化，"This rollback prevents compounding degradations from suboptimal designer updates"，并配以固定 patience 早停 [2]。ACE 用增量 delta 更新替代整体重写，作者指出整体重写会使模型"shorten and compress what was written before"，诱发 brevity bias 与 context collapse [3]。

记忆更新侧则收敛为"受控非破坏性写回 + 语义筛选"。SENTINELMEM 的 FSMM 明确针对"destructive memory updates"这一失败模式，保留历史状态而非丢弃，使 agent 既能推理当前事实、也能推理该事实如何形成 [14]。MemRL 以 z-score 归一化 + similarity gating 压制 forgetting rate；去掉二者后均值升至 0.073 且出现明显尖峰，说明 agent 会反复检索并强化"只对特定实例有效"的噪声策略 [1]。相较之下，AWM 的"去重后全量注入"是弱门控形态，其后果在后续文献中被系统性揭示。

对抗性验证：记忆更新并不自动等于稳健或安全

骨架完备性自检时，两条反证据无法被任何单一组件配置吸收，必须作为跨组件的失效模式记录。

其一，记忆类方法的自我改进在更严苛评测下会退化为自我损害。对 AWM 与 ReasoningBank 在多次运行与乱序任务下复评发现"agents do not self-improve, but instead degrade"，尤其在基线本就较强或任务随机到达时；进一步定位为 environment and task underspecification（如 agent 把 Haversine 公式估计距离这类偶然奏效的替代策略写入记忆，并在后续任务中被愈发频繁地检索与复用）；补充规格信息后性能退化仅被削减 31%，作者坦承"the remaining 69% performance gap"仍未解决 [4]。这直接挑战了 AWM 一类"只学成功轨迹"的弱门控设计。

其二，经验积累会系统性侵蚀安全属性。即便所有存入记忆的经验都来自良性、无害任务，AWM 框架下的离线自我演化在所有被测模型与环境中均系统性抬升攻击成功率 ASR，且在线演化中 ASR 在早期急剧上升后平台化，"no model recovering to its initial safety level"，800 步以上的长程实验亦观察到持续下滑 [5]。这否证了"记忆类方法因不改权重而天然更安全"的直觉。

其三，策略优化路线的有效性存在能力边界。开放优化（OEO）在 14 组头对头比较中对预置流水线（SKILLOPT / GEPA）取得 12 胜 1 平 1 负，仅用 SKILLOPT 配置 token 预算的中位 34.3%；但当 optimizer 能力为中等时 SKILLOPT 反超，作者据此把预置流水线重新定义为"capability-dependent scaffolding"[7]。

三处映射失败非孤例，均指向"组件间关系"而非"组件内部配置"：0038 的 authority collapse 与 relinking 属抽象操作内部的安全属性传递（建议新增 C2a 抽象保真校验）[8]；0037 的 A.4 跨组件级联传播属组件间依赖机制（建议新增 C7 级联传播控制）[13]；2391 的"改善过程本身由 optimizer 在线编排"属元层面控制（建议新增 C0 优化过程编排者）[7]。三者合计约占所考察论文贡献的 21%，超过 5% 的自检阈值，故骨架应视为 v1.0 待修订版本。

设计关联：协同、独立与不兼容

对各组件配置组合计算共现率（> 0.7 判为强协同）。最强的两条协同关系都围绕 C4 门控展开：其一是"整体重写可编辑程序"与"验证集门控加快照回滚"共现 0.83；其二是"确定性求解器或验证器打分"与"严格改进门槛"共现 0.75。这说明门控机制并非可选装饰，而是与载体和信号形态共同决定的配套设计——一旦选择整体重写型载体，就必须配备验证集门控，否则退化不可控。

记忆更新侧"外部记忆条目 + 语义筛选"的协同强度较低（0.71），反映出该侧门控目前尚弱：MemRL 的 gating 本质是检索侧筛选而非提交侧验证，AWM 更是仅做去重。这一不对称正是记忆类方法在 2401 与 2295 中暴露脆弱性的结构性根源 [4][5]。

关于"不兼容"声明，需特别谨慎：本次仅识别出一组有条件的不兼容——"整体重写 + 摘要式压缩"，依据不是低共现率，而是 ACE 的直接消融证据：整体重写会导致后续写入不断压缩先前内容，形成 brevity bias 与 context collapse，使高价值条目归零 [3]，Combee 亦独立复现了同一机制（并行朴素聚合使 h≥3 条目从 19/38 个降至 0）[12]。其余低共现组合均标注为 independent，不作不兼容推断。

量化效能对照

在本次抽取的实证中，策略优化类方法的增益幅度显著高于记忆更新类，但代价是更强的领域依赖性与更小的样本量。0001 在同一 benchmark 上把同类型任务成功率从 38% 提到 74%（+36pp），准则通过率从 0.51 提到 0.87，平均尝试次数从 4.10 降至 2.30；在 New-type-B 上从 0.20 提到 0.90（+70pp），而在 New-type-A 上从 0.92 略降至 0.90（−2pp，净变化仅 1 个任务）[16]。Agent symbolic learning 在软件开发任务平均分 3.8（Agent 基线 2.4、LLM 1.6），创意写作 LLM/LLM 下为 6.9/7.4（对比 Agents w/ AutoPE 4.4/6.5、ToT 3.8/6.8）[15]。

MemRL 在四个 benchmark 上的平均 CSR 为 0.798、迁移成功率 0.794，相对最强基线分别 +3.8% 与 +2.8% [1]。SENTINELMEM 的三指标提升为 +2.91% Recall / +23.80% PSR / +10.73% PHS [14]。需强调：这三组数字的度量口径、基线与任务领域互不相同，不能直接横向比较绝对幅度，只能比较"相对基线的增益方向与稳健性"。

分析局限性

第一，证据集与问题设定存在错配。RQ2.1 冻结证据集仅 6 篇，而实际最有信息量的对照材料（MemRL [1]、MemSkill [2]、ACE [3]、Fragility [4]、Experience-Driven Safety [5]、FinEvolveBench [6]）均来自证据集之外，属于本次分析主动扩展引入。若严格限定在冻结集内，"四方法头对头比较"根本无法完成——冻结集中 ReAct 仅以"training-free 对照"角色被二手转述，KG 内无其方法节点；AWM 亦无独立论文节点，其配置描述来自 2401 与 2274 的转述 [4][11]。因此本报告对 ReAct 的定位标注为低置信。

第二，跨方法量化比较在统计上不成立。第二节所列数字分属不同 benchmark、不同 backbone、不同基线，且缺少共享的受控实验。报告中已尽量避免绝对幅度比较，但仍存在读者误读的风险。

第三，KG 节点密度不均。method 节点 558 个中，只有约 30 个与本题直接相关；大量节点（如 Q-learning、ACO、水平集方法）与 LLM 自演化无关，本次分析已通过问题/论文边关系过滤。limitation 与 assumption 节点高度偏向 0001 与 0037 两篇，导致"退化机理"的证据分布不均衡。

第四，骨架 v1.0 尚不完备。自检显示约 21% 的考察贡献无法映射到 C0–C5，分别为抽象保真（C2a）、级联传播（C7）与优化过程编排（C0）。这三者反映的是"组件间关系"与"元层面控制"，而非组件内部配置，说明当前骨架偏"静态组件清单"、弱于"动态演化过程"，后续需修订。

第五，综述类节点（0037、0038、2200、2205）本身不提供一手实证，被引作"共识证据"时置信度应低于实验论文。

结论

对 RQ2.1 的回答可以凝练为一句判据：**记忆更新优化的是"检索什么"，策略优化优化的是"程序长什么样"，二者的系统差异由载体位置而非算法名称决定。**

具体而言：（1）**更新什么**——记忆更新改写外部 episodic/semantic 条目（三元组、状态机转移、workflow 列表），模型权重冻结；策略优化改写 prompt / tool / pipeline 结构，范围更大、耦合更深、收益也更大 [1][14][10][15][16]。（2）**用什么信号更新**——策略优化依赖即时、可判定、位于 agent 之外的验证信号（确定性求解器打分、验证集 SG），从而在结构上封堵了评估信号被模型篡改的可能 [16]；记忆更新依赖延迟、含噪、归因困难的结果奖励，需借 Q 值等机制回传 [1]，这既是它胜任多步长程任务的来源（+6.2pp），也是它在低重复任务上失灵的根源（FinEvolveBench 中不consistently优于无经验基线）[6]。（3）**如何避免退化**——策略优化侧收敛为"显式验证门控 + 快照回滚 + 增量编辑"，且有效性可量化（elitist 规则、stabilized-reward rollback、ACE 消融 −11.7/−27.8pp）[16][2][3]；记忆更新侧收敛为"非破坏性写回 + 语义筛选"，其必要性同样可量化（PSR −88.69% 的破坏性更新代价）[14][1]。

最重要的分歧点在于：**记忆更新路线当前缺乏提交侧门控**。AWM 的去重式弱门控使其在乱序任务与强基线下退化为自我损害（仅修复 31% 性能差）[4]，并在完全良性的经验流下系统性抬升 ASR 且无自然恢复 [5]。这意味着"不改权重所以更安全"的直觉不成立，记忆类方法必须补齐 C4 与 C6 两个组件才能获得与策略优化同等的退化控制力。

最终，两条路线正在向同一组设计原则收敛：局部化编辑（rewrite locality）、形式化门控、以及可回滚的版本化载体。而领域共同的最大缺口在于 C6——溯源与审计覆盖率仅 33%，0037 所呼吁的"temporally valid、localized、reversible、auditable"四项检验，在 0038 的 authority collapse 与 SkillMisevo-Bench 的 21/21 不安全制品结果面前，仍未被任何单一方法同时满足 [13][8]。
