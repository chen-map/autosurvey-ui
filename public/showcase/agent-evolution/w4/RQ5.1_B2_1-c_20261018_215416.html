摘要

本报告基于知识图谱的 extends/contradicts 谱系边与原文段落，重建了 RQ5.1 所问的“推理范式 → 符号学习 → 技能库/RL → 协议化自进化”方法演化链。结论是：该链可以被重建，且中间三段有密集的结构化 extends 边直接支撑；KG 呈现的是以符号学习论文 [1] 和技能库 RL 论文 SAGE [2] 两个高入度枢纽为核心向外辐射的谱系树，而非单根有向路径。

各阶段主导的进化载体依次为：符号学习阶段的“prompt/tool/pipeline 可学符号组件”；技能库/RL 阶段的“可复用可执行的 skill”，由 RL（GRPO + Sequential Rollout + Skill-integrated Reward）驱动 [2]；协议化自进化阶段的“资源本体（RSPL）+ 闭环进化算子（SEPL）”，由 Autogenesis Protocol 收束 [3]，并向递归元技能进化延伸 [4]。综述 [5] 给出的 Verbal→Procedural→Structural 三载体分类与本四段链高度吻合。需要强调，链起点 ReAct 与 Procedural 奠基作 Voyager 在本 KG 中无独立论文节点，链首端衔接依赖综述二手引用，这是最主要的证据缺口。

演化链四阶段与主导进化载体

下表给出 RQ5.1 追问的演化主线。每一阶段标注其“进化载体”（evolvable substrate）与代表性论文。

阶段一（推理范式）：以 ReAct 式 think-act-observe 为隐式基线，KG 中仅以方法节点 method_method_react 出现（origin_paper_id 为空），在 ALFWorld、GAIA、WebShop 等基准上作为 baseline 被评测，无其自身的谱系出边。

阶段二（符号学习）：[1] 将 agent 视为 symbolic network，用手写所有符号组件的语言化 loss/gradient/optimizer 联合优化，完成 engineering-centric → data-centric 的转向，成为谱系根（30+ extends 入边）。

阶段三（技能库/RL）：[2] 明确以 RL 取代“仅靠 LLM prompting 的技能库”，把进化载体升级为可执行、可复用、可保存/更新的程序化 skill，并在 AppWorld 上量化收益。

阶段四（协议化自进化）：[3] 把零散 ad-hoc 自进化抽象为两层协议（RSPL 资源本体 + SEPL 闭环算子），[4] 进一步把“改进过程本身”作为可进化对象，实现递归自进化。

谱系结构的拓扑特征：双枢纽而非单链

KG 的 extends 边揭示了演化链的真实拓扑：[1] 与 [2] 是两个“超级枢纽”。[1] 被 AVATAR [7]、ToolMaker [8]、Agentic Context Engineering [9]、MemSkill [10]、Combee [11]、CoEvoSkills [12]、MetaSkill-Evolve [4] 等 30+ 篇论文 extends 继承，下游横跨 prompt 优化、工具生成、上下文工程、记忆技能、进化搜索、验证合成等多个子方向，证明它是范式根的候选。

[2] SAGE 则成为第二枢纽，被 CoEvoSkills [12]、SkillOS [13]、SkillPyramid [14]、EVOSOP [15]、MetaSkill-Evolve [4] 等 20 篇左右 extends，把载体从“文本符号”推进到“可执行程序化技能”。这种双枢纽结构意味着：RQ 所设想的“线性链”更准确的描述是“符号学习根 → RL 技能库升级 → 协议收束”的三级放大树状谱系。

反事实检验：演化并非线性单向

按分析框架要求，主动寻找“曾试图替代旧范式但未成功或仅部分成功”的挑战者，避免把演化叙述为必然进程。

【失败挑战者 1：结构进化 DARWIN [6]】DARWIN 尝试用遗传算法改写 LLM 训练代码以直接进化架构，但其自述在 50 次训练中遭遇 18 次错误（错误率 37.5%）、错误解决率仅 16.67%，且“无显著改进”，是典型的“结构进化尝试效果不足”分支。

【强挑战但受能力边界限制：[16]】“Rethinking Self-Evolving Agents” 直接质问“还需要预设优化流水线吗”，其 Open-Ended Optimization 在 8 个基准 14 组对比中 12 胜 1 平 1 负，仅用 SKILLOPT 34.3% token 预算；但也自承弱优化器无法通过 OEO 接口运作、中等优化器下 SKILLOPT 反超——说明范式共存的“能力边界”，而非替代。

【自进化的非单调性修正：[17][18]】Do Self-Evolving Agents Forget? 指出跨 workflow/skill/model/memory 四通道的 capability erosion，workflow 进化下简单任务保持率需靠 CPE 从 41.8% 提至 52.8% [17]；LLM-as-a-Judge Is Not an Oracle 指出自进化管线需确定性护栏 [18]。二者把“纯自进化”叙事修正为“需保留 + 可治理”的混合路径。

分析局限性

1) 链起点证据缺口：ReAct 在本 KG 中仅作为基线方法节点（origin_paper_id 为空），Voyager、Reflexion、AlphaEvolve 均无独立论文节点，只作为综述 [5] 的引用出现。因此“ReAct → 符号学习”的直接 extends 边不存在，链首端衔接依赖二手引用与 [19] 的反思机制论文，属重建而非 KG 直证。

2) extends 边的推断性质：大量 extends 边（confidence 0.85）为 citation-based 语义推断而非作者显式声明，部分下游（如 SkillOS [13]、SkillMaster）实为并行竞争路线，谱系树在节点边界存在模糊。

3) 时间维度缺失：节点无结构化 year 字段，无法完成框架要求的年度范式种群统计、兴起/高峰/衰退阶段划分与 <3 年数据充分性检验，故未输出 paradigm_timelines 的量化曲线。

4) 量化结果可比性：各论文的 benchmark 不同（AppWorld、GAIA、HLE、OfficeQA 等），跨阶段数字不可直接横向比较，仅作各阶段内部有效性证据。

5) 反事实样本有限：仅识别出 DARWIN [6] 这一明确的失败挑战者，[16] 属“受能力边界限制”而非彻底失败，失败挑战者样本不足以支撑统计性结论。

结论

RQ5.1 的答案是可以重建，且呈四段式：ReAct 式推理（隐式基线）→ 符号学习（载体 = prompt/tool/pipeline）→ 技能库/RL（载体 = 可执行 skill）→ 协议化/递归自进化（载体 = 资源本体 + 进化算子 + meta-skill）。各阶段主导进化载体已逐段标注：符号学习用语言化符号梯度优化组件 [1]，技能库/RL 用 RL 训练可复用程序化技能 [2]，协议化用两层 AGP 把进化治理化 [3]，递归层用双时间尺度进化“改进过程本身” [4]。综述 [5] 的 Verbal→Procedural→Structural 三载体分类与之一致。

但演化链的真实拓扑是“以 [1] 和 [2] 为双枢纽的放大谱系树”，而非单根直线；且链起点衔接与时间序列维度存在明确证据缺口，反事实检验（[6] 失败、[16] 能力边界、[17][18] 安全修正）显示演化终点是“协议化 + 递归 + 可治理”的收敛，而非旧范式被简单取代。后续研究应补齐 ReAct/Voyager 等奠基论文的独立节点，并结构化年份字段以支撑真正的时序演化分析。
