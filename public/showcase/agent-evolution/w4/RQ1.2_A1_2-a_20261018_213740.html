摘要

本报告回答 RQ1.2：能否将 LLM 智能体的“进化轨迹”分解为“进化载体（memory / policy / skill library / workflow / protocol）—更新信号（feedback / verifier / reflection）—更新算子（write / prune / optimize / compose）”三层结构。基于知识图谱（629 Problem、558 Method、274 Paper、317 Limitation、200 Assumption、391 Metric、400 DatasetBenchmark 节点）与 14 篇核心论文的段落级精读，结论是：**该三层分解部分成立，但需要一处关键修正**。其中“进化载体”与“更新算子”两轴真正正交、可构成 MECE 骨架；而“更新信号”不是与二者并列的正交第三轴，而是算子的触发输入，应降格为算子层级上的子维度（信号源 × 更新目标）。

这一判断得到三条独立证据线支撑：SAVER 框架以 Substrate（载体）× Adaptation（算子）为核心配对关系 [1]；动态图视角综述把载体重述为类型化节点、把算子重述为 DPO 图重写规则 [2]；AGP 协议则把“载体（what evolves）”与“进化逻辑（how evolution occurs）”的分离升为核心设计原则 [3]。与此同时，Self-Improvements 综述给出的“信号 e_t → 更新算子 U”二层结构 [4]，恰好解释了为什么信号不应被视为独立维度——它是算子的输入而非并列的分类格。

研究问题与认知坐标

本分析采用**约束满足视角**：寻找唯一同时满足互斥性与穷尽性双硬约束的维度组合，而非追求维度命名上的“直觉合理性”。RQ1.2 提出的三层结构本质上是一个分类学主张——主张三个维度可以正交地张成一个覆盖全部演化事件的分类空间。判定标准因此是操作性的：若某一层与另两层无法互斥归类（同一演化事件可被多格覆盖），则该层不构成有效轴。

本子问题的六篇冻结证据论文为：0014（自反思）[5]、2137（SAGE 反射+记忆）[6]、2381（DiffuseAgent-MI 分布接地）[7]、0004（符号学习）[8]、0037（动态图转型综述）[2]、0038（自进化智能体安全综述）[1]。此外为验证分类学命题，补充检索了 2292（AGP 协议）[3]、2368（Self-Improvements 综述）[4]、2289（外部化综述）[9]、2380（AgentStream 流式评测）[10]、2387（FinEvo-Bench）[11]、2420（Experience Funnel）[12]、0073（SAGE 技能库 RL）[13]、0001（超表面自进化框架）[14] 等。

数据来源与规模

本次分析全部结论来自知识图谱的结构化节点/边与论文原文段落检索（search_paper_sections），未使用 LLM 先验知识填充。共执行 31 次工具调用，覆盖全部六类节点（problem、method、paper、dataset、metric、limitation、assumption），并对 14 篇关键论文做了段落级精读（≥8 篇的下限要求已满足）。

核心发现一：载体轴是最稳健、证据最充分的一轴

“进化载体”维度得到至少四条独立证据线的一致支持，彼此重合度极高。SAVER 框架 [1] 以 Substrate 为状态承载单元划分出 memory、tool/interface、skill/procedure、workflow、multi-agent、model/policy 六族，其关键论证是：**“同一句话在 transient context、durable memory、workflow rule、tool-bearing procedure 下后果不同”**，从必要性上确立了载体维度不可省略。动态图视角综述 [2] 独立地把同样内容重述为类型化节点（memory/tool/skill/workflow/agent/communication），其 Table I 的 Scope 列与 SAVER 载体族几乎一一对应。AGP 协议 [3] 把 prompts、tools、memory 等作为独立资源实体管理（RSPL 层），并明确“把载体与进化逻辑分离”使演化具备模块性、可追溯性与安全性。

RQ 提出的五项载体（memory / policy / skill library / workflow / protocol）可被上述证据线覆盖：policy 对应 model/policy substrate，protocol 对应 tool/interface 与 multi-agent 载体。外部化综述 [9] 进一步把 memory（externalized state）、skill（externalized expertise）、protocol（externalized interaction）列为三个并列模块，支持 protocol 作为独立载体保留。AgentStream [10] 与 FinEvo-Bench [11] 也以“context / memory / skill / harness / workflow / policy”为分类主轴，佐证载体轴已具备操作化评测基础。

核心发现二：算子轴是文献形式算子的合法粗粒度归并

RQ 的 write / prune / optimize / compose 四类算子，实质上是文献中更细粒度形式算子的功能语义压缩。SAVER [1] 用七族算子（add、abstract、activate、modify、forget、propagate、migrate）对全文献编码，并强调“算子只有结合其所作用的载体才具有安全含义”。动态图综述 [2] 给出 DPO 式算子：节点级 INSERT / DELETE / FEATUREUPDATE / MERGE，边级 LINK / UNLINK / REWIRE / EDGEFEATUREUPDATE，以及跨组件 CASCADE。RQ 四类恰是这些算子的语义归并：write≈INSERT/ADD，prune≈DELETE/FORGET/UNLINK，optimize≈FEATUREUPDATE/MODIFY，compose≈MERGE/LINK/cascade。

但归并过程会丢失两类信息。第一，**read-only activation**——[2] 专门用一节论证它是一种不改变持久状态的算子，并强调“只有被激活的视图变化，持久图不变”，且“不应被误当作持久学习”；RQ 四类中没有对应项（最接近 prune 或 optimize 都不准确）。第二，**migrate / propagate 这类跨载体搬运算子**——[1] 明确指出“传播倍增了影响可激活的位点，迁移改变了影响可被使用的权限制度”，[2] 则用 CASCADE 刻画跨组件级联。这两类恰是两篇综述反复强调的演化关键形态，却是 RQ 四类算子的盲区。

核心发现三：“更新信号”不是与载体、算子正交的第三轴

这是对 RQ 提法的核心修正。Self-Improvements 综述 [4] 给出了目前最清晰的二层结构：改进目标分为 foundation-model（更新参数 θ）与 scaffolding（更新外围脚手架 Σ），而每条更新路径都被写成“信号 e_t → 更新算子 U（Uθ 或 UΣ）”，即 **信号是算子的输入，不是并列维度**。它进一步把信号源细分为 rubric 反馈（评分/偏好）、consistency 反馈（多数投票/熵/自确定性）、corrective 反馈（自然语言批判 + 修正）[4]。这与 SAVER 的“selection before commitment”功能同构——[1] 中效用代理 b_t 负责排序候选、c_t 限定资格，选择/评估只是算子提交前的环节。

三篇冻结论文提供了“同一更新事件可被三层描述同时覆盖”的直接反证：

- [5] 的反思既是 reflection 信号，其落地方式是把 guidance 注入 prompt（optimize 算子 × policy/context 载体）；

- [7] 的 verifier 产生 faithfulness flag 后触发 re-sample（verifier 信号 × optimize 算子）；

- [14] 的确定性物理 evaluator 产生 CPF/BM/SG 后改写 SKILL.md（verifier 信号 × optimize 算子 × skill 载体）。

若三层真正互斥，同一事件不应同时落入三格；实际却全部同时成立。故 feedback / verifier / reflection 三分描述的是“谁生成监督信号”，属于算子层的触发子维度，与“作用在哪个载体”“用哪种算子改状态”分属不同层级。

核心发现四：各载体上的更新产生可测增益，但普遍有益性存在强反证

在“载体 × 算子”框架下，各载体上的更新确实产生了可量化增益，且增益形态与载体类型高度相关，这为框架的实用性提供了经验支撑。

- **skill 载体 + optimize 算子（0001 [14]）**：在同型任务把成功率 SG 从 38% 提升到 74%，CPF 从 0.51 提升到 0.87，平均尝试次数从 4.10 降到 2.30，而基座语言模型与物理求解器全程固定。

- **skill library 载体 + RL 信号（0073 [13]）**：在 AppWorld 达 72.0% TGC / 60.7% SGC，优于纯 GRPO 的 69.2%/51.8%，且交互步数从 16.4 降至 12.1、生成 token 从 3,613 降至 1,475。

- **memory 载体 + reflection 信号 + 衰减算子（2137 [6]）**：AgentBench 消融中，MemorySyntax 把 LLM 的 KG 任务从 6.8 提升到 45.3，把 Codellama-7B 从 0.0 提升到 48.0。

- **policy/推理载体 + verifier 信号 + repair 算子（2381 [7]）**：MI-Faith / MI-Interp 从 ReAct 的 51.2/44.1 提升至 94.7/88.9，Loc-Acc / Fact-Acc 达 90.1/86.2。

但 AgentStream [10] 的受控流式评测给出关键反证：自我进化**并非普遍有益**——最弱模型出现负增益、收益对模型能力呈非单调关系（中等能力模型获益超过更强模型）、无单一演化方法占优，且 context 类方法偏好 Isolated 场景、检索类方法偏好 Interleaved 场景。这说明“载体 × 算子”框架必须承认载体—场景—模型的交互效应，否则会显著高估通用性。

核心发现五：载体与算子之间存在内部化桥梁

框架的一个重要补充发现是：载体轴并非静态切分。Experience Funnel [12] 提出“状态—策略交替循环”，把外部 skill/memory 载体中的经验通过参数化/策略合并转化为 policy 内部能力，在 SearchQA / ALFWorld / WebShop 平均达 57.6%，超过最强显式状态方法 SkillOpt 的 53.9% 与最强策略内部化基线 OPID。这与 [4] 的“foundation-model 改进 vs scaffolding 改进”二分直接呼应：**更新目标（θ 还是 Σ）本身就是信号层之下的一个关键区分维度，而它恰好刻画了载体之间的迁移方向**。

因此更精确的三层表述应为：**载体（六族） × 算子（四族，需补 activate 与 migrate/propagate）为主矩阵，信号作为每个格子的触发标注（信号源：feedback / verifier / reflection；更新目标：model 参数 vs scaffolding）**。

对 RQ 的直接答复与重构后的分类体系

RQ1.2 的原提法“载体—信号—算子”三层**部分成立**：载体轴与算子轴可作为正交双轴构成 MECE 骨架；信号层则不应与二者并列，而应降格为算子层的触发子维度。重构后的表达式为：

**进化轨迹 = ⟨载体 C, 算子 O, 触发 T⟩，其中 C ∈ {memory, tool/protocol, skill, workflow, multi-agent, model/policy}，O ∈ {write, prune, optimize, compose, activate*, migrate/propagate*}，T = ⟨信号源 ∈ {feedback, verifier, reflection}, 更新目标 ∈ {scaffolding, model}⟩（*为建议补充的算子族）。**

这一重构保留了 RQ 原三层中真正正交的两个轴，并把第三层重新定位为附着于算子格的标注，从而消除了原提法的类别重叠问题。同时它在载体轴上完整覆盖了六篇冻结论文的全部载体类型，在算子轴上覆盖了价值矩阵中的 6 个格子（见第三章表格）。

分析局限性

**第一，正交性缺乏定量检验。** 本分析框架要求对候选维度对计算 Cramer's V 或 Jaccard 相似度（>0.3 即判为不正交），但 KG 中的 Problem 节点未附带统一的“载体/算子”类别标注字段，且大量节点与本 RQ 无关（629 个 Problem 中绝大多数属光学、网络科学等其他领域）。因此在可操作的节点集合上无法执行真实的集合交并运算，正交性判断只能基于文献的结构性论述，属定性推断而非数值证明。

**第二，缺少直接文献背书。** 没有任何单篇论文把“载体 × 信号 × 算子”三轴明确并列作为分类体系。最接近的是 2368 的“信号→算子”二层 [4] 与 AGP 2292 的“载体/算子”二层 [3]，二者各自只支持两层。这意味着 RQ 的三层提法属于合理但未被直接验证的构想。

**第三，视角偏置。** 0037 [2] 自承其从动态图到自进化智能体的映射“主要是概念性的，不提供经验评估”；SAVER [1] 以安全而非能力为主视角。因此两轴骨架在“安全性/可治理性”维度的证据强于“能力提升”维度。

**第四，定义性分歧。** activation 是否属于“演化”存在争议——[2] 强调 read-only activation “不应被误当作持久学习”，若纳入算子轴会使“演化”的边界模糊，需下游研究澄清。

**第五，证据矩阵规模有限。** 六篇冻结论文中，0014 仅测单步问题 [5]，2381 的 verifier 在固定协议上训练 [7]，0073 仅在 AppWorld 验证 [13]，0001 受限于单一求解器栈与单一基准设计 [14]——各经验增益的外部效度均受约束。

结论

RQ1.2 提出的三层分解**部分成立，但需结构性修正**。正确的分类骨架是“进化载体 × 更新算子”正交双轴：载体轴分六族（memory、tool/protocol、skill、workflow、multi-agent、model/policy），得到 SAVER [1]、动态图综述 [2]、AGP 协议 [3]、外部化综述 [9] 四条独立证据线的一致支持；算子轴分四族（write、prune、optimize、compose），是文献形式算子（INSERT/DELETE/FEATUREUPDATE/MERGE、LINK/UNLINK/REWIRE、add/abstract/modify/forget）的合法粗粒度归并，但建议补充 activate 与 migrate/propagate 两族以覆盖 [1] 与 [2] 强调的关键演化形态。

“更新信号”不应作为并列第三轴：2368 [4] 将其严格建模为更新算子 U 的输入 e_t，SAVER [1] 将其定位为算子提交前的选择/评估环节；且 [5][7][14] 三例证明同一更新事件可同时被三层描述覆盖，违背互斥性。信号应降格为算子层的触发子维度，其内部区分（信号源：feedback / verifier / reflection；更新目标：scaffolding / model）仍有分析价值，并与载体间的内部化迁移相耦合 [12]。

经验层面，各载体上的更新确实产生可量化增益（0001 SG 38%→74% [14]、0073 SGC 51.8%→60.7% [13]、2137 KG 6.8→45.3 [6]、2381 MI-Faith 51.2→94.7 [7]），但 AgentStream 的受控评测表明自进化并非普遍有益，其收益受模型能力与任务流结构门控 [10]——因此“载体 × 算子”框架须显式纳入载体—场景—模型的交互项，方能在真实部署条件下成立。
