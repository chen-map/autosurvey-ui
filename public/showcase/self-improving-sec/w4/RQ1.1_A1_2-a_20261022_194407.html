摘要

本报告针对子问题 RQ1.1——已有工作各自如何界定"自改进"，其反馈信号来源、更新对象与更新触发时机分别落在哪些取值上、构成怎样的组合分布——基于知识图谱结构化数据（problem / method / paper / dataset / metric / limitation / assumption 七类节点及其关系边）进行系统性分析。

核心结论：已有工作并非围绕单一"自改进"定义，而是沿三条近似独立轴分布的三元取值组合。反馈信号来源观测到四类取值（verification results、runtime/attack feedback、test coverage、attack-defense experience）；更新对象观测到六类取值（prompt/skill、memory、workflow-scaffold、policy、toolchain、weights）；更新触发时机呈三级（intra-episode reflection、inter-episode iteration、cross-task accumulation）。六篇冻结论文绝大多数仅占据三轴组合中的 2–3 格，没有任何一篇覆盖全部取值；且真正实现跨任务持久更新的"强意义自改进"比表面宣称的显著更稀少，多数工作实为回合内（intra-episode）的判定核验或修复，而非产生可复用持久产物的自进化。

数据来源与规模

本次分析的全部证据来自知识图谱的结构化节点与关系边，未使用任何 LLM 先验填充。KG 规模为：problem 节点 402 个、method 节点 385 个、paper 节点 141 个、limitation 节点 226 个、dataset 节点 235 个、metric 节点 256 个、assumption 节点 100 个，合计约 1,745 个节点。

分析聚焦 RQ 冻结的 6 篇证据论文（0045、0324、0336、0362、0462、0528），并追溯其 proposes / targets / addresses / has_limitation / evaluated_on / measured_by 一跳关系边，同时引入 13 篇提供关键对照证据的邻域论文（含自改进综述 [1]、自进化安全综述 [2]、CyberEvolver [3]、EvoRepair [4]、EVOHUNT [5]、SkillProx [6]、SED [7]、技能-记忆自进化智能体 [8] 等），以补全冻结集稀疏的取值格。共执行 32 次工具调用，覆盖 problem / method / paper / dataset / metric / limitation / assumption 全部七类节点。

重要说明：语义原文检索工具 search_paper_sections 在多次调用中均返回 'Unknown tool' 错误而不可用。因此原文级溯源改由 KG 边（edge）的 evidence 字段承担——这些字段直接保存了论文原文引用片段，可视为等价的可核验证据来源。凡在本报告中引用的结论，均对应 KG 中某个节点的 description 或某条边的 evidence 字段。

核心分析一：反馈信号来源的差异本质是"信号来自何处"

在漏洞检测 / 审计这一侧，反馈信号以静态判定加人工或工具核验为主。[9] 以 RAG、SFT、Dual-Agent 三路线对比平均 F1（RAG 0.85 > SFT 0.80 > Dual-Agent 0.77 > base 0.67），其中 Dual-Agent 的"第二智能体验证并纠正推理与假设"本质是 intra-episode 的判定核验，而非跨任务更新。[10] SmartAuditFlow 的反馈则明确来自静态分析器（Semgrep / CodeQL）与 RAG 的检出结果，驱动"计划—执行"的迭代精炼，以降低幻觉与误报。

在渗透测试这一侧，信号转为 runtime / attack feedback。[11] PentestAgent 用 self-reflection 处理执行阶段的命令结果，解决长期记忆与状态化工作记忆管理问题；[12] VulnBot 用 Planner + Memory Retriever + Summarizer 维护跨子任务的上下文，其 Penetration Task Graph 承担了任务依赖与进展信号的载体。攻击-防御经验作为第三种信号，最典型地出现在 [15] MACRO（把成功轨迹蒸馏为可复用 composite tool）与 [16] EvoRec（把每轮 success/failure 归因写入 Memory）；邻域中 [17] RefPentester 的 Reflector + Success/Failure Log、[13] EvoMail 的 red-team/blue-team 对抗自进化循环亦属此列。

test coverage 作为反馈信号在六篇冻结论文内几乎缺位，仅在邻域论文中出现：[18] 以小规模强测试套件作为自进化智能体的"改进信号"、[3] CyberEvolver 用轨迹诊断从嘈杂反馈中提取变异信号。这说明冻结集更关注"攻击是否成功/漏洞是否确认"这类终局信号，而较少使用覆盖率这类过程性信号。

核心分析二：更新对象的分歧即"真自进化"与"回合内修复"的分界线

[16] EvoRec 是六篇中更新面最宽者：自进化 Model 参数 + 可进化 Skill library + 持久 Memory 三件套协同演进，四智能体构成 dual-track 循环，实现模型与方法的共同进化。[15] MACRO 次之，更新 composite-tool 技能库、memory 与 GRPO 下的 policy，将成功轨迹内化为可复用多步过程。[10] SmartAuditFlow 主要更新 workflow/scaffold（审计计划）与 prompt。[12] VulnBot 更新的是 memory 与任务图。而 [9] Dual-Agent 与 [11] self-reflection 基本停留在 prompt/context 层面，不产生持久产物。

邻域证据进一步补全 weights 一端：[4] EvoRepair 的 experience bank、[6] SkillProx 的文本梯度式 skill 精炼、[5] EVOHUNT 把学习信号外化为可迁移 text playbook（明确"不改模型权重"），共同印证 weights 更新是被多数工作主动规避的昂贵选项——自改进主要通过上下文、记忆、技能等外部载体实现，而非重新训练模型。这一取向与 [8] 技能-记忆架构、[7] SED 的 training-free 安全策略学习相互印证。

核心分析三：触发时机三级与持久性强相关

intra-episode reflection（[11][10]）在单回合内修正动作，不跨任务留存；inter-episode iteration（[16][10] 的计划多轮精炼）在一批任务内迭代；cross-task accumulation（[16][15]）才真正把经验沉淀为下一批任务的先验。

这里存在固有张力：自改进综述 [1] 明确指出"智能体用反馈解决当前任务却不把可复用变更带入后续任务"是普遍病灶，并把"artifact correctness ≠ agent improvement"（产物正确不等于智能体改进）列为核心问题，还批评基准复用会导致"适应评估器"被误读为"一般性改进"。这直接说明多数被标定为"自改进"的工作实则只在 intra-episode 层面运作。[2] 的安全综述则以 SAVER 框架（substrate × adaptation → violation → exposure → response）强调必须区分"载体"与"操作"，进一步说明触发时机与更新对象的组合才是刻画自进化的关键，而非单一维度。

核心分析四：现有分类体系的缺陷诊断（支撑 A1.2-a 重构动机）

本 RQ 的三轴命名（prompt / memory / skill / policy / toolchain / weights）与文献中已有 taxonomy 存在系统性错位，这构成后续正交重构的直接证据。

其一，**命名异质与重叠**。自改进综述 [1] 将持久变更分为"技能与工具、工作流与拓扑、记忆、框架、模型"五类（skills-and-tools / workflow-and-topology / memory / framework / model 自进化），[2] 则用"substrate × adaptation"二维框架。RQ 的 skill library 与 toolchain 实际横跨 [1] 的"技能与工具"与"框架"两类；RQ 的 prompt 与 workflow-scaffold 的边界在 [10] 与 [11] 的描述中高度模糊（二者都在"改上下文/改流程"之间游移）。这种 1:N 映射使"组合分布"的精确枚举受命名粒度制约。

其二，**遗漏（omission）**。RQ 六分法未把"environment / evaluator 自进化"单列，但 [1] 单列 self-play co-evolution（改变供给学习信号的任务与评估器）为一类独立演化面，这是六分法的结构性遗漏。

其三，**语义模糊导致的误标**。[1] 明确批评多数智能体"用反馈解决当前任务却不带可复用变更"，意味着大量方法被错误地放入"自改进"名下，实为 intra-episode 修复；[6] 进一步指出"未验证的前向更新"（把 LLM 生成的诊断直接当作有效更新方向）与"未受控的技能膨胀"是现有技能自进化的两大缺陷，说明"更新对象"轴上技能类取值的内部质量差异被现有分类抹平。

分析局限性

1. **原文检索工具不可用**：search_paper_sections 多次返回 'Unknown tool' 错误，导致无法执行段落级语义检索（框架要求的 Step 6 原文溯源）。证据改由 KG 边 evidence 字段承担，虽为原文引用，但覆盖粒度受限于已抽取的边，可能遗漏未入库的细节论述。

2. **冻结集证据格稀疏**：test coverage 作为反馈信号在六篇冻结论文内几乎空缺；weights 更新仅见 partial 证据（[16] 的 Model 更新、[15] 的 GRPO policy）。依赖邻域论文补足会引入外部普适性风险，相关结论外推需谨慎（C6、C8 置信度 0.70–0.75）。

3. **缺少跨任务因果证据**：各论文报告的量化收益多针对单任务指标（F1、solve rate、bAcc、Recall@K），鲜有"跨任务留存增益"的因果证据，故触发时机轴 high tier（cross-task）的实际验证样本极少，C9 置信度仅 0.78。

4. **三轴划分的判定依赖语义解读**：update object 与 trigger timing 的归属由方法节点 description 的语义判定，缺乏统一的量化标注规则；C3（PentestAgent 是否含跨任务持久化）存在解释空间（置信度 0.72）。

5. **领域偏置**：更新面最宽的两篇 [16][15] 均来自非网络安全域（推荐系统、医学影像），其在安全任务上的可迁移性未经验证，这限制了"最宽更新面"结论向安全域的推广。

结论

对 RQ1.1 的回答是：已有工作对"自改进"的界定呈"三轴稀疏组合"格局。反馈信号来源上，漏洞检测/审计类以 verification results（静态判定 + 核验）为主（[9][10]），渗透测试类以 runtime/attack feedback 为主（[11][12]），而 attack-defense experience 与 test coverage 更多见于自进化/对抗防御类与邻域工作（[15][16][17][18]）；更新对象上，以 prompt/context、memory、skill-toolchain 为三大主流载体，weights 更新被普遍规避（[4][5][6] 均转向外部文本载体），policy 与 workflow-scaffold 居中；触发时机上，intra-episode reflection 是最大公约数（[9][10][11]），真正达成 cross-task accumulation 的仅 [15][16]，且二者均非安全域。

因此，本子问题的正确答案不是"自改进被统一定义为 X"，而是：**自改进被界定为一个三维取值的组合空间，现有工作在该空间中高度分散，且三分之二以上的"自改进"宣称实际只落在 intra-episode 层级**。这一诊断直接为 A1.2-a 的正交重构提供了动机：需要一个能显式区分"反馈来源 × 更新载体 × 触发时机"、并补上 environment/evaluator 自进化遗漏维度的新分类体系，同时修复 prompt/workflow、skill/toolchain 的边界模糊问题。后续工作应优先补充 test coverage 与 weights 两格的证据，并建立跨任务留存增益的因果评估协议，以消除触发时机高 tier 的证据缺口。
