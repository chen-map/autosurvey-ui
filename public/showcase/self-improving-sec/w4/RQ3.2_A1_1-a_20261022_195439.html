摘要

本报告针对 RQ3.2——现有工作显式声明了哪些泛化收窄假设（Isolated-function evaluation、C/C++ memory-related vulnerability scope、High and Critical severity only、Identical foundation model），这些约束节点中多少带有关系边、多少完全孤立，是否意味着结论的可迁移性从未被作者正面讨论——对知识图谱执行了系统性结构分析。核心发现是一个鲜明的『非对称结构』：四类命名假设在 KG 中以 `assumptionconstraint_*` 节点形式存在，且全部为完全孤立节点——一跳关系边为 0、origin_paper_id 为空。抽样验证的 16 个此类节点无一例外零边，说明假设层整体被结构化地孤立化而非个别现象。

然而 RQ 假设需要一处重要修正：作者并非『从未触及』这些约束的内容，而是换了两条不指向『假设-迁移』关系的替代表述路径——其一为『改写成我方法要解决的研究问题』（Problem 家族带 addresses/targets 边，如 RAVEN、EvoRepair、EVOHUNT），其二为『退守为局限性自陈』（Limitation 家族带 has_limitation 边，如 SecureVibeBench、EVOHUNT）。因此精确结论是：可迁移性从未以『假设被放宽→结论如何衰减』的迁移律形式被正面讨论；作者只在两个替代位置上零散触及，故『从未讨论』应弱化为『从未以假设-迁移界律形式讨论，但已零散做过迁移测量』。

数据来源与规模

本分析基于知识图谱的多类型节点与关系边，共执行 39 次工具调用，覆盖全部 7 类节点（problem、method、paper、dataset、metric、limitation、assumption）。具体数据规模如下：Problem 节点总量 402（展示 30 条样本）、Method 节点 385、Assumption 节点 100（展示 30 条样本，逐一验证 16 个的边状态）、Limitation 节点 226（展示 30 条样本）、Dataset 节点 235。深度读取了 16 篇关键论文的完整一跳关系，包括 RapidPen[1]、Metrics Failure[2]、SecureVibeBench[3]、RAVEN[5]、EVOHUNT[6]、EvoRepair[7]、Security Arena[8]、ACE[9] 等。分析路径为：对四类命名假设节点做双向边查询（全部返回空）→ 通过模糊实体链接找到其内容孪生的 Problem/Limitation 节点 → 验证孪生节点确实携带关系边，从而建立『假设层孤立 vs 内容层带边』的对照。

重要方法论说明：本环境中 `search_paper_sections` 原文检索工具不可用（返回 Unknown tool）。因此所有结论建立在 KG 结构化节点与关系边之上，未能核对论文正文方法章节中可能存在的正向迁移叙述。这一缺口已在『分析局限性』章节显式声明。

核心发现：假设层的完全孤立化

对四类 RQ3.2 命名假设节点的双向关系边查询全部返回空列表，且其 origin_paper_id 字段均为空字符串。进一步抽样验证了 16 个 `assumptionconstraint_*` 节点（包括 perfect_recall、cwe_identifier_upstream、default_tool_configuration、remote_api_access、adversary_can_develop_own_llm_agents 等），无一例外零边。这与 Method/Problem/Limitation 层的密集边形成强烈反差：例如 ProverAG[10] 方法节点携带 8 条出边（targets、relaxes、evaluated_on、measured_by 等），RAVEN[5] 论文节点携带 18 条出边。

这揭示了一个关键的结构性事实：假设节点在 KG 中是『被贴上标签却从不被任何方法/论文/问题引用』的悬空实体。没有任何一条 requires 或 relaxes 边把某个方法与它依赖或放宽的假设连接起来——这意味着『方法依赖哪些泛化假设、放宽后是否能迁移』这一因果链在结构化知识中根本不存在。

假设的两种替代表述路径

作者虽未以『假设-迁移』形式讨论这些约束，但通过两条替代路径触及了它们的实质内容。

**路径一：改写为『待解问题』以支撑通用性主张。** 同一内容在 Problem 家族中以带边节点出现，被论文以 addresses/targets 边声明为『本方法已解决』，从而把收窄约束转化为通用性正面主张而非迁移警告。RAVEN[5] 以 addresses 边关联 limited_generalization_to_unseen_vulnerability_types（『现有 AVR 框架大多局限于内存相关、可本地修复的漏洞』），并声称跨漏洞类型、跨未见 CWE、跨语言（Java 与 C）泛化，还在 Vul4j 上以 23 个随机 CVE 做 OOD 评估。EvoRepair[7] 则以跨语言基准（PATCHEVAL 的 JS/Python/Go、SEC-bench 的 C、Vul4j 的 Java 且『语言与 CVE 组成正交，用以验证经验迁移能力』）直接检验跨语言、跨 CVE 迁移。EVOHUNT[6] 以 addresses 边关联 transfer_of_audit_procedures_across_models_and_harnesses，用 Codex/LLM 与 OpenCode/GLM5.1 双环境验证跨模型迁移。

**路径二：退守为『局限性自陈』。** 同一约束在 Limitation 家族中以带 has_limitation 入边的节点出现，但表述是自我否定的止损声明。SecureVibeBench[3] 的 narrow_vulnerability_and_language_coverage（『聚焦 OSS-Fuzz 与 ARVO 的内存相关 C/C++ 漏洞，可能对其他漏洞类型与编程语言产生偏置』）正是 C/C++ scope 约束的软化身；EVOHUNT[6] 的 benchmark_scope（『聚焦源码可得仓库、high/critical 通告、CVSS 合格可达性』）正是 severity 约束的软化身。关键在于这些局限从不反过来约束『假设被放宽后结论仍成立』——作者写法止于『我们只在这些条件下测过』，从不写『因此换 CWE/语言/仓库规模/基础模型时，收益预计如何衰减』。

对抗性证据：谁在事实上做了迁移测量

必须记录真实的反向证据：多篇论文实际上做了跨 CWE/语言/模型的迁移测量，因此『从未讨论』的强表述站不住。Security Arena[8] 用 3×3 攻击者-防御者矩阵（LLM Opus 4.6、LLM、Gemini 2.5 Pro）实证『汇合三个攻击者 LLM 比最强单攻击者多发现 1.7–2.2 倍唯一成功输入』，从方法论上证明单一基础模型会系统性低估能力边界。EVOHUNT[6] 直接以两个不同厂商模型栈验证 playbook 迁移。EvoRepair[7] 明确以『与 PATCHEVAL、SEC-bench 正交』的 Vul4j 验证跨语言/跨 CVE 经验迁移。RAVEN[5] 以 23 个随机 CVE 做 OOD 评估。

但这些测量都嵌在『我方法有效』的叙事里，而非『我的假设在何种边界上失效』的叙事里。没有一篇论文给出『当 CWE 从 7 类扩展到 N 类、或基础模型从 LLM 换成他者时，报告的收益按什么规律衰减』这样的迁移律。这正是 RQ 想揭示的空白：迁移测量存在，但迁移界律缺席。

分析局限性

其一，原文检索工具 search_paper_sections 在本环境不可用，全部结论仅基于 KG 结构化边，若论文正文方法章节存在未被结构化的正向迁移叙述，本分析无法捕捉，这是最显著的证据缺口。其二，跨 repository scale 维度几乎找不到任何带边证据（既无假设/问题/局限节点以仓库规模为自变量），该冷区成因只能标为 unknown_blind_spot，置信度较低（0.78）。其三，跨 severity 等级泛化的成因（technical_barrier）是基于『低危漏洞缺少 PoC/可利用性信号』的合理推断，缺乏直接检索证据支撑。其四，孤立假设节点的抽样覆盖为 16 个（占 100 个 assumption 节点的约 16%），虽高度一致但仍属抽样。其五，『identical foundation model』（LLM）的原始出处论文未能在工具结果中精确定位到唯一节点，只能通过其内容孪生（single_llm_used 等）间接论证。

结论

对 RQ3.2 的精确回答是：四类命名泛化收窄假设在知识图谱中 100% 表现为完全孤立节点（0 条关系边、无源论文绑定），假设层整体被结构化地孤立化。结论的可迁移性从未以『假设被放宽→收益如何衰减』的迁移律形式被作者正面讨论。作者仅在两个替代位置上触及这些约束——或改写为待解问题（进而转化为通用性正面主张，如 RAVEN[5]、EvoRepair[7]、EVOHUNT[6]），或退守为局限性自陈（只声明测试范围、不声明迁移律，如 SecureVibeBench[3]、EVOHUNT[6]）。

因此 RQ 的核心判断在结构层面获得强支持，但需弱化一处：并非『从未讨论』，而是『从未以假设-迁移界律形式讨论』——零散的跨 CWE/语言/模型迁移测量确实存在（尤其 Security Arena[8] 的 1.7–2.2× 多模型结论从方法论上反证了单一模型的风险）。而在四类约束中，跨 repository scale 是最深的认知冷区（近乎无证据，属认知盲区），跨 severity 等级泛化次之（仅 1 条隐含局限、属技术壁垒），这两处是自改进方法泛化边界研究最值得填补的空白。
