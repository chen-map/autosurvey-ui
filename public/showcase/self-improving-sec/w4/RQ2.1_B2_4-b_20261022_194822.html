摘要

本报告针对 RQ2.1——「漏洞检测结果作为反馈信号时，其 Precision/Recall/F1 水平如何转化为自改进增益；在缺少显式安全规格条件下，告警噪声如何影响闭环稳定性」——基于知识图谱 assumption/problem/method/paper/metric/limitation 六类节点及其关系边进行系统分析。核心结论是：漏洞检测反馈的自改进增益高度依赖检测器信噪比。当检测器经 RAG/LLM 语义增强时（F1 可达 0.85）反馈信号携带强可执行性；而直接以传统静态分析器（CodeQL/Semgrep/Bandit/cppcheck）作为反馈源时，其聚合 precision 虚高而逐样本一致率仅 61–65%，会把大量噪声注入闭环。

在缺少显式安全规格的条件下，噪声是闭环稳定性的首要破坏源：LLM 自审准确率仅 43.6–74.6%、对抗性输入可使 >90% 补丁偏离目标、Bandit 反馈闭环中同类漏洞（CWE-94）在 44 样本中复发 25 次。缓解路径集中于多信号融合与语义判据压噪（多工具融合、语义漏洞预测器、检测+验证子代理），而非信任静态规则原始告警。需注意：语料中缺少「告警噪声比例 vs 闭环收敛」的显式敏感性消融曲线，故该问题为部分回答（partial）。

证据主线一：检测器 P/R/F1 差异直接决定反馈价值上限

KG 中 0045 [5] 的对比边显示：RAG=0.85、SFT=0.80、双智能体=0.77、基线=0.67，检索增强检测高出基线约 18 个 F1 点，说明高 F1 检测器携带更强可执行反馈信号。相反，0153 [1] 用 1,080 条人工标注 LLM 样本构建 ground truth 后发现 Semgrep/CodeQL 逐样本一致率仅 65%/61%，尽管 CodeQL 聚合 secure 分类率达 80%——precision 的『聚合假象』掩盖了样例级崩塌。0571 [2] 进一步证明 CodeQL/Semgrep 在 Autoware 46 个已知弱点上命中 0/46，而 LLM 分析最多恢复 76%，cppcheck 单次产生 1,301 条告警。三方证据形成一致链条：传统静态分析器 recall 极低、precision 虚高且逐样本不可靠，其输出作为反馈会把噪声直接灌入闭环。

证据主线二：噪声进入闭环后破坏稳定性并诱发错误修复

0309 [6] 报告 LLM 自审漏洞准确率仅 LLM 43.6%、LLM 74.6%，假阳性率 LLM 达 4.3%，且对自产代码修复更差（成功修复上限约 60%，SecurityEval 上平均 76.2% 代码不安全）。0315 [3] 的 AutoSafeCoder 用 Bandit 静态反馈闭环，却把反馈限制在 4 次迭代，CWE-94 在 44 个漏洞样本中复发 25 次，暴露『噪声反馈下迭代不收敛、同类漏洞复发』的闭环失稳。0217 [7] 从对抗视角佐证：在无显式规格条件下 >90% 精心构造的缺陷报告诱导出攻击者意图补丁，最强过滤器仅挡 47%，说明规格缺失时闭环极易被噪声劫持。0518 [8] 的 CLOSED-LOOP 安全框架亦承认硬约束过滤在近零防御压力下会过剪枝，属于同一稳定性的另一面。

证据主线三：缓解噪声靠多信号融合与语义判据，而非信任静态规则

0438 [9] 融合 GCC+KLEE+CodeQL 三路信号并把修复循环限制在 3 次；0409 [10] 用 Bandit 检测—LLM 修复—Bandit 复扫的检测-修复-验证闭环；0458 [4] 的 SAFuzz 用 LLM 语义漏洞预测器（以 ROC-AUC、precision、bug detection recall、speedup 度量）做自适应时间分配，先过滤非漏洞目标以降低噪信比；0451 [11] 的 AgenticSCR 用检测子代理+验证子代理+安全语义记忆处理『噪声大、缺上下文的静态告警』，并以定位(L)、类型正确(T)、相关性(R)等指标评测。共同逻辑是：用外部/语义信号压噪，而非信任静态规则原始告警。0493 [12] 的综述亦指出 SAST 工具缺乏从扫描历史/人工分诊/运行时证据学习的能力，产生需大量人工分诊的告警洪流。

分析局限性

其一，最关键的『告警噪声比例如何定量影响闭环稳定性』缺乏直接的敏感性消融数据（sensitivity_data: absent），无法从原文图表提取具体拐点阈值，相关判定只能由间接证据（迭代上限、漏洞复发、对抗成功率）推断。其二，检测器定义不一致导致数值不可直接横比——0045 [5] 的 F1=0.85 来自 LLM/RAG 增强检测，0153/0571 [1][2] 的崩塌来自传统静态工具，二者口径不同。其三，闭环论文多以固定迭代上限（4 次、3 次、回合制）作隐式约束，复发可能部分归因于硬上限而非纯噪声效应，难以完全分离。其四，多数结论限于 Python 单语言或单一代码库（Autoware/SWE-bench），泛化性未验证。整体置信度约 0.78。

结论

RQ2.1 的答案是：漏洞检测反馈的自改进增益受制于检测器信噪比。高 precision/高 F1 的检索增强检测器（F1≈0.85）能有效驱动自改进，而传统静态分析器因逐样本一致率仅 61–65%、已知弱点命中 0/46，其聚合 precision 是危险假象。在缺少显式安全规格的条件下，告警噪声成为闭环稳定性的首要破坏源——表现为 LLM 自审低准确率、同类漏洞反复复发（CWE-94 复发 25/44）与对抗输入下 >90% 的错误补丁。有效缓解路径是多信号融合与语义判据压噪（多工具融合、语义漏洞预测器、检测+验证子代理）。当前范式的核心盲区在于：『静态分析器可作可信反馈代理』与『缺陷区域已显式标注』两项高敏感假设从未被噪声-收敛敏感性实验检验，这是最需要补做的消融研究。
