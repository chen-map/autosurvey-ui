摘要

本报告对知识图谱中的 100 个 AssumptionConstraint 节点进行了系统性结构核查，验证「访问权限 / 预算 / 对手能力 / 环境保真度」四轴威胁模型坐标系的重构可行性，并评估假设-方法依赖关系缺失对结论可比性的后果。核心发现：全部 100 个假设中仅存在 6 条 requires 边、约 2 条 relaxes 边，约 60 个假设节点零关系边；其中 6 条 requires 边里有 5 条集中于 ToolLeak 单篇论文 [1]，依赖建模高度集中而非均布。

更关键的是，即使被论文正文明确写出的核心约束——perfect_recall、fixed_llm_execution_budget、identical_foundation_model、python_only_evaluation、adversary_can_develop_own_llm_agents——其节点入边反向查询均返回空列表，说明显式建模缺失是系统性的，而非个别遗漏。四篇冻结论文 [2][3][4][5] 均具备完整的 addresses/proposes/evaluated_on/measured_by/has_limitation 边，却无一条 requires/relaxes 边指向假设节点，呈现『方法-问题-基准-指标关联充分、方法-假设关联缺位』的结构性失衡。

本分析的全部数据来自知识图谱（KG）结构化字段（节点 canonical_name、description 以及边的 evidence 文本），未使用外部原文段落——因 search_paper_sections RAG 检索接口在本次会话中持续返回 Unknown tool 错误而不可用。涉及的数据规模如下：AssumptionConstraint 假设节点 100 个；Problem 问题节点 402 个；Method 方法节点 385 个；Limitation 局限节点 226 个；Paper 论文节点 141 个；DatasetBenchmark 节点 235 个；Metric 指标节点 256 个。六类节点（问题/方法/数据集/指标/局限/假设）均已执行针对性查询，四篇冻结证据论文 [2][3][4][5] 的完整关系边均已读取。

核心发现一：假设-方法依赖关系几乎未被显式建模

对假设节点的入边反向查询是本次分析最具决定性的证据。逐一查询显示：perfect_recall（完美回忆）——尽管 ADAPT 的 Micro Tactic Games 方法证据中明确写着『with perfect recall assumed』[6]，该假设节点入边仍为空；fixed_llm_execution_budget（固定 LLM 令牌预算）、identical_foundation_model（相同基座模型）、compact_llm_hardware_budget（32B/A100 硬件预算）、15-minute time limit、python_only_evaluation、adversary_can_develop_own_llm_agents 等节点的入边查询全部返回空列表 []。

唯一有实质 requires 边的假设集群来自 ToolLeak [1]：secret-in-context、untrusted tool influence、expressive required fields、observable sink、no effective argument sanitization 五个假设均由 ToolLeak 一篇论文通过 requires 边连接。这说明依赖建模的『孤岛化』——绝大多数方法与其依赖的假设之间没有任何可查询的图结构联系。

核心发现二：四轴坐标系可无造词地从现有假设归纳

四个候选维度均可直接从 KG 现有假设的 canonical_name 与 description 文本归纳，无需新造术语。访问权限轴呈黑盒↔灰盒↔白盒梯度（black-box access、black-box HTTP-only interaction、black-box target model access、strict black-box attacker、attacker access to knowledge base）；预算轴量化信息最密集（fixed LLM execution budget、bounded query/round budget、iteration limit ≤4、fuzzing mutation limit 150、sandbox 6 秒、15-minute per-challenge、LLM context window limit、compact LLM 32B/A100）；对手能力轴（adversary can develop own LLM agents、adversary knows library vulnerabilities、attacker knowledge、attacker access to programming intents）；环境保真度轴（Docker-based Kali Linux environment、single-environment evaluation、单 IP 范围、单一语言/CWE 范围、reproducibility limited by changing environments）。

四轴概念上基本正交：访问权限刻画『能看见什么』、预算刻画『能做多少』、对手能力刻画『对手本身多强』、环境保真度刻画『实验场与真实世界的距离』。其中预算轴因携带大量具体数值（≤4、150、6s、15min、32B/A100、ASR@15）最易落地为坐标系取值。

核心发现三：依赖缺失对结论可比性的后果

依赖关系未显式化直接摧毁跨论文可比性，因为同一句『黑盒 LLM agent 达到 X% 成功率』背后的四轴取值组合几乎从不被声明。以 Honeypot 论文 [2] 为例：其问题节点 budget_aware_target_selection_under_honeypot_uncertainty 的 evidence 明写『under a fixed LLM execution budget』，却无任何 requires 边指向 fixed_llm_execution_budget 假设——预算这一决定成败的关键变量仅『内嵌』在问题文本中，未成为可查询的结构化依赖，其 20 主机混布测试台（8 honeypot / 12 vulnerable）[2] 的结论边界因此无法自动界定。

xOffense [3] 声称『消除商业 API 依赖』，通过 LoRA 微调 32B LLM 达成，但 compact_llm_hardware_budget 假设同样无入边。SEVerA [4] 在 DafnyBench、tau2-bench 等基准上报告『零约束违反』，但其 closed-source 模型无法微调这一实质继承自 remote_api_access 的约束亦未连边，使『零违反』的可迁移范围无法被程序化界定。下游若把『15 分钟限制下的 51.9%』与『无时间限制的 100%』直接对表，结论必然失真。

分析局限性

第一，工具层面的硬约束：search_paper_sections RAG 检索接口在整个会话中持续返回 Unknown tool 错误，因此所有证据均来自 KG 结构化字段（节点 description 与边 evidence），未能取得论文原文段落级引用，结论的原文溯源验证无法完成，需在具备 RAG 能力时补检。

第二，覆盖缺口：60 个零关系边假设中仅抽样核查约 25 个并通过反向查询验证了约 10 个核心假设，未穷尽逐一验证全部 100 个假设，omission_rate 与 exclusivity_rate 为抽样估计。第三，正交性风险：四轴虽概念正交，但『对手能力』与『访问权限』在灰盒场景存在取值边界模糊（灰盒既是访问权限取值，也隐含对手具备一定内部知识），未能执行 Cramer's V 定量正交性检验，正式落地时需补做该检验以确保数值 ≤0.3。尽管如此，核心事实——requires/relaxes 极端稀疏、核心假设普遍无结构化依赖——已通过多篇论文 [2][3][4][5][6] 的直接反向查询交叉确认，稳健性较高。

结论

RQ 的初始判断成立且被 KG 数据强化：假设-方法依赖关系几乎未被显式建模——6 条 requires、约 2 条 relaxes、约 60 个零边假设，且核心约束（完美回忆、固定预算、相同基座、仅 Python、对手能力）全部无入边，6 条 requires 中 5 条孤立地集中于 ToolLeak 一篇论文。

「访问权限 / 预算 / 对手能力 / 环境保真度」四轴坐标系对现有 100 个假设具备良好的归纳覆盖能力，且四个维度名称与取值均可从现有假设文本直接取得、无需造词；其中预算轴量化信息最丰富、最易操作化。依赖缺失的直接后果是跨论文结论的可比性被系统性削弱：方法报告的性能数字悬空于未声明的威胁模型格点之上，Honeypot [2]、xOffense [3]、SEVerA [4] 均在被正文明确约束、却未被结构化连接的情形下报告结论。重构的落地路径应是：批量补齐 Method→Assumption 的 requires/relaxes 边，并以四轴格点 (A_i, B_j) 标注每篇论文结论，方能真正划定自改进机制可迁移性的边界。
