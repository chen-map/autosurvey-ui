# Skill: A1.3-c 范式转移对比与边界界定

**层级**：P1.3 深层动因层 · Rationale & Root Causes  
**RQ类型**：为什么？（深层机制解释）  
**元认知逻辑**：构建多维对比矩阵，展示新旧范式在多个维度上的断层，识别「量变引起质变」的临界点，解释旧范式假设的失效机制。  
**认知基准面**：以「假设失效溯源」为透镜——范式转移的本质不是新方法更好，而是旧方法赖以成立的隐含假设在新场景下被系统性违反；因此分析重心在于「旧假设是什么、新场景如何打破它」，而非单纯比较性能数字。

---

## Goal

通过系统性的新旧范式对比，识别导致旧方法根本失效的维度断层，定位「量变到质变」的临界点，为当前 Problem Space 的出现提供范式层面的深层解释。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — 新旧方法节点，含范式标签
- `knowledge_graph/nodes/problems.json` — Problem 节点（旧范式失效带来的问题）
- `knowledge_graph/edges/` — `supersedes` / `incompatible_with` / `assumes` / `contradicts` 类型边
- `paper_cards/parsed/` — Paper Cards，重点提取新旧方法的 System Model / Threat Model 章节
- `analyze_report/design_report.md` — RQ 定义

---

## Execution Steps

### Step 1: 识别新旧范式及其 KG 节点

**认知目标**：范式识别必须有 KG 结构支撑——`contradicts` 类型边直接标记了新范式对旧范式的拒绝，是范式断层的客观编码；`supersedes` 边标记了方法替代关系。从这些边出发，比从文本描述出发更精确。

从 KG method 节点中查找直接编码了新旧对立关系的边：

```python
all_methods = get_entity_by_type(loader, "method")

# 找到所有含 contradicts 边的方法节点对——这些就是范式断层的直接证据
for method in all_methods:
    out_edges = get_relation(loader, method["node_id"], "out")
    contradicts_edges = [e for e in out_edges if e["edge_type"] == "contradicts"]
    supersedes_edges = [e for e in out_edges if e["edge_type"] == "supersedes"]
    # contradicts 边的 evidence 字段包含对比主张文本
```

同时检索文献中的范式对比表述：

```python
paradigm_contrast_hits = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="compared to traditional methods our setting has",
    topk=5
)
paradigm_era_hits = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="era methods versus current paradigm",
    topk=5
)
```

**旧范式**：被大量 `contradicts` 或 `supersedes` 边指向的方法节点集合  
**新范式**：发出 `contradicts` 或 `supersedes` 边的方法节点集合

### Step 2: 选择对比维度

**认知目标**：对比维度必须是 KG 中编码的或论文中明确讨论的变量，不能是 AI 凭印象构造的。`contradicts` 边的 `evidence` 字段文本往往直接包含对比维度的名称——从这里提取比从论文全文检索更可靠。

从所有 `contradicts` 边的 `evidence` 字段提取对比主张，识别其中反复出现的维度关键词（计算规模、环境封闭性、数据可控性、模型透明度、攻击面开放性等）：

```python
for edge in all_contradicts_edges:
    contrast_text = edge["evidence"]  # 直接包含范式对比的文本依据
    context_snippets = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=contrast_text[:80],
        paper_ids=[edge["context_paper_id"]],
        topk=2
    )
```

从出现频率 ≥ 2 次的维度关键词中，选取 4~6 个作为对比维度。

**对比维度提取必须基于文献中讨论的核心变量，不得引入外部概念。**

### Step 3: 构建多维对比矩阵

**认知目标**：「质变」vs「量变」的判断是此步的核心输出——质变意味着旧方法的适用性从「可以用，效果差」变成「根本不能用」，这是论证旧方法系统性失效的关键。每个质变判断都需要逻辑论证，而非感觉。

对每个维度，描述旧范式和新范式的取值或特征：

| 维度 | 旧范式 | 新范式 | 断层描述 | 变化类型 |
|------|--------|--------|----------|----------|
| 维度A | 旧值 | 新值 | 具体断层 | 量变/质变 |

**质变判定标准**：若旧方法在新范式取值下的核心假设不再成立（不仅是效果下降，而是前提条件被违反），则为质变。必须附逻辑论证：「为什么不仅仅是程度差异，而是性质差异」。

### Step 4: 识别旧范式假设的失效点

**认知目标**：旧方法的「失效」不是随机的，而是由其隐含假设被新场景违反导致的。挖掘这些假设——它们往往没有在论文中明确写出，而是隐含在方法设计中——需要用 `requires` 边来反向提取。

对每个旧范式方法节点，使用 `get_tail_entity` 提取其假设节点（即旧方法成立的前提条件）：

```python
# 提取旧方法的假设/前提节点
old_method_assumptions = get_tail_entity(loader, "requires", old_method_id)
# assumption 节点的 description 字段即为该假设的文本表述
```

对每个假设节点，分析其在新范式下为何不再成立：
- 旧假设：`assumption_node["description"]`
- 新范式违反方式：对比 assumption 描述与新范式特征，用 `search_paper_sections` 确认

示例推理结构：
- 旧假设：「系统输入是受控的」→ 新范式：「系统输入来自互联网，完全不可控」→ 旧方法的白名单过滤全面失效

**每个失效假设必须至少引用一篇论文的具体段落（含章节号）作为证据。**

### Step 5: 界定旧方法的有效边界

**认知目标**：边界分析的目的不是「贬低」旧方法，而是精确定位「旧方法在何种条件下仍有效、何时失效」——这为研究者提供了清晰的适用范围判断，避免在错误场景下使用旧方法或错误地否定旧方法的贡献。

明确旧方法在什么条件下仍然有效（边界条件），超出边界条件后失效：
- 旧方法有效区间：[具体可操作的条件，如「当训练数据规模 < 100K 时」]
- 失效临界点：[临界条件，必须量化或可操作化]
- 新范式覆盖区间：[条件描述]

**禁止使用「在简单场景下」等模糊表述；有效边界必须具体可操作。**

### Step 5a: 对抗性验证对比维度的完整性

**认知目标**：在输出最终矩阵之前，必须检验：是否遗漏了关键对比维度？是否有论文的核心对比主张未被纳入矩阵？

```python
# 检验 contradicts 边是否全部被处理
unprocessed_contradicts = [
    e for e in all_contradicts_edges
    if e["evidence"] not in [d["source_evidence"] for d in comparison_dimensions]
]
# 若存在未处理的 contradicts 边，从中提取新的对比维度候选
```

同时验证：对于每个质变维度，确认旧方法的 `requires` 边中确实存在对应的假设节点被违反——若无 KG 假设节点，降级为「文本证据支撑的质变」并标注 `assumption_kg_node: absent`。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **对比维度必须来源于文献中明确讨论的变量**（如论文中出现过「compared to traditional methods, our setting has ...」类描述），禁止 LLM 自创对比维度；优先从 `contradicts` 边的 `evidence` 字段提取。
- 「质变」判定需要严格说明：为什么不仅仅是程度差异，而是性质差异？必须附逻辑论证。
- 旧方法有效边界的描述必须具体可操作（如「当训练数据规模 < 100K 时」），禁止使用「在简单场景下」等模糊表述。
- 若文献集中无明确的新旧范式对比讨论，必须标注 `paradigm_shift: not_explicitly_discussed`，不得强行构造范式对比叙事。
- 每个失效假设必须至少引用一篇论文的具体段落（含章节号）作为证据。
- **认知坐标纪律**：`get_tail_entity(loader, "requires", old_method_id)` 返回的 assumption 节点是假设提取的第一来源，文本检索是补充手段，不得颠倒优先级。
