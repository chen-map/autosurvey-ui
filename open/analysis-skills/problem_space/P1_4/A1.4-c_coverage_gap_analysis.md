# Skill: A1.4-c 覆盖率缺口分析

**层级**：P1.4 后果影响层 · Consequences & Impacts  
**RQ类型**：带来什么后果？（领域级风险）  
**元认知逻辑**：构建「现实高危场景集」与「研究覆盖集」的映射矩阵，通过计算覆盖率识别「高危害但低研究覆盖」的风险盲区，量化领域的防御缺口。  
**认知基准面**：以「场景-覆盖布尔矩阵」为透镜——覆盖的判定标准是「论文在该场景下有实验」而非「论文讨论了该场景」，这一区分决定了覆盖率统计是否真实反映研究防御能力；风险优先级由 A1.4-a 的影响评级交叉验证，而非由 AI 主观判断。

---

## Goal

系统性地枚举现实世界中的高危应用场景，与 KG/文献的研究覆盖范围进行对比，计算覆盖率，定位「已知高危但研究严重不足」的领域，为 Problem Space 的危害评估提供全局视角。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点，含 `application_context` / `deployment_scenario` 属性
- `knowledge_graph/nodes/scenario_nodes.json`（若有）— 应用场景节点
- `paper_cards/parsed/` — Paper Cards，提取 Background / Motivation 的「高危场景描述」
- `analyze_report/design_report.md` — RQ 定义，确认应用领域范围

---

## Execution Steps

### Step 1: 从 KG problem 节点中提取应用场景集

**认知目标**：应用场景集的构建必须从 KG 结构出发，而非凭常识枚举——`get_entity_by_type(loader, "problem")` 获取的 problem 节点的 `description` 字段中往往含有应用域关键词（如 "medical", "financial", "autonomous", "code generation"），按这些关键词聚类就是从研究文献中归纳出的「研究社区认可的高危场景集」。

```python
all_problems = get_entity_by_type(loader, "problem")

# 按应用领域关键词聚类 problem 节点，构建场景集
domain_keywords = ["medical", "healthcare", "financial", "autonomous driving",
                   "code generation", "critical infrastructure", "legal", "education"]

scenario_clusters = {}
for keyword in domain_keywords:
    domain_problems = get_entity_by_constraint(
        all_problems, "description", "contains", keyword
    )
    if len(domain_problems) > 0:
        scenario_clusters[keyword] = domain_problems
```

同时从 Paper Cards 的 Background / Introduction / Motivation 章节补充场景描述——这些章节中被明确提及的高危场景代表了研究社区的共识认知：

```python
high_risk_scenario_hits = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="high-risk application scenario critical deployment",
    topk=10
)
```

**高危场景清单必须来源于综述文献的背景介绍或挑战章节，禁止凭常识自行构造。**

对每个场景，评估其危害潜力标注必须引用文献中对该场景风险的明确描述（如「FDA 已将 X 列为高风险医疗器械场景」），不得由 LLM 主观评级。

### Step 2: 构建研究覆盖映射

**认知目标**：「有论文在该场景下做实验」与「有论文讨论了该场景」是根本不同的——前者意味着该场景的风险已被实验量化，后者只意味着研究社区意识到了该场景。覆盖率只统计前者。

对每个高危应用场景，使用 `get_head_entity` 检索 KG 中是否存在 addresses 该场景对应 problem 节点的方法：

```python
for scenario_keyword, scenario_problems in scenario_clusters.items():
    for problem in scenario_problems:
        problem_id = problem["node_id"]
        # 找到 addresses 该 problem 的所有方法——代表有研究尝试解决该场景的问题
        covering_methods = get_head_entity(loader, "addresses", problem_id)
        coverage = len(covering_methods)
```

覆盖状态判定标准（基于 addressing 方法数量及其论文的实验记录）：
- **已覆盖（Covered）**：≥ 2 个不同 `context_paper_id` 的方法 addresses 该 problem，且对应论文有该场景下的实验
- **部分覆盖（Partial）**：仅 1 个方法 addresses，或 addressing 方法的论文仅有理论分析无实验
- **未覆盖（Uncovered）**：`get_head_entity` 返回为空（coverage = 0）

若某场景对应 problem 节点的 `origin_paper_id` 为 null，调用 `get_evidence_papers(loader, problem_id)` 确认该场景是否有真实的文献依据。

### Step 3: 构建覆盖率矩阵

建立「高危场景 × 覆盖状态」矩阵，计算：
```
overall_coverage_rate = covered_scenarios / total_scenarios
high_risk_coverage_rate = covered_high_risk_scenarios / total_high_risk_scenarios
```

矩阵单元格包含：`coverage_status`、`covering_methods_count`、`covering_paper_ids`。

### Step 4: 识别「高危害低覆盖」优先关注盲区

**认知目标**：「高危害」的判定必须引用 A1.4-a 的影响评级结果，而非重新评级——跨 skill 的一致性是整个分析框架可信度的基础。若 A1.4-a 未执行，则此处的风险评级必须标注为独立评估并声明与 A1.4-a 不一致的可能性。

筛选条件：危害潜力 = High（来自 A1.4-a 影响评级或文献明确定级）**且** 覆盖状态 = Uncovered 或 Partial。

```python
# 与 A1.4-a 的影响评级交叉验证
if a1_4a_report_exists:
    high_harm_problem_ids = [
        p_id for p_id, impacts in a1_4a_report["problem_impact_matrix"].items()
        if any(v["severity"] == "High" for v in impacts.values())
    ]
    priority_blind_spots = [
        s for s in scenario_clusters_flat
        if s["problem_id"] in high_harm_problem_ids
        and s["coverage_status"] in ["uncovered", "partial"]
    ]
```

### Step 5: 分析盲区成因

**认知目标**：盲区成因分析的价值在于为研究社区提供「为什么此方向难以推进」的诊断，从而区分「值得努力突破的盲区」（技术壁垒可克服）和「需要外部条件改变的盲区」（数据监管限制）。每个成因必须有文献支撑，不得仅凭逻辑推测。

```python
for blind_spot in priority_blind_spots:
    # 搜索该场景研究困难的文献证据
    barrier_evidence = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"{blind_spot['scenario_name']} challenge difficulty data unavailable",
        topk=5
    )
    future_work_callout = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"{blind_spot['scenario_name']} future work open problem",
        topk=3
    )
```

成因分类：
- **数据不可得**：该场景数据受隐私/监管限制（需引用文献中对此的说明）
- **技术壁垒**：该场景的评估方法尚未建立（需引用文献的 Future Work 段落）
- **认知盲区**：该场景的危害尚未被研究社区充分认识（近 2 年内无相关论文，需说明无文献讨论的证据）

### Step 5a: 对抗性验证优先关注盲区的完整性

**认知目标**：在输出优先盲区列表之前，检验是否因 KG 覆盖不完整而遗漏了某些场景的已有研究——`addresses` 边为空不一定意味着无研究，也可能意味着 KG 收录不完整。

```python
for blind_spot in priority_blind_spots:
    # 直接检索文献，跨越 KG 覆盖局限
    direct_literature_check = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"{blind_spot['scenario_name']} experiment evaluation dataset",
        topk=5
    )
    if direct_literature_check and max(s["score"] for s in direct_literature_check) > 0.7:
        # 可能存在 KG 未收录的覆盖研究，将覆盖状态调整为 partial 并标注
        blind_spot["kg_coverage_caveat"] = "KG_may_be_incomplete"
        blind_spot["literature_evidence"] = direct_literature_check[0]
```

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **高危场景清单必须来自文献**，仅接受综述文献 Background 或挑战章节中明确列举的场景，或从 KG problem 节点 `description` 字段聚类得出，禁止 LLM 自行生成危险场景清单。
- 覆盖状态的判断依据：「论文在该场景下有实验」，而非「论文讨论了该场景」，两者有本质区别，必须严格区分。
- `risk_level` 的判断优先引用 A1.4-a 的影响评级，其次引用文献中对该场景危害的明确描述，不得由 LLM 主观评级。
- 盲区成因分析必须有文献支撑（如某论文的 Future Work 提到了该场景研究的困难），不得仅凭逻辑推测。
- 若枚举到的场景少于 5 个，必须在报告中声明「场景清单可能不完整」，建议用户补充。
- **认知坐标纪律**：`get_head_entity(loader, "addresses", problem_id)` 返回为空是「未覆盖」的 KG 层面判定，必须通过 Step 5a 的文献直接检索进行对抗验证，防止 KG 收录不完整导致的假性覆盖盲区。
