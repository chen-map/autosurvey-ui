# Skill: A1.4-a 多维权衡与边界分析

**层级**：P1.4 后果影响层 · Consequences & Impacts  
**RQ类型**：带来什么后果？（系统级影响）  
**元认知逻辑**：提取多个影响维度，对每个维度分析问题的损害类型与严重程度，通过多维热力图揭示问题后果的全貌，避免单一维度分析的认知偏差。  
**认知基准面**：以「多维影响空间构建」为透镜——拒绝单一维度的危害分析；每个 Problem 节点的影响必须在可靠性/安全性/隐私/效率/合规等多个维度上同时投影，并识别「影响放大器」（高连通度 problem 节点会通过链式效应放大跨维度影响）。

---

## Goal

对 KG Problem Space 中的问题节点，系统性地分析其在多个影响维度上的后果，量化损害程度（或定性分级），识别「高危害低关注」的影响盲区，并发现跨维度影响放大器节点。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点，含 `impact` / `consequence` 属性
- `knowledge_graph/edges/` — `addresses` / `leads_to` / `impacts` 类型边，指向影响节点
- `knowledge_graph/nodes/impact_nodes.json`（若有）— 独立的影响/后果节点
- `paper_cards/parsed/` — Paper Cards，提取 Impact Analysis / Consequence 章节
- `analyze_report/design_report.md` — RQ 定义

---

## Execution Steps

### Step 1: 定义影响维度框架

**认知目标**：影响维度框架不能是 AI 凭直觉构造的——它必须从 KG 的 metric 节点中反向推导，因为 metric 节点记录了研究社区实际测量的属性，代表了领域对「什么值得评估」的共识。

从 KG 中提取所有 metric 类型节点，将其映射到影响类别：

```python
all_metrics = get_entity_by_type(loader, "metric")
# metric 节点的 label 和 description 字段揭示该领域的评估维度
# 例如：accuracy/F1/precision → 模型性能维度
#       attack_success_rate/bypass_rate → 安全性维度
#       inference_time/throughput → 效率维度
#       privacy_leakage/membership_inference → 隐私维度
```

依据 metric 节点的分布，确定影响维度集合（4~6 个维度），优先使用文献中被多篇论文采用的维度。维度定义必须来源于文献中的影响分类框架（如 CIA Triad、CVSS 框架等），在 `source_framework` 字段中注明。

### Step 2: 提取每个 Problem 节点在各维度上的损害描述

**认知目标**：损害程度的评级不能由 AI 主观赋值——必须锚定到文献中的定量数据或原文定级。`get_entity_by_constraint` 的作用是系统性地覆盖所有 problem 节点，而非手动挑选「重要的」节点（手动挑选会引入选择偏差）。

```python
all_problems = get_entity_by_type(loader, "problem")

# 对每个影响维度，统计与该维度相关的 problem 节点数量
for dimension_keyword in ["reliability", "security", "privacy", "efficiency", "compliance"]:
    dimension_problems = get_entity_by_constraint(
        all_problems, "description", "contains", dimension_keyword
    )
    # 同时检索英文和中文关键词变体
```

对每个 Problem 节点，从对应 Paper Cards 提取：
- 损害类型（定性描述，来自 Impact/Consequence/Evaluation 章节）
- 损害程度：优先使用定量数据（如「性能下降 X%」）；若无定量数据则标注 `severity: estimated_qualitative`

使用定量数据时，精确引用格式：「模型准确率下降 15.3%，引自 [paper_id] Table 3」。

```python
# 检索每个 problem 的量化危害证据
harm_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="attack success rate damage impact severity",
    paper_ids=[problem_source_paper_ids],
    topk=5
)
```

若某 Problem 节点在某维度无任何文献讨论，标注 `severity: Unknown`，不得默认为 Low。

### Step 3: 构建影响热力矩阵

构建「Problem 类型 × 影响维度」热力矩阵，单元格值为损害程度（0=无影响，1=Low，2=Medium，3=High，-1=Unknown）。

矩阵填充规则：
- High (3)：有定量数据支撑，或原文明确定级为「严重」/「critical」
- Medium (2)：有定性论证但无定量数据，或原文定级为「中等」
- Low (1)：仅有间接提及，影响程度轻微
- Unknown (-1)：该维度无任何文献讨论

### Step 4: 识别高危区域、影响盲区与影响放大器

**认知目标**：「影响放大器」是 P1.4 层的关键洞察——某些 problem 节点因为被多个其他 problem 节点通过 `addresses` 链反向连接，形成高连通度节点，意味着解决/忽视它会产生连锁效应。识别这些节点对于研究优先级排序至关重要。

**高危区域**（多个 Problem 在同一维度均为 High）：

```python
high_severity_by_dimension = {}
for dimension in impact_dimensions:
    high_problems = [p for p in problem_impact_matrix
                     if problem_impact_matrix[p][dimension]["severity"] == "High"]
    if len(high_problems) >= 2:
        high_severity_by_dimension[dimension] = high_problems
```

**影响盲区**（某影响维度在现有研究中几乎无定量评估）：
- 判定标准：该维度下所有 problem 的 severity 均为 Unknown 或 estimated_qualitative
- 需有至少一篇文献的 Limitation 或 Future Work 章节表达对该维度研究不足的呼吁

**影响放大器检测**（高连通度 problem 节点）：

```python
# 找到被 ≥3 个其他 problem 节点通过 addresses 反向链连接的节点
for problem_id in all_problem_ids:
    # 找到 addresses 该 problem 的所有方法，再找这些方法 addresses 的其他 problem
    addressing_methods = get_head_entity(loader, "addresses", problem_id)
    # 高连通度节点是影响放大器：解决它会间接影响多个其他 problem
    if len(addressing_methods) >= 3:
        amplifier_candidates.append(problem_id)

# 验证：同时检查 leads_to 边，看该 problem 是否直接导致其他 problem
leads_to_edges = get_relation(loader, problem_id, "out")
downstream_problems = [e for e in leads_to_edges if e["edge_type"] == "leads_to"]
```

影响放大器 = 同时满足：被 ≥3 个方法 addresses + 有 ≥1 条 leads_to 出边

### Step 4a: 对抗性验证影响评级的完整性

**认知目标**：在输出热力矩阵之前，检验是否存在系统性遗漏——特别是高影响但低研究关注的维度。

```python
# 对每个标注为 Unknown 的维度，验证是否真的无文献讨论
for unknown_cell in unknown_severity_cells:
    verification_search = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"{unknown_cell['problem_description']} {unknown_cell['dimension']} impact",
        topk=3
    )
    if verification_search and max(s["score"] for s in verification_search) > 0.6:
        # 降级为 estimated_qualitative 而非 Unknown
        unknown_cell["severity"] = "estimated_qualitative"
        unknown_cell["downgrade_evidence"] = verification_search[0]
```

### Step 5: 输出报告

汇总热力矩阵、高危区域、影响盲区和放大器节点，构建完整报告。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **严重程度评级必须基于文献中的原始数据或原文定级**，若文献仅有定性描述（如「significant impact」），必须标注 `severity: estimated_qualitative`，不得直接标注 High/Medium/Low 为客观事实。
- 若某 Problem 节点在某维度无任何文献讨论，标注 `severity: Unknown`，不得默认为 Low。
- 影响维度框架来源必须在 `source_framework` 字段注明（如 `CIA Triad`、`CVSS v3.1`），优先从 KG metric 节点归纳得出，不得凭空构造维度体系。
- 盲区识别结论（「该维度损害被低估」）必须有至少一篇文献的 Limitation 或 Future Work 章节表达对该维度研究不足的呼吁。
- 定量数据必须精确引用（如「模型准确率下降 15.3%，引自 [paper_id] Table 3」），不得笼统表述。
- **认知坐标纪律**：影响放大器检测必须基于 `get_head_entity` 和 `get_relation` 的实际连通度统计，不得凭 LLM 判断哪些 problem「看起来很关键」。
