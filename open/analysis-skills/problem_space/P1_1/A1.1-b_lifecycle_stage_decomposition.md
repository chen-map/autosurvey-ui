# Skill: A1.1-b 生命周期阶段拆解

**层级**：P1.1 实体识别层 · Phenomenon & Inventory  
**RQ类型**：有什么？（分布统计 / 属性刻画）  
**元认知逻辑**：定义研究对象从生到死的完整生命周期模型，将问题实体归类到各阶段，揭示阶段间分布失衡与研究重心偏移。  
**认知基准面**：将研究对象视为一条有序的流程管道，每个问题都是管道某一节点的故障模式，分析任务是绘制这条管道的"故障热力图"，而非孤立地列举故障。

---

## Goal

为研究对象构建完整的生命周期模型，将 KG Problem Space 中的问题/威胁/现象实体归入对应阶段，量化各阶段的研究密度，定位被过度关注和被忽视的阶段。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG 中所有 Problem 类型节点，需含 `stage` 或 `phase` 属性
- `knowledge_graph/edges/` — 论文与 Problem 节点的关联边
- `analyze_report/design_report.md` — RQ 定义，确认研究对象的领域（如 LLM 训练流程、软件供应链、AI Agent 执行流程等）
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）

---

## Execution Steps

### Step 1: 从 KG 证据归纳生命周期模型

**为什么**：生命周期模型若凭先验假设构造，会导致后续归类时出现大量"不符合任何阶段"的节点，说明模型与实际研究语境不匹配。必须先从文献实际描述的阶段词汇中归纳模型。

首先，用 `search_paper_sections` 扫描文献中对流程/阶段的描述：

```python
# 搜索论文中明确描述生命周期阶段的文本
stage_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="pipeline stage phase workflow lifecycle process",
    paper_ids=all_paper_ids,
    topk=20
)
# 从命中片段中提取阶段词汇（如 "training", "fine-tuning", "deployment", "inference", "data collection"）
```

同时从 KG Problem 节点的 `stage`/`phase` 字段统计词频：

```python
stage_vocab = {}
for p in get_entity_by_type(loader, "Problem"):
    if p.attributes.get("stage"):
        stage_vocab[p.attributes["stage"]] = stage_vocab.get(p.attributes["stage"], 0) + 1
```

将文献词汇和 KG 字段词汇合并，按词频排序，归纳出 4~8 个阶段候选。用 `judge` 判断阶段间的顺序关系（哪个阶段在前、哪个在后），构建有序阶段序列。

决策逻辑：
- 若文献中存在被 ≥3 篇论文引用的标准流程定义 → 直接采用，`source: standard_reference`
- 若无统一标准 → 从上述归纳结果合成，`source: synthesized_from_literature`，并在 `lifecycle_model.synthesis_papers` 中列出支撑论文

**禁止自创脱离文献语境的生命周期，阶段名称必须能在输入文献集中找到对应描述。**

### Step 2: 将 Problem 节点映射到阶段

**为什么**：精确的阶段归类是密度统计准确性的前提。`description` 字段通常比结构化字段更丰富，应作为首选语义来源。

遍历所有 Problem 节点，按以下优先级确定阶段归属：

```python
for p in get_entity_by_type(loader, "Problem"):
    # 优先级1：直接读取 KG stage/phase 字段
    stage = p.attributes.get("stage") or p.attributes.get("phase")
    
    # 优先级2：字段缺失时读取 description 字段（主语义内容）
    if stage is None:
        stage = judge(
            f"Given this problem description: '{p.description}', "
            f"which lifecycle stage does this problem primarily occur in? "
            f"Choose from: {stage_list}. "
            f"If the problem spans multiple stages, identify the root-cause stage."
        )
        p.attributes["stage_source"] = "inferred_from_description"
    
    # 优先级3：description 仍不明确时，调用 get_evidence_papers 补充上下文
    if stage is None:
        source_papers = get_evidence_papers(loader, p.id)
        for sp in source_papers:
            stage_context = search_paper_sections(
                query=p.description[:100],
                paper_ids=[sp.id],
                topk=1
            )
            # 从命中章节名称推断阶段（如章节标题含 "Training Attack" 则归入 training 阶段）
```

跨阶段问题：归入「首发阶段」（根因所在阶段），其余受影响阶段记录在 `cross_stage` 字段。

### Step 3: 统计各阶段密度

```
stage_density[s] = count(problems in stage s)
paper_density[s] = count(papers addressing problems in stage s)
```

计算各阶段的问题数与论文数，构建对比视图：
- 问题多且论文多 → `over_studied`（研究饱和区）
- 问题多但论文少 → `under_studied`（研究滞后区，重点分析）
- 问题少但论文多 → `over_represented`（可能存在问题定义过细）
- 问题少且论文少 → `sparse`（可能是新兴阶段或认知盲区）

### Step 4: 分析阶段间传播路径

**为什么**：单阶段的问题密度统计忽略了问题的因果传播效应。某些阶段虽然论文少，但却是多条传播链的起点，其战略重要性被低估。

使用 `get_relation` 提取跨阶段传播边：

```python
propagation_chains = []
for p in all_problems:
    # 获取该问题触发的下游问题
    downstream = get_tail_entity(loader, "propagates_to", p.id)
    if not downstream:
        downstream = get_tail_entity(loader, "triggers", p.id)
    
    for d in downstream:
        if d.stage != p.stage:  # 跨阶段才记录
            propagation_chains.append({
                "from_stage": p.stage,
                "to_stage": d.stage,
                "trigger_problem": p.id,
                "caused_problem": d.id
            })
```

构建阶段间传播有向图，计算每个阶段的出度（传播能力）和入度（被污染程度），识别「高传播源点阶段」。

### Step 5: 对抗性验证：检验生命周期模型的完整性

**为什么**：任何生命周期模型都有可能遗漏新兴阶段（如 LLM 的 RLHF 阶段在早期文献中不存在），必须主动检验。

执行以下反例检查：
1. 计算归类失败率：`unclassified_count / total_problems`，若 > 10%，说明生命周期模型存在覆盖漏洞
2. 对未归类节点，用 `judge` 分析其 `description`，检查是否代表一个尚未命名的新阶段
3. 用 `search_paper_sections` 搜索近 2 年论文中是否出现了当前阶段模型未包含的新流程词汇：

```python
new_stage_hints = search_paper_sections(
    query="new phase emerging stage novel step pipeline",
    paper_ids=[p.id for p in papers if p.year >= max_year - 2],
    topk=10
)
```

若发现证据确凿的新阶段（≥2 篇近期论文支撑），将其加入生命周期模型并标注 `status: emerging`。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **生命周期模型必须来自文献**，不得凭空创造，必须在 JSON 的 `source` 字段注明依据；`synthesized_from_literature` 时必须列出至少 3 篇支撑论文。
- 阶段归类冲突时，优先遵循 KG 节点的 `stage` 字段值；若字段缺失，读取 `description` 字段由 LLM 判断，标注 `stage_source: inferred_from_description`；再缺失则调用 `get_evidence_papers` 补充上下文。
- 若某阶段的论文数为 0，必须在 summary 中分析原因（技术壁垒 / 数据不可得 / 认知盲区），并引用文献集中有讨论该阶段挑战的论文作佐证。
- 跨阶段传播链必须有具体论文的 Security Analysis 或 Threat Model 章节支撑，不得主观推断。
- **认知基准面纪律**：生命周期模型（即流程管道的形状）必须在 Step 1 完成后固化，后续步骤不得修改阶段定义；若 Step 5 发现新阶段，须记录在 `emerging` 状态并说明其对已有分布结论的影响，不得悄然改变已完成的归类结果。
