# Skill: A1.1-d 问题形态的时间漂移分析

**层级**：P1.1 实体识别层 · Phenomenon & Inventory  
**RQ类型**：有什么？（动态演化 · 自然漂移）  
**元认知逻辑**：引入时间轴，分析早期与近期文献中问题定义的偏移或升级，提炼随时间发生的形态变异与演化拐点。  
**认知基准面**：将问题空间视为一个随时间漂移的语义场，同一问题标签在不同年代指向不同的技术实质——分析任务是测量这种语义场的漂移速度和方向，而非简单统计问题数量的增减。

---

## Goal

基于 KG Problem 节点的时间戳与对应论文的发表年份，追踪问题实体（威胁手法、故障模式、挑战形态）在时间序列上的演化轨迹，识别形态发生质变的拐点年份。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG Problem 节点，需含 `first_reported_year` 或可通过关联论文推断年份
- `knowledge_graph/edges/` — `evolves_from` / `variant_of` / `supersedes` 类型边
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `analyze_report/design_report.md` — RQ 定义，确认分析的时间跨度

---

## Execution Steps

### Step 1: 构建时间序列，按年份分组 Problem 节点

**为什么**：`first_reported_year` 字段常常缺失，必须通过关联论文的发表年份反推。同时，年份分组的粒度影响拐点检测的灵敏度，需根据时间跨度动态调整。

```python
# 从 papers.json 建立 paper_id → year 映射
paper_year_map = {p.id: p.year for p in get_entity_by_type(loader, "Paper")}

# 对每个 Problem 节点推断首次报告年份
for p in get_entity_by_type(loader, "Problem"):
    if p.attributes.get("first_reported_year"):
        year = p.attributes["first_reported_year"]
        year_source = "kg_field"
    else:
        # 通过 addresses 边反推：找到所有 address 该问题的论文，取最早年份
        source_papers = get_evidence_papers(loader, p.id)
        if source_papers:
            year = min(paper_year_map.get(sp.id, 9999) for sp in source_papers)
            year_source = "inferred_from_papers"
        else:
            year = None
            year_source = "unknown"
    
    p.attributes["derived_year"] = year
    p.attributes["year_source"] = year_source
```

年份分组粒度：
- 时间跨度 ≤ 5 年 → 步长 1 年
- 时间跨度 6~10 年 → 步长 1 年，但拐点检测窗口为 2 年
- 时间跨度 > 10 年 → 步长 2 年

无法确定年份的节点标注 `year: unknown`，不参与时序统计，但在报告末尾单独列出。

### Step 2: 按时间段提取问题描述，测量语义漂移

**为什么**：单纯统计每年新增问题数量只能反映"量"的变化，而无法捕捉"质"的漂移。同一问题类别（如"数据投毒"）在早期和近期论文中的描述方式往往存在实质性差异，这种语义漂移才是拐点的真正信号。

对每个时间段，用 `get_entity_by_constraint` 过滤该时间段内的问题节点：

```python
for year_start, year_end in year_buckets:
    # 获取该时间段内的 Problem 节点（基于 derived_year）
    period_problems = [p for p in all_problems
                       if year_start <= (p.attributes.get("derived_year") or 0) <= year_end]
    
    period_paper_ids = []
    for p in period_problems:
        source_papers = get_evidence_papers(loader, p.id)
        period_paper_ids.extend([sp.id for sp in source_papers
                                  if paper_year_map.get(sp.id, 0) in range(year_start, year_end+1)])
    
    # 从该时间段论文中提取问题描述片段
    desc_snippets = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query="problem challenge threat attack vulnerability",
        paper_ids=list(set(period_paper_ids)),
        topk=10
    )
    
    # 提取关键术语：从 desc_snippets 的 paragraph_snippet 中提取高频名词短语
    # 形成该时间段的「语义画像」：key_terms = [term1, term2, ...]
```

计算相邻时间段语义画像的重叠度（Jaccard 相似度）：
- 重叠度高（> 0.6）→ 语义稳定期
- 重叠度低（< 0.3）→ 语义漂移期，标记为拐点候选

### Step 3: 检测演化拐点，分析语义质变

**为什么**：拐点检测不能只看数量突变，还要看描述方式的质变。一个真正的拐点意味着研究社区开始用不同的概念框架来理解同一类问题。

对语义漂移期（Step 2 中重叠度 < 0.3 的相邻时间段对），执行以下拐点验证：

```python
for inflection_candidate in candidates:
    year_before = inflection_candidate.year - 1
    year_after  = inflection_candidate.year + 1
    
    # 获取拐点前后各一年的代表性论文
    papers_before = [p for p in all_papers if p.year == year_before]
    papers_after  = [p for p in all_papers if p.year == year_after]
    
    # 从拐点前论文中提取问题描述的核心术语
    before_snippets = search_paper_sections(
        query="problem definition challenge threat",
        paper_ids=[p.id for p in papers_before],
        topk=5
    )
    
    # 从拐点后论文中提取同类问题的描述
    after_snippets = search_paper_sections(
        query="problem definition challenge threat",
        paper_ids=[p.id for p in papers_after],
        topk=5
    )
    
    # 语义对比：提取 before 和 after 的 key_terms，计算差集
    new_terms = set(after_key_terms) - set(before_key_terms)    # 新出现的概念
    dropped_terms = set(before_key_terms) - set(after_key_terms)  # 消失的概念
    
    # 用 judge 分析质变原因
    change_analysis = judge(
        f"Before {inflection_candidate.year}: key terms = {before_key_terms}\n"
        f"After {inflection_candidate.year}: key terms = {after_key_terms}\n"
        f"New terms: {new_terms}, Dropped terms: {dropped_terms}\n"
        f"Based on these paper snippets, what fundamental change in the problem's nature occurred? "
        f"Was it driven by: new_technology / new_attack_capability / regulatory_change / paradigm_shift?"
    )
```

**每个确认的拐点必须附带：拐点前代表性论文 ID + 拐点后代表性论文 ID + 语义差集（新增和消失的关键术语）。**

### Step 4: 识别 KG 中的演化边，验证时序结论

**为什么**：KG 中的 `evolves_from` / `variant_of` / `supersedes` 边是问题演化关系的直接编码，应与时序分析的统计结论相互验证，两者不一致处需要特别审查。

```python
evolution_edges = []
for p in all_problems:
    ancestors = get_head_entity(loader, "evolves_from", p.id)
    variants   = get_head_entity(loader, "variant_of", p.id)
    superseded = get_tail_entity(loader, "supersedes", p.id)
    
    for a in ancestors:
        evolution_edges.append({
            "ancestor": a.id,
            "descendant": p.id,
            "relation": "evolves_from",
            "year_gap": p.attributes.get("derived_year", 0) - a.attributes.get("derived_year", 0)
        })
```

交叉验证：
- 若 KG 演化边显示某问题在年份 Y 演化出变体，而 Step 3 的拐点检测未在年份 Y 附近发现信号 → 说明该演化是局部的、非系统性的
- 若 Step 3 发现拐点但 KG 无对应演化边 → 说明 KG 的演化边可能不完整，需标注 `evolution_edge_missing`

### Step 5: 对抗性验证：检验拐点的替代解释

**为什么**：统计上的「拐点」可能只是论文数量偏差（如某年顶会恰好接受了大量相关论文），而非真正的语义质变。必须排除这种平凡解释。

对每个识别出的拐点，检验以下替代假设：

```python
for inflection in confirmed_inflections:
    # 假设1：该年份是否只是论文数量的统计高峰？
    paper_count_before = count(papers in year inflection.year - 1)
    paper_count_after  = count(papers in year inflection.year + 1)
    if abs(paper_count_after - paper_count_before) / paper_count_before > 0.5:
        inflection.confound_risk = "publication_volume_bias"
    
    # 假设2：语义变化是否只来自少数几篇高影响力论文？
    dominant_papers = [s for s in after_snippets if s.score > 0.8]
    if len(dominant_papers) <= 2:
        inflection.confound_risk = "dominated_by_few_papers"
    
    # 若无上述混淆因素，确认为真实拐点；否则降级为 candidate
    inflection.status = "confirmed" if not inflection.get("confound_risk") else "candidate"
```

仅 `status: confirmed` 的拐点可作为最终结论输出；`status: candidate` 的拐点必须在报告中注明混淆风险。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **拐点年份必须由具体论文支撑**，每个拐点必须引用拐点前后各至少 1 篇论文，并附语义差集（新增术语 / 消失术语），禁止主观臆断演进趋势。
- `first_reported_year` 若无法从 KG 直接获取，必须通过 `get_evidence_papers` + 关联论文年份推断，标注 `year_source: inferred_from_papers`。
- 若某年份无相关文献，该年份标注 `no_coverage`，不得用插值填充。
- LLM 对拐点原因的分析必须基于 `search_paper_sections` 命中的对应论文片段，**禁止引入文献集之外的外部知识作为拐点原因**。
- 演化谱系边必须来自 KG 中已存在的边或 Paper Cards 中明确的 `compared_with` / `extends` 描述，不得凭关键词相似性推断演化关系。
- **认知基准面纪律**：「语义场漂移」视角要求始终以描述内容的变化（关键术语的进出）为核心度量，而非论文数量的增减；整个分析过程中不得将数量统计误认为语义证据，若两者出现矛盾，以语义分析结果为准。
