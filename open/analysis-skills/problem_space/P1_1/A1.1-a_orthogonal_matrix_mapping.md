# Skill: A1.1-a 多维正交矩阵映射

**层级**：P1.1 实体识别层 · Phenomenon & Inventory  
**RQ类型**：有什么？（类型枚举 / 分布统计）  
**元认知逻辑**：提取 2~3 个正交属性作为坐标轴，将文献/KG节点映射到象限，统计密度，识别热点与冷区。  
**认知基准面**：将问题空间视为一个二维坐标系，每个问题实体都是空间中的一个点，分析任务是找到最能揭示点分布规律的两条坐标轴，而非描述点本身的表面特征。

---

## Goal

基于 KG 的 Problem Space 节点，提取两个互不干扰的本质属性维度，构建二维分布矩阵，量化各象限的文献覆盖密度，定位领域热点区与认知冷区，为 RQ 提供结构化的现象清单。

---

## Inputs

- `knowledge_graph/nodes/problems.json` — KG 中所有 Problem 类型节点
- `knowledge_graph/edges/` — 论文与问题实体的关联边（`addresses` 等）
- `analyze_report/design_report.md` — 目标 RQ 定义，明确分析聚焦的问题域
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）

---

## Execution Steps

### Step 1: 加载全量 Problem 节点并扫描语义结构

**为什么**：维度选择必须从数据本身归纳，而非先验假设。扫描 `description` 字段的结构性模式是找到真正正交维度的唯一可靠途径。

加载 KG 中所有 Problem 类型节点：

```python
all_problems = get_entity_by_type(loader, "Problem")
# 对每个节点，读取 description 字段（主语义内容）和结构属性字段
for p in all_problems:
    node = get_entity_by_constraint(loader, "Problem", {"id": p.id})
    # 提取 description 中的关键模式词：攻击目标、发生阶段、危害类型、技术机制
```

若某节点 `origin_paper_id` 为 null，则用 `get_evidence_papers` 补全来源：

```python
if node.origin_paper_id is None:
    source_papers = get_evidence_papers(loader, node.id)
    # 从 source_papers 的 description/abstract 中补充语义信息
```

从 `description` 字段扫描时，重点寻找以下结构性模式：
- 问题的**发生位置**（in training / at inference / during deployment / in API layer）
- 问题的**影响性质**（confidentiality / integrity / availability / fairness）
- 问题的**触发条件**（requires model access / data access / API access only）
- 问题的**受害主体**（model provider / end user / third-party system）

提出 3 组候选维度对（A₁×B₁, A₂×B₂, A₃×B₃），进入 Step 2 验证正交性。

### Step 2: 验证维度正交性，选定坐标轴

**为什么**：两个维度若存在因果或包含关系，则矩阵会退化为对角线分布，失去分类意义。正交性验证排除"一个维度预测另一个维度"的情形。

对每组候选维度对 (A, B)，从全量 Problem 节点计算联合分布：

```python
# 对每个 problem 节点，记录其 (A_value, B_value) 组合
joint_dist = {}
for p in all_problems:
    a_val = p.attributes.get("dim_A_field") or infer_from_description(p.description, dim_A)
    b_val = p.attributes.get("dim_B_field") or infer_from_description(p.description, dim_B)
    joint_dist[(a_val, b_val)] = joint_dist.get((a_val, b_val), 0) + 1

# 检验：若某个 A_i 值高度预测某个特定 B_j 值（条件分布集中度 > 0.7），则维度不正交
# 计算 Jaccard 相似度：|overlap| / |A_papers ∪ B_papers|，要求 < 0.3
```

决策逻辑：
- 若 Jaccard < 0.3 且联合分布中无单格占比 > 50%：维度正交，可用
- 若 Jaccard ≥ 0.3：该维度对被拒绝，换下一候选对
- 若三组候选均不合格：退化为单维度分布分析，在报告中注明 `dimensionality: 1D`

选定维度 A 和 B，标签集各 ≤ 6 个，标签必须来自 KG 节点字段值或 Paper Cards 原文，**禁止 AI 自创标签**。

### Step 3: 映射 Problem 节点到矩阵象限

**为什么**：每个 Problem 节点必须有唯一的象限归属，才能使密度统计有意义。跨象限问题若不处理会导致总数膨胀失真。

遍历全量 Problem 节点，读取 `description` 字段和结构属性，将每个节点投影到 (A_i, B_j) 象限：

```python
for p in all_problems:
    # 优先读 KG 字段，字段缺失时读 description 推断
    a_val = p.attributes.get(dim_A_field)
    if a_val is None:
        a_val = judge(
            f"Given this problem description: '{p.description}', "
            f"classify it into one of {dim_A_labels} based on {dim_A_name}."
        )
        p.attributes["dim_A_inferred"] = True
    
    b_val = p.attributes.get(dim_B_field)
    if b_val is None:
        b_val = judge(...)
        p.attributes["dim_B_inferred"] = True
    
    # 若跨多象限：归入主象限，notes 标注 multi-quadrant
    matrix[(a_val, b_val)].append(p.id)
```

通过 `get_relation(loader, paper_id, "addresses")` 获取每篇论文关联的 Problem 节点集合，将论文计数映射到象限。若 `origin_paper_id` 为 null，调用 `get_evidence_papers(loader, problem_id)` 补全。

### Step 4: 统计密度，识别热点与冷区，分析冷区成因

**为什么**：冷区的成因分析才是核心洞察。"技术壁垒"和"认知盲区"对应完全不同的研究机会，必须区分。

```
matrix_density[A_i][B_j] = count(papers in quadrant (A_i, B_j))
hot_zone  = 密度前 20% 的象限
cold_zone = 密度为 0 或后 20% 的象限
```

对每个冷区象限，执行以下因果判断流程：

```python
for cold_quadrant in cold_zones:
    # 步骤1：在 Future Work 中搜索该象限的关键词
    future_work_hits = search_paper_sections(
        paper_cards_root="paper_cards/parsed",
        query=f"{cold_quadrant.A_label} {cold_quadrant.B_label} future challenge",
        paper_ids=all_paper_ids,
        topk=5
    )
    
    if future_work_hits:
        # 论文主动提及但未解决 → awareness_gap（研究者知道但没做）
        cold_quadrant.cause = "awareness_gap"
        cold_quadrant.evidence = future_work_hits[0]
    else:
        # 搜索是否有论文解释该方向的技术困难
        barrier_hits = search_paper_sections(
            query=f"{cold_quadrant.A_label} {cold_quadrant.B_label} difficult infeasible limitation",
            paper_ids=all_paper_ids,
            topk=5
        )
        cold_quadrant.cause = "technical_barrier" if barrier_hits else "unknown_blind_spot"
        cold_quadrant.evidence = barrier_hits[0] if barrier_hits else None
```

### Step 5: 对抗性验证：检验维度选择的稳健性

**为什么**：任何二维矩阵都是对高维现实的压缩，必须主动检验是否遗漏了关键的第三维度，避免结论被维度选择偏见所误导。

执行以下反例检查：
1. 从 cold_zones 中随机抽取 3 个 Problem 节点，检查其 `description` 是否揭示了当前两个维度无法捕捉的重要特征
2. 查询 `get_entity_by_constraint(loader, "Problem", {"type": "boundary_case"})` 找到跨象限节点，检查是否系统性地集中在某些象限边界上（若是，说明维度切割位置不当）
3. 用 `judge` 评估：「当前矩阵是否遗漏了一个重要的第三维度？若存在，该维度是什么，影响多少个 Problem 节点？」

若发现严重的维度遗漏（影响 > 15% 节点），在报告中记录为 `dimension_limitation`，并建议后续分析用 A1.1-c（分层堆栈）补充。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **必须列出每个象限的具体论文引用标号**，禁止凭空捏造分类结果。
- 正交属性维度必须来自文献原文或 KG 节点字段，不可由 AI 主观创造维度。
- 若某论文的属性值在 KG 中缺失，必须标记为 `attribute_missing`，不得推断填充（description 推断的必须标注 `inferred_from_description`）。
- 冷区识别结论必须附带成因分类（`technical_barrier` 或 `awareness_gap`），分类依据必须是 `search_paper_sections` 的检索结果，不得主观判断。
- 维度标签数量超过 6 个时，必须先进行聚类合并，再构建矩阵，防止矩阵稀疏失效。
- **认知基准面纪律**：分析开始前必须明确陈述选定的二维坐标系视角，并在整个分析过程中保持该视角不漂移；若中途发现更优维度对，须完整重跑 Step 2-4，不得在同一报告中混用不同维度框架。
