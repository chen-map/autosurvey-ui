# Skill: B2.3-c 基线对比公平性分析

**层级**：S2.3 验证度量层 · Evaluation Metrics & Benchmarks  
**RQ类型**：效果好不好？（基线对比）  
**元认知逻辑**：审查论文实验中基线是否代表真正的 SOTA、超参数是否经过充分调优、硬件条件是否一致，识别「不公平对比」导致的虚假性能优势，评估各论文性能声明的实际可信度。  
**认知基准面**：基线选择不是中性的技术决策——选择弱基线、旧基线或未充分调优的基线，每一种都会系统性地放大被评估方法的相对优势；识别这些选择偏差需要从 KG 的 `compares_with` 和 `extends` 边结构中读取客观关系，而不只是相信论文的自我声明。

---

## Goal

对 Solution Space 中每篇论文的对比实验设计进行公平性审查，识别那些通过选择弱基线、不调优基线超参、或在不公平硬件条件下获得的虚假性能优势，输出可信度校正后的方法排名，并揭示「自我服务比较」的结构性模式。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点
- `paper_cards/parsed/` — Paper Cards，提取 Experimental Setup / Baseline 章节
- `knowledge_graph/nodes/papers.json` — 论文元数据（year、venue、authors字段）
- `working_memory/rq_{id}/B2.3-a_eval_meta_report.json` — 评估元分析结果（可选）

## Execution Steps

### Step 1: 从 KG `compares_with` 边提取声称的基线比较

**推理目标**：为什么从 `compares_with` 边出发而不是从 Paper Cards 的 Baseline 章节出发？因为 `compares_with` 边是论文对比关系的 KG 编码，是已经经过规范化的比较声明；而 Paper Cards 中的 Baseline 章节可能使用非标准名称引用基线方法，难以与 KG 中的方法节点对齐。两者结合使用，以 KG 边为主，Paper Cards 为补充。

**操作流程**：

```python
for method in all_methods:
    out_edges = get_relation(loader, method["node_id"], "out")
    compares_with_edges = [e for e in out_edges if e["edge_type"] == "compares_with"]
    # compares_with_edges 的 tail 节点 = 该论文声称比较过的基线方法
```

对每条 `compares_with` 边，提取：
- 被比较的基线方法节点（`node_id`, `canonical_name`）
- 该基线方法对应论文的发表年份（通过 `context_paper_id` 查找 `papers.json`）
- `compares_with` 边的 `evidence` 字段（若有，记录了比较描述）

补充搜索 Paper Cards 以捕获 KG 未建模的基线比较：
```python
baseline_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="compared against|we compare with|baseline methods|we use X as baseline|baselines include",
    paper_ids=[method["context_paper_id"]],
    topk=3
)
```

### Step 2: 检测「谱系回归」——与被自己超越的祖先比较

**推理目标**：若方法 B `extends` 方法 A（B 是 A 的改进版），但 B 在比较时选择与 A 对比而不是与 A 的其他后继版本（A → C → D）对比，这是「谱系回归」——一种系统性低估竞争难度的策略。KG 的 `extends` 链能精确识别这种模式。

**操作流程**：

对每条 `compares_with` 边，检查被比较的基线方法是否在当前方法的 `extends` 祖先链上：
```python
def get_ancestors(loader, method_id):
    ancestors = set()
    out_edges = get_relation(loader, method_id, "out")
    extends_edges = [e for e in out_edges if e["edge_type"] == "extends"]
    for edge in extends_edges:
        ancestor_id = edge["tail_node_id"]
        ancestors.add(ancestor_id)
        ancestors.update(get_ancestors(loader, ancestor_id))  # 递归获取所有祖先
    return ancestors

for method in all_methods:
    ancestors = get_ancestors(loader, method["node_id"])
    for baseline in compares_with_baselines[method["node_id"]]:
        if baseline["node_id"] in ancestors:
            # 该方法在与自己的祖先比较——潜在谱系回归
            # 进一步检查：祖先的后继版本（兄弟节点）是否存在且未被比较？
            ancestor_successors = get_head_entity(loader, "extends", baseline["node_id"])
            uncompared_successors = [s for s in ancestor_successors
                                     if s["node_id"] != method["node_id"]
                                     and s["node_id"] not in compares_with_baselines[method["node_id"]]]
            if uncompared_successors:
                flag_as_lineage_regression(method, baseline, uncompared_successors)
```

### Step 3: 检测「自我服务比较」——与被自己否定的方法比较

**推理目标**：若方法 A 有 `contradicts` 边指向方法 B（A 明确否定了 B 的范式），但 A 选择与 B 作为主要基线进行比较，这是「自我服务比较设置」——A 在一个对自己最有利的对手面前展示优势。这是比「旧基线」更隐蔽的偏差，因为它结合了意识形态否定和实验设计选择。

**操作流程**：

```python
for method in all_methods:
    out_edges = get_relation(loader, method["node_id"], "out")
    contradicts_edges = [e for e in out_edges if e["edge_type"] == "contradicts"]
    contradicted_methods = [e["tail_node_id"] for e in contradicts_edges]
    
    # 检查被否定的方法是否同时出现在基线列表中
    for baseline_id in compares_with_baselines[method["node_id"]]:
        if baseline_id in contradicted_methods:
            # 方法 A contradicts 方法 B，但同时将 B 作为基线 → 自我服务比较
            flag_as_self_serving_comparison(method, baseline_id)
```

自我服务比较的严重程度：
- **Severe**：所有主要基线都是被 `contradicts` 的方法，无更新的中立基线
- **Moderate**：部分基线是被 `contradicts` 的方法，但还有中立基线
- **Minor**：被 `contradicts` 的方法只是补充基线之一

### Step 4: 执行公平性三项检验

对每篇论文的基线设置检验三个条件：

**条件 1：时效性检验（基线是否为同期 SOTA？）**

获取被比较方法的发表年份，与当前论文发表年份对比：
```python
method_year = get_paper_year(method["context_paper_id"])
baseline_year = get_paper_year(baseline["context_paper_id"])
staleness_gap = method_year - baseline_year
```

判断标准：
- `staleness_gap > 2`：`outdated`（过时基线，Major 问题）
- `staleness_gap = 1~2`：`slightly_old`（略旧，Minor 问题）
- `staleness_gap ≤ 1`：`up_to_date`（同期，通过）

**特殊处理**：若论文在原文中给出了使用旧基线的合理理由（如「为与 ICSE'2020 评估保持一致」），需记录该理由，不得自动降低置信度。搜索此类理由：
```python
old_baseline_justification = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="for fair comparison|to be consistent with|following prior work|same setting as",
    paper_ids=[method["context_paper_id"]],
    topk=2
)
```

**条件 2：超参调优检验**

```python
hyperparameter_tuning_evidence = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="tuned all baselines|grid search|hyperparameter search|we optimized|we searched",
    paper_ids=[method["context_paper_id"]],
    topk=2
)
```

若论文明确声明对所有基线进行了超参调优，该项通过；否则标注 `hyperparameter_tuned: unspecified`（默认为未充分调优风险）。

**条件 3：硬件条件检验**

只能基于论文中的显式描述判断：若论文未描述硬件信息，标注 `hardware_parity: unclear`，不得推断。若描述显示新方法使用显著更强的硬件，标注 `hardware_parity: unequal`。

### Step 5: 综合公平性判定与可信度校正

综合三项检验结果和 Step 2-3 的结构性偏差分析，给出每篇论文的综合公平性判定：

- **fair**：三项检验均通过，无谱系回归，无自我服务比较
- **minor_issues**：有轻微问题（略旧基线或硬件信息不明），无结构性偏差
- **moderate_issues**：有一项 Major 检验失败，或有中等程度的谱系回归/自我服务比较
- **major_issues**：有多项 Major 检验失败，或有 Severe 的自我服务比较，或与被 `contradicts` 的所有方法进行比较

对每个 `major_issues` 案例，指出应当使用的更合适基线（只能引用文献集中实际存在的方法）：
```python
# 寻找同期（发表年份相近）且与当前方法无 contradicts 关系的候选基线
candidate_baselines = [m for m in all_methods
                       if abs(get_paper_year(m["context_paper_id"]) - method_year) <= 1
                       and m["node_id"] not in contradicted_methods
                       and m["node_id"] != method["node_id"]]
```

### Step 6: 对抗性验证——系统性模式识别

**推理目标**：单篇论文的基线选择偏差可能是个体疏忽；但若某种偏差模式在多篇论文中反复出现，这就是领域级的评估文化问题，需要在报告中突出。

**操作流程**：
- 统计谱系回归案例的分布：是否某个特定祖先方法被反复选为基线而其后继版本被忽视？
- 统计自我服务比较的分布：是否某个特定的被 `contradicts` 方法被反复选为「靶子基线」？
- 若某种模式在 ≥ 3 篇论文中出现，标注为「系统性评估文化偏差」（systematic_evaluation_culture_bias），这需要在报告中专门讨论

### Step 7: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **`compares_with` 边是基线比较的主要 KG 来源**，必须在 Step 1 从 KG 边提取，不得仅依赖 Paper Cards 文本。
- **谱系回归检测（Step 2）是必选步骤**——`extends` 链分析必须执行，不得跳过。
- **自我服务比较检测（Step 3）是必选步骤**——`contradicts` 边与 `compares_with` 边的交叉检查必须执行。
- 「过时基线」判断标准为 > 2 年，这是审计的硬阈值；1~2 年差距标注为 `slightly_old` 但不标记为不公平。
- 若论文的 Experimental Setup 章节中明确描述了对基线进行了超参调优（如「we tuned all baselines using grid search」），则该项通过，不得凭直觉推翻。
- 硬件不对等的判断只能基于论文中的显式描述，若论文未描述硬件信息，标注 `hardware_parity: unclear`，不得推断。
- `recommended_replacement_baselines` 字段只填写文献集中实际存在且更合适的基线，不得引入文献集之外的方法。
- 若某论文故意选择旧基线但在原文中给出了合理理由（如「与 ICSE'2020 的评估保持一致」），需在报告中记录该理由，不得自动降低置信度。
- 系统性模式识别需 ≥ 3 篇论文支撑才能声称「系统性评估文化偏差」，不得凭少数案例泛化。
- **认知坐标规则**：每次执行在 Checkpoint Output 第一行记录认知坐标，格式为 `[认知坐标: S2.3 · 基线选择偏差结构性审计 · <本次分析的论文集合和重点偏差类型>]`。
