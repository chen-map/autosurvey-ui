# Skill: B2.4-b 约束变量敏感性分析

**层级**：S2.4 效能对比层 · Comparative Efficacy & Trade-offs  
**RQ类型**：优劣势如何？（适用边界）  
**元认知逻辑**：识别影响解法效能的关键约束变量，绘制「性能-约束变量」曲线，识别性能骤降的拐点（失效临界点），为每个解法定义其有效工作区间。  
**认知基准面**：约束不只是「方法有时不好用」的备注——约束节点 IS 当前范式的隐含假设清单；松弛了哪条约束的方法，就是在探测该假设的边界。

---

## Goal

从 KG 的 `assumption` 节点和 Paper Cards 的 Ablation Study / Sensitivity Analysis / Discussion 章节，系统性提取解法对关键约束变量的敏感性数据，界定各方法的有效边界和失效临界点。

---

## Inputs

- `knowledge_graph/nodes/methods.json` — KG 方法节点
- `knowledge_graph/nodes/assumptions.json` — KG 假设/约束节点（assumption 类型）
- `paper_cards/parsed/` — Paper Cards，提取 Ablation / Sensitivity / Limitation 章节
- `working_memory/rq_{id}/B2.4-a_pareto_report.json` — 帕累托分析结果（可选，识别性能最敏感的方法）

---

## Execution Steps

### Step 1: 从 KG 的 assumption 节点识别关键约束（KG优先策略）

**为什么这样做**：KG 中的 `assumption` 节点不是辅助信息——它们就是当前技术范式的隐含约束清单。从这里出发，而不是从 Ablation Study 出发，能让我们发现那些「从未被消融研究测试过」的隐性约束，这恰恰是最危险的盲区。

```python
# 获取所有约束/假设节点
all_assumptions = get_entity_by_type(loader, "assumption")

for assumption in all_assumptions:
    assumption_id = assumption["id"]
    # 找到依赖该假设的所有方法（requires 边）
    dependent_methods = get_head_entity(loader, "requires", assumption_id)
    assumption["dependent_count"] = len(dependent_methods)
    assumption["dependent_methods"] = [m["id"] for m in dependent_methods]

    # 找到松弛了该假设的方法（relaxes 边）——这些方法是在探测边界
    relaxing_methods = get_head_entity(loader, "relaxes", assumption_id)
    assumption["relaxing_count"] = len(relaxing_methods)
    assumption["relaxing_methods"] = [m["id"] for m in relaxing_methods]
```

**约束重要性排序逻辑**：
- `dependent_count` 高 AND `relaxing_count` 低 = 高敏感约束（很多方法依赖，但很少有方法尝试突破）
- `dependent_count` 高 AND `relaxing_count` 高 = 活跃研究约束（社区正在积极探测边界）
- `dependent_count` 低 = 方法特定约束（非普遍性约束）

**决策条件**：优先分析高敏感约束（dependent_count ≥ 3 且 relaxing_count ≤ 1）；这些约束一旦被违反，将导致大量方法同时失效。

补充从 Paper Cards 的 Ablation Study 章节提取的约束变量（如规模、训练数据量、模型大小、超参数 k、噪声比例），统计哪些变量被 ≥ 2 篇论文研究过（跨论文的共性约束变量）。

### Step 2: 收集性能-变量曲线数据（双源验证）

**为什么这样做**：仅依赖 Ablation Study 会遗漏「从未被测试但实际重要」的约束。正确做法是：先从 KG assumption 节点找到约束的存在，再去 Paper Cards 找实验数据；如果 KG 中存在但实验中从未测试，这本身就是一个重要发现——「未测试的依赖假设」。

对每个高敏感约束，执行两路查询：

**路径 A：从 KG 验证假设的存在**
```python
for assumption in high_sensitivity_assumptions:
    # 追踪哪些方法依赖该约束
    dependent_methods = get_head_entity(loader, "requires", assumption["id"])
    # 对每个依赖方法，获取其证据论文
    for method in dependent_methods:
        evidence_papers = get_evidence_papers(loader, method["id"])
```

**路径 B：从 Paper Cards 提取定量曲线数据**
```python
violation_snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query=f"fails when|breaks down if|assumes that without which|performance degrades when {assumption['name']}",
    paper_ids=[p["id"] for p in evidence_papers],
    topk=5
)
```

对每条性能-变量曲线：
- 若有图表，提取图表中的关键数据点
- 若仅有文字描述，提取定性结论
- 若完全无数据，标注 `sensitivity_data: absent`（这是已发现的约束盲区）

**临界阈值的界定必须依托于原文中的 Ablation Study 或 Sensitivity Analysis。**

### Step 3: 识别性能拐点（失效临界点）

**为什么这样做**：有效区间的边界不是模糊的「大概」，而是有实验数据支撑的具体阈值。只有找到拐点，才能给出「何时应该切换方法」的可操作建议。

对每条性能-变量曲线，识别：
- **有效区间**：性能稳定在可接受水平的变量范围
- **拐点**：性能骤降（下降幅度 > 20%）的变量临界值
- **失效区间**：超出拐点后的性能不可接受范围

**失效阈值定义必须明确**：在报告中声明「低于 X 性能定义为失效」的标准。若 Paper 中有明确的失效定义（如「F1 < 0.5 为不可用」），采用 Paper 的定义；若无，采用「相对最优性能下降 > 20%」作为通用阈值。

**决策条件**：若某方法无任何 Ablation 或 Sensitivity 章节，标注 `sensitivity_data: absent`，有效区间字段留空，不得从其他论文数据推断其约束边界。

### Step 4: 跨方法的边界对比（基于 relaxes 关系发现突破者）

**为什么这样做**：简单排名「哪个方法边界最宽」是描述性的；真正的洞察是：哪些方法通过「松弛某个假设」实现了边界扩展？这些方法是迈向下一代范式的路标。

```python
# 对每个高敏感约束，找到松弛它的方法——这是边界拓展者
for assumption in high_sensitivity_assumptions:
    boundary_breakers = get_head_entity(loader, "relaxes", assumption["id"])
    # 比较 boundary_breakers 在该约束维度上的有效区间 vs 依赖该约束的方法
    dependent_methods = get_head_entity(loader, "requires", assumption["id"])
    # 若 boundary_breakers 的有效区间显著更宽 → 验证了松弛该约束的价值
```

对同一约束变量，对比不同方法的有效区间边界：
- 哪个方法对大规模输入最鲁棒？
- 哪个方法在少量训练数据下仍有效？
- 识别「在所有约束变量上边界最宽」的方法

**若不同论文对同一变量的结论相互矛盾，必须并列展示矛盾结论，并分析可能的原因，不得选择性忽略一方。**

### Step 5: 生成场景化适用建议

基于有效区间分析，给出各方法的适用场景矩阵：
「方法 X 适用于 [变量条件]，当 [变量超出范围] 时推荐使用方法 Y」

**推荐的完整格式**：必须同时说明「在什么约束条件下适用」和「当哪个约束被违反时失效」——没有失效条件的推荐是不完整的。

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **拐点数值必须来自原文的图表或实验数据**，不得通过插值或估算推断拐点位置。
- 若某方法在 Paper Card 中无 Ablation 或 Sensitivity 章节，必须标注 `sensitivity_data: absent`，有效区间字段留空，不得基于其他论文数据推断。
- 「有效区间」边界值必须有具体依据（如「精度 < 80% 定义为失效」），需在报告中声明失效阈值定义。
- 跨方法边界对比必须确保不同论文中该变量的定义一致（如「项目规模」是按文件数还是代码行数衡量）。
- 若不同论文对同一变量的结论相互矛盾，必须并列展示矛盾结论，并分析可能的原因，不得选择性忽略一方。
- **KG assumption 节点优先**：约束识别必须先查 `get_entity_by_type(loader, "assumption")`，再补充 Paper Cards 数据；不得跳过 KG 直接从文本提取约束。
- **未被测试的高敏感约束（`sensitivity_data: absent` 且 `dependent_count ≥ 3`）必须在报告中单独列出**作为「约束盲区」警告，这些是领域最需要消融研究的地方。
- **认知坐标纪律**：本技能的核心产出是「哪些约束是范式赖以成立的必要条件」以及「哪些方法在扩展这些边界」——若分析结果只是「方法A比方法B鲁棒」的排名，缺乏对约束本质的追溯，分析是不完整的。
