# Skill: B2.6-c 解法反噬与反馈闭环识别

**层级**：S2.6 资源、可复现性与反馈核算层 · [V3 新增]  
**RQ类型**：花多少钱？能复现吗？（解法负面外溢性）  
**元认知逻辑**：将 A1.6-b 的次生灾害清单与 Solution Space 的解法联动，构建「解法 → 副作用 → 催生新问题 → 需要新解法 → 可能引入更多副作用」的完整反馈回路，分析若不打断回路系统风险将如何累积。  
**认知基准面**：制造新问题的解法会形成闭合回路——目标是找到可以打断恶性循环的干预点，而不是继续添加新的局部解法（这只会延伸回路）。

---

## Goal

将 Problem Space（A1.6-b）和 Solution Space（B2.6-a/b）的分析结果整合，识别 Solution Space 中解法的负面外溢所形成的反馈回路，提出阻断回路的系统性改进点，避免「解法军备竞赛」的恶性循环。

---

## Inputs

- `working_memory/rq_{id}/A1.6-b_problem_shift_report.json` — 次生灾害清单（强依赖）
- `working_memory/rq_{id}/B2.4-d_coverage_audit_report.json` — 解法覆盖率（含高风险解法列表）
- `working_memory/rq_{id}/A1.6-a_coevolution_report.json` — 攻防演化轨迹（可选）
- `paper_cards/parsed/` — Paper Cards，提取 Discussion / Future Work 章节

## Execution Steps

### Step 1: 构建解法-次生问题链接（从 A1.6-b 和 KG 双源）

**为什么这样做**：反馈回路的每一条边都必须有文献证据支撑——不能凭系统动力学直觉构造假设的因果链。A1.6-b 的 `problem_shift_chains` 是已经验证过的「解法→次生问题」链接，这是分析的可靠起点。

```python
from A1_6_b_report import problem_shift_chains

# 构建解法 → 次生问题的映射（基于 A1.6-b 已验证的证据）
solution_to_secondary = {}
for chain in problem_shift_chains:
    solution_id = chain["solution_id"]
    secondary_problem_id = chain["secondary_problem_id"]
    evidence_count = len(chain["evidence_papers"])

    if solution_id not in solution_to_secondary:
        solution_to_secondary[solution_id] = []
    solution_to_secondary[solution_id].append({
        "secondary_problem": secondary_problem_id,
        "evidence_strength": "strong" if evidence_count >= 3 else "moderate" if evidence_count >= 1 else "weak",
        "evidence_papers": chain["evidence_papers"]
    })
```

记录链接强度（A1.6-b 中的 `evidence_paper` 数量）和次生问题 P' 的严重程度。

**反馈回路的连接必须基于 A1.6-b 已经验证的文献证据，禁止凭空构建复杂的系统动力学图表。**

### Step 2: 识别反馈闭环（KG 路径查询）

**为什么这样做**：「闭环」的定义是精确的：存在一条路径，从问题 P 出发，经过解法 D → 次生问题 P' → 新解法 D' → 次生问题 P'' → … → 最终回到 P 类型的问题。这个闭合性可以通过 KG 结构查询来验证。

```python
for solution_id, secondary_problems in solution_to_secondary.items():
    for secondary in secondary_problems:
        secondary_problem_id = secondary["secondary_problem"]

        # 找到专门解决该次生问题的新解法
        new_solutions = get_head_entity(loader, "addresses", secondary_problem_id)

        for new_solution in new_solutions:
            new_solution_id = new_solution["id"]
            # 检查新解法是否又引入了次生问题
            if new_solution_id in solution_to_secondary:
                new_secondary_problems = solution_to_secondary[new_solution_id]

                # 检查新次生问题是否回到了原始问题的类型
                for new_secondary in new_secondary_problems:
                    if problems_are_related(new_secondary["secondary_problem"],
                                           original_problem_id):
                        # 找到闭环！
                        loop = build_loop_chain(
                            solution_id, secondary_problem_id,
                            new_solution_id, new_secondary["secondary_problem"]
                        )
                        feedback_loops.append(loop)
```

检查次生问题 P' 是否反过来促使研究人员开发新解法 D'，而 D' 又引入新的次生问题 P''：
- 在 KG 中查找「P' → D'（新解法专门应对 P'）→ P''（D' 的次生问题）」的链
- 若存在两条以上这样的链，构成反馈回路

**决策条件**：若 A1.6-b 的次生灾害清单为空（无次生问题被识别），此 skill 必须声明「无可识别反馈回路」，不得强行构造分析。

### Step 3: 分析反馈回路的放大效应

**为什么这样做**：有些反馈回路是良性的（问题在循环中逐渐缩小），有些是恶性的（总风险在累积）。区分两者需要对每一跳的严重程度做量化累加——如果次生问题比原始问题更严重，系统总风险就在放大。

```python
for loop in feedback_loops:
    total_secondary_severity = sum(
        get_problem_severity(node["node_id"])
        for node in loop["chain"]
        if node["node_type"] == "problem" and node["node_id"] != original_problem_id
    )
    original_severity = get_problem_severity(original_problem_id)

    loop["total_risk_exceeds_original"] = total_secondary_severity > original_severity
    loop["amplification_analysis"] = (
        f"原始问题严重度: {original_severity}, "
        f"次生问题累积严重度: {total_secondary_severity}"
    )
```

若无定量数据，进行定性论证：「基于文献描述，次生问题 P' 的影响范围比原始问题 P 更广」。

**「总风险超过原始问题」的判断必须基于严重程度数据的累加，若仅有定性数据，只能声明「可能超过」（不确定性标注）。**

### Step 4: 识别反馈回路中的最优干预点（最弱因果边）

**为什么这样做**：在闭合回路中，干预效率最高的点不是「最重要的节点」，而是「最弱的因果链接」——因为打断最弱的链接所需的证据最少、工程代价最小，且一旦打断，整个回路就无法闭合。

```python
for loop in feedback_loops:
    # 对每条边，评估其因果证据强度
    edge_strengths = []
    for i in range(len(loop["chain"]) - 1):
        node_a = loop["chain"][i]
        node_b = loop["chain"][i + 1]
        # 通过 A1.6-b 的证据论文数量判断因果强度
        edge_evidence = get_edge_evidence(node_a["node_id"], node_b["node_id"])
        edge_strengths.append({
            "from": node_a["node_id"],
            "to": node_b["node_id"],
            "evidence_count": len(edge_evidence),
            "strength": "strong" if len(edge_evidence) >= 3 else "moderate" if len(edge_evidence) >= 1 else "weak"
        })

    # 最弱边 = 证据最少的因果链接 = 最优干预点
    weakest_edge = min(edge_strengths, key=lambda e: e["evidence_count"])
    loop["optimal_intervention_point"] = weakest_edge
```

对抗验证：对每条因果边，验证其方向——用 `search_paper_sections` 确认因果方向是「解法导致次生问题」而非「次生问题的存在促使研究者开发该解法」（方向相反）。

```python
for loop in feedback_loops:
    for edge in loop["chain_edges"]:
        direction_check = search_paper_sections(
            paper_cards_root="paper_cards/parsed",
            query=f"{edge['from_name']} leads to|causes|results in {edge['to_name']}",
            paper_ids=edge["evidence_papers"],
            topk=3
        )
        if not direction_check:
            edge["causal_direction_unverified"] = True
```

### Step 5: 确定改进优先级

寻找可以阻断反馈回路的「干预节点」类型：
- 能否对解法 D 进行改造，消除其导致 P' 的副作用？（D → P' 边的删除）
- 能否引入「元解法」D_meta，同时解决 P 和 P'，避免 D' 的引入？
- 能否通过设计约束，防止 D 引入 P'？

**干预节点的「可行性」评估必须引用文献中已有的改进尝试**（如已有论文尝试修改解法以减少副作用），不得凭 LLM 假设干预可行。

基于反馈回路中各解法的「风险净贡献」，给出改进优先级排序：
- **高优先级**：处于多条回路关键节点的解法（切断该解法可阻断多条回路）
- **低优先级**：处于回路末端的解法

### Step 6: 原文溯源验证

对所有分析结论中引用的证据，使用 `search_paper_sections` 工具在 `paper_cards/parsed/` 中精确定位原文片段：

```python
snippets = search_paper_sections(
    paper_cards_root="paper_cards/parsed",
    query="<分析结论的关键词>",
    paper_ids=[<涉及的paper_id列表>],
    topk=3
)
```

每条关键结论必须附带：
- `paper_id`：来源论文ID（对应 `knowledge_graph/nodes/papers.json` 中的记录）
- `section`：原文章节标题
- `paragraph_snippet`：原文片段（≥20字，直接引用，禁止改写）
- `score`：语义相似度分值

**无法找到原文片段支撑的结论必须标注 `evidence: unverified`，不得作为最终结论输出。**

## Key Rules

- **所有反馈回路节点必须在 A1.6-b 中有已验证的证据支撑**，不得通过逻辑推演构造超出 A1.6-b 已有证据的回路。
- 「总风险超过原始问题」的判断必须基于严重程度数据的累加，若仅有定性数据，只能声明「可能超过」（不确定性标注）。
- 干预节点的「可行性」评估必须引用文献中已有的改进尝试（如已有论文尝试修改解法以减少副作用），不得凭 LLM 假设干预可行。
- 若 A1.6-b 的次生灾害清单为空（无次生问题被识别），此 skill 必须声明「无可识别反馈回路」，不得强行构造分析。
- 反馈回路的「长度」（chain length）超过 4 时，需特别审查其可信度：链越长，每一步的证据要求越严格。
- **因果方向验证是强制步骤**：对每条声称「解法导致次生问题」的边，必须用 `search_paper_sections` 验证因果方向；方向未验证的边必须标注 `causal_direction_unverified: true`，不得作为强证据支撑回路分析。
- **最优干预点识别必须基于最弱因果边**（`evidence_count` 最少的边），而不是「感觉最重要的节点」——弱边是最容易打断的，也是反馈回路最脆弱的环节。
- **认知坐标纪律**：本技能的核心产出是「哪个干预点以最小代价打断最多回路」——若报告只有回路描述而无干预优先级，分析缺乏实践价值。
