> 处置决议：只登记；轻微、不涉及大规模调整的改动可尝试；改文件类型（存储格式迁移）可能引发 bug，暂不动。

## 一、知识图谱构建流程优化方向

### 1. 候选对生成与 Pre-score 精细化
- 三阶段流程已落地但精度待提升：当前采用向量初筛 → Rank Top-K（可配置前 1000 或几千）→ 大模型 Pre-score 流程，核心问题是 Pre-score 评分不够准确。
- 提议按论文章节分区域解析关系：纯大模型匹配不精细，建议针对不同章节解析不同关系（如 Introduction 部分比对解析特定关系），虽增加复杂度但可提升候选对生成质量。

### 2. 结构化对象定义校验
- Notes 指标准确性需复核：需检查每篇论文的 Notes 是否为准确的结构化对象，包括 Proposal、Solution、Metric 等指标定义是否精准。
- 提取应定位到具体章节：当前将论文前若干段整体输入大模型提取结构化对象，建议改为针对特定节点读取论文对应部分（如 Solution 节点只读解决方案章节），以提升本地大模型提取精度。

### 3. Related Work 引用关系解析缺失
- 引用关系当前无法有效识别：即使两篇论文存在引用关系，现有筛选机制也无法识别，因 Related Work 部分解析效果不佳。
- 需双向解析 Related Work 建立连接：正常引用即代表相关，需将双方论文的 Related Work 部分均良好解析后再做连接判断，此为当前短板。

### 4. 知识图谱存储格式待升级
- 当前 JSON 存储查询粗暴：最终产物以 JSON 形式存储，节点含子节点（如 Paper 节点下挂 Problem/Solution），查询时用类似 grep 工具在 JSON 中检索，效率低且不便在线增删改查。
- 拟调研主流图数据库替代方案：发言人2 提及 **Obsidian**（原文 "OpenCBOC" 为语音识别误写，2026-09-23 用户更正）作为 KG 存储/浏览形态——即 markdown 笔记 + [[双链]] + 图视图的文件型知识库。建议调研主流 KG 存储格式，确定后统一演示数据格式。

### 5. 节点 AutoMerge 机制缺失
- 跨论文同义名词融合尚未实现：不同论文对同一对象命名不一，当前完全缺失自动合并步骤，称为新加坡医学 KG 团队最大痛点。
- 提议维护 MD 文档 + 向量匹配 + Prompt 规则：最简方案为维护名词表文档，新名词进来时新建节点/边，向量匹配 Top5-10 后由大模型依据明确融合规则判定是否合并，若能实现将显著提升 KG 详细度。

## 二、三层分析架构与 Skill 体系

### 1. Analysis V2 参考 KGA 但结构不同
- 底层原子操作与数据强相关：分析底层仍依赖大量原子操作（如读文档各类操作），其有效性取决于 KG 定义质量；若 KG 标准化程度高，可用向量/关键词/模糊匹配精准查询。
- 三层结构区别于 KGA 两层：KGA Agent 为大模型生成原子操作序列直接回答（两层），本项目为原子操作层 + Skill 层 + RQ 分类层（三层），中间 Skill 层承载专家经验。

### 2. Problem/Solution 双域 Skill 体系
- RQ 分为 Problem 与 Solution 两大类：依据刘洋老师"世界万物分两层"观点，Problem 域涵盖实体识别、认知框架、深沉度、后果影响、认知盲区、对抗演化等；Solution 域研究方案演化、对比与评估。
- Skill 构建采用自上而下 + 自下而上结合：自上而下从顶会 Survey 蒸馏数十篇论文的 RQ 分析过程；自下而上归纳已有原子序列共性提炼经验；两者映射互补，目标覆盖设备领域所有分析方法。

### 3. Agent 记忆攻击防御分析案例
- 拆解子问题匹配 Skill 调用：针对 Agent 记忆系统攻击防御分析，拆解为业务节点子问题，选用范式抽象、能力风险推理等 Skill，底层调用 KG 节点/边获取数据。
- 识别四类攻击范式与防御空白：攻击分为记忆提取、持久化控制、上下文劫持等类别，并识别出针对特定态势的防御空白，为后续研究提供方向指引。

### 4. 对标新加坡团队创新 Skill 论文
- 创新 Skill 构建与验证方法：该团队用大模型总结 1000 篇论文创新方案，向量聚类出 50 种创新 Skill，新问题检索适配 Skill 生成方案；验证时用 Ground Truth 或 Open Review 审稿意见对比，大模型多维度评分证明挂载 Skill 优于人类创新。
- 本项目方法论更具优势：采用自上而下 + 自下而上结合，比纯自下而上更优，且任务聚焦设备领域比宽泛创新任务更易落地。
