# 开放计划（Open-Core）

## 1. 定位

AutoSurvey 采用 **open-core**：把可复用、可核验、可公开的部分开放；完整可运行的生产系统（后端服务、数据库、部署与生产配置）保留在私有仓库，避免在专利申请或论文发表前公开完整的工程实现。

这不是“只用开源软件做开发环境”。我们公开的是可复用的**五步工作流关键实现摘录、分析工作流规范、真实运行数据、评测材料与文档**；这些是他人可以直接使用、复核或扩展的成果。

## 3. 暂不公开（私有仓库）

- 完整可运行的后端服务、多项目编排运行时与数据库结构（公开仓库仅含 `open/pipeline/` 摘录）。
- 模型路由、成本控制与质量门参数等生产调定取值。
- 部署脚本、服务器与访问配置、凭据。
- 用户数据与未获授权的第三方全文。

评审需要时，可提供私有仓库的只读访问或离线代码包（不含密钥与用户数据）。

## 4. 开放路线图

| 阶段 | 开放内容 | 许可证 | 说明 |
|---|---|---|---|
| 现在 | 37 个分析策略规范、五步工作流实现摘录（`open/pipeline/`）、前端、真实快照、文档 | Apache-2.0 / CC BY 4.0 | 已在本仓库 |
| 赛期内 | 证据对齐工具整理为可独立运行的 CLI（PDF 引文 → 页码 → 条带，不依赖核心编排）、评测脚本与评分表、无 Key 的 Docker 演示包 | Apache-2.0 | 源码已随 `open/pipeline/` 摘录开放 |
| 知识产权保护完成后 | 检索/筛选适配层、结构化抽取接口、报告生成模板 | Apache-2.0 | 以插件/接口形式开放 |
| 6–12 个月 | 核心编排的部分模块（按专利与论文进度） | Apache-2.0 或兼容许可 | 采用“先申请、后开放”的顺序 |

## 5. 上游协作

- 对实际使用中发现的问题，向上游项目提交可复现的 Issue 与补丁（例如 PDF 解析、LaTeX 模板、检索客户端）。
- 上游贡献遵循对应项目的贡献指南与许可证；不提交含用户数据或未授权内容的样本。
- 欢迎通过 GitHub Issues 提出需求、缺陷与复用案例。

## 6. 贡献方式

1. 提交 Issue 描述场景、复现步骤与期望行为。
2. 提交 PR 时说明许可证与来源；默认同意以 Apache-2.0 授权。
3. 不提交论文全文、摘要批量文本、访问凭据或个人信息。
4. 数据类贡献需附来源与许可说明。

## 7. 合规边界

- 只开放团队有权公开的内容；第三方论文、模型权重、模板与数据按其许可使用。
- 公开数据仅保留引用核验所需的最短片段；如权利方提出异议，及时下线。
- 涉及专利申请的内容，在申请完成前不公开；本计划会随进度更新。
